## New opt-in deployment authority

The additive `deployment-v1` profile provides admin-only
`GET /deployment-snapshot` and these owner mutations:

```text
DELETE /proxies/{id}?conditional=true&cleanup_orphaned_upstream=false
PUT /api-specs/{id}?conditional=true
```

Capture one coherent snapshot under the intended `X-Ferrum-Namespace` using an
admin-role JWT. It carries `Cache-Control: no-store`, `profile: "deployment-v1"`,
typed proxies/upstreams/plugins/full specs and complete raw namespace evidence.
The HTTP `ETag` equals `namespace_etag`: retain that **original quoted token**
in encrypted recovery storage and send it in exactly one `If-Match` field after
validating the complete original deployment. Its keyed `deployment-v1-` authority
is distinct from backup namespace tags and ordinary resource row ETags.
Replicas must share the admin JWT secret. Snapshot evidence includes unredacted
credentials and must not enter routine logs.

Evidence covers all namespace resources, spec gzip bytes and external-reference
evidence, association fields, credential indexes, trust, namespace metadata and
the durable change watermark. SQL preserves every supported column's type and
lossless scalar evidence, including float bits, blob bytes and typed NULLs;
MongoDB binds raw BSON documents and supported embedded metadata. Unknown raw
state that cannot be represented losslessly, or undecodable state, refuses
authority without a cached or normalized fallback.
Unsupported SQLx Any types or a selected row that cannot be reinserted safely
refuse. Unknown MongoDB top-level fields rejected by the typed resource schema
are never erased to admit a mutation. Supported arbitrary credential/config
maps and association metadata remain fenced and preserved; unknown collections
are not represented as deployable resources or mutated by this profile.

`conditional=true` must occur exactly once; removal also requires exactly one
`cleanup_orphaned_upstream=false`. Only a single optional `apply=sync` is
accepted. Unknown/ambiguous modes, `apply=async`, missing/duplicate headers,
lists, wildcards, weak tags and wrong-profile tokens refuse with `400`.
Missing discriminator cannot turn deployment authority into an ordinary write.
An original token invalidated by target or unrelated namespace writes, even
recorded changes later reverted, returns `412` before mutation. Existing roles,
namespace authorization, validation and read-only gates still apply.

| Store | Required authority and transaction capability |
| --- | --- |
| SQLite | Coherent SQL snapshot; mutation takes the writer lock and pins the live owner/generation lease before evidence reads and through commit. |
| PostgreSQL | Namespace writer/row fences precede the mutation snapshot; READ COMMITTED refreshes the view after those fences; dependency reads stay protected through commit. |
| MySQL | REPEATABLE READ is required; establish the snapshot after namespace writer fences. Other isolation settings fail closed. |
| MongoDB | Replica-set snapshot/majority transactions and changed lease-document write pin; standalone topology is `501`. Driver retries retain original evidence. |

Missing/unavailable stores, lease ownership, tag keys or coherent raw state fail
closed. Unsupported atomic topology refuses; no unconditional fallback,
whole-namespace restore-minus-target or late compensation is authorized.
Successful partial mutations preserve unrelated rows/documents, historical
credentials, timestamps, trust revisions, retained hand-owned upstreams and
surviving shared owners/association fields. An unchanged proxy in a plugin-only
replacement retains its complete raw fields, timestamps and row ETag.

### Exact acknowledgement and recovery rules

Successful envelopes contain `profile: "deployment-v1"`, the expected `id`,
`durable`, `live` and `recovery_cleanup_authorized`. Error envelopes may omit
profile/id; ordinary auth/validation errors may omit all acknowledgement fields.
Missing evidence never authorizes cleanup.

| Outcome | HTTP | `durable` | `live` | `recovery_cleanup_authorized` |
| --- | --- | --- | --- | --- |
| Confirmed commit, covering local generation applied, final security audit admitted and owner-qualified namespace lease release acknowledged | 200 | `committed` | `applied` | `true` |
| Confirmed commit in CP, an unserved namespace or without a serving coordinator | 200 | `committed` | `not_applicable` | `false` |
| Confirmed commit but apply, cursor capture, audit or lease release unconfirmed | 503 | `committed` | `unconfirmed` | `false` |
| Driver/database/commit, auxiliary release or transport result uncertain | 503 when a response exists | `unknown` | `unconfirmed` | `false` |
| Stale original authority or typed dependency/ownership refusal | 412 / 409 | `not_committed` | `unconfirmed` | `false` |
| Unsupported atomic topology | 501 | `not_committed` | `unconfirmed` | `false` |
| Initial mode/evidence/admission failure | 400 / 503 as applicable | `not_started` | `unconfirmed` | `false` |

A covering local success carries `X-Ferrum-Config-Cursor`; it proves application
by this process only. It does not attest every remote DP. CP durable-only
responses cannot clear a recovery journal.

The precise dependency refusal correction distinguishes proven external
references to spec-owned upstreams from untyped failures. Resource-changing
PUT/DELETE with that typed conflict return
`409/not_committed/unconfirmed/recovery_cleanup_authorized=false`, without
exposing conflict identifiers or driver details. Metadata-only spec replacement
keeps its shortcut before the external-reference guard; the guard precedes
every selected resource write. Ordinary direct proxy admission still refuses
the invalid external owner with `400` and no durable row or covering change;
historical store-seeded dependencies do not weaken that admission rule.

Database/commit unknown remains uncertain. Never infer rollback from a driver
message, HTTP failure, cancellation or lost response. Retain the encrypted
original snapshot/token/journal after stale/refused, committed-not-live,
audit/lease failure or uncertain outcomes. Reconciliation may inspect current
owner state, but no retry, refreshed token or fresh read retroactively grants
cleanup authority for the original destructive action. See the complete
[adoption contract](../deployment_mutations.md).

## SQLx typed NULL correction and upgrade limits

The pre-existing SQLx Any conversion defect is corrected without changing
SQLx 0.8.6 or the dependency graph: REAL NULL uses `Option<f32>::None` and
DOUBLE NULL uses `Option<f64>::None`. The PostgreSQL regression checks native
uncast parameter types (`real` and `double precision`) and explicit NULL
results. The extended-schema fixture completes every ALTER and reconnects once
to the same durable database before capturing authority. These controls do not
establish the original initial-import PostgreSQL 500's cause, stored value loss,
or online DDL safety.

Retire [SQLx patch 002](../upstream-sqlx-patches/002-typed-float-null-bindings/README.md)
only when a compatible upstream release preserves these types and passes the
same hosted regression. Keep the vendor copy while [TLS patch 001](../upstream-sqlx-patches/001-verify-ca-name-context/README.md)
still needs it; remove the copy, both root/mesh patch entries and corresponding
lock/integrity/lifecycle records together only when both can retire. Preserve
the behavioral regressions after retirement.

Read [Upgrading to 0.9.12](../upgrade_guide.md#upgrading-to-0912).
All previously released breaking identifiers and upgrade/rollback guidance
remain applicable. Core baseline changes require a fresh database with logical
import and the intact old database for rollback. This release adds no schema
migration and promises no online schema upgrade or mixed CP/DP build support.
