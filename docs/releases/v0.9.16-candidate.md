## Historical protected recovery and qualification plan

Follow the documented [release procedure](../ci_cd.md#step-by-step): land
a follow-up PR using **Create a merge commit**, retaining the reviewed runtime
source and version. Validate that resulting main commit and bind its second
parent to the follow-up PR's exact approved head. This provenance record is
the follow-up's documentation change; no publisher, verifier or ruleset
change is needed. The documented `RELEASE_TAG_TOKEN` configuration
prerequisite remains applicable.

The eventual release target must pass every publish-blocking check under its
canonical workflow identity. Earlier candidate checks and the initial squash
commit's main-push checks are not proof for that new target. Final-source
affinity qualification must use the eventual target's signed `main-<sha>`
image; the [October 9 affinity measurements](../../tests/performance/multi_protocol/affinity-measurements-2026-10-09.md)
cover earlier revisions only.

Only after those gates pass, dispatch **Start Production Release** from
`main` with `version=v0.9.16`. Verify the immutable tag target, the separate
Release workflow, binary checksums, image digests, signatures and attestations
before updating public download references. Publish the matching
`contracts-edge-0.9.16` contract update before downstream contract pins move,
as required by the upgrade guide; companion application releases retain
their own qualification and approval requirements.
