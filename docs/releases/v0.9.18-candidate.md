# Ferrum Edge 0.9.18 candidate provenance

This historical pre-publication record is retained from October 26, 2026.
The final protected follow-up was merged as PR #6949 at
`57966eb9d047378ef6ebf8aa97c94ebf96a38fa6`; the immutable v0.9.18 tag was
created there, but production ARM64 failed and no GitHub Release was
published. Attempts 2 and 3 proved host OOM during fat LTO. The historical plan below
is superseded by the [0.9.19 recovery strategy](v0.9.18-arm64-recovery.md).
Do not redispatch or move the existing v0.9.18 tag. Release changes and rollout
requirements are carried forward in the
[changelog](../../CHANGELOG.md#0919---2026-10-27) and
[upgrade guide](../upgrade_guide.md#upgrading-to-0919). The replacement
v0.9.19 is now published; see its [publication record](v0.9.19-candidate.md).
There is no `contracts-edge-0.9.18`.

## Reviewed source and the initial main commit

[PR #6944](https://github.com/ferrum-edge/ferrum-edge/pull/6944) prepared the
release metadata. Cargo's package version and both Helm chart appVersions are
`0.9.18`. Two independent reviewers (GPT-6.1 Sol and Muse, xhigh) reported
CLEAN on its final head `77d578f6d9cff43478a8c234fe53df65f2c8b1bc`, and every
check on that head completed successfully or with a legitimate skip.

It was squash-merged at `dc7009b4c6a94bf554faa9f4c1944eae72e7d43e` on
October 26, 2026 at 09:49:58 UTC. That commit has one parent,
`ba419a00a25914a33bd1c81bc1f02d32effcbbf2`. Its Git tree is identical to the
reviewed head: both trees are `f0f7138226d7de8316edcdd6692cab12724572bd`.

Tree equivalence does not satisfy the protected publication gate. The
[publication-check inventory](../../.github/required-publication-checks.json)
binds evidence to the producing PR's head through the release commit's second
parent, and [`resolve_pr_head`](../../.github/scripts/verify_publication_gate.py)
refused the one-parent commit in
[Start Production Release run 40302638790](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40302638790)
with:

```text
dc7009b4c6a94bf554faa9f4c1944eae72e7d43e has no second parent and cannot be bound to a PR head
```

No tag was created by that run.

## First protected merge and the gate defect

The protected follow-up,
[PR #6945](https://github.com/ferrum-edge/ferrum-edge/pull/6945), was cut from
main at `dc7009b4c6a94bf554faa9f4c1944eae72e7d43e` and merged with a merge
commit at `a8c1cdb62efa77f4b69dc016766cbb5741b77086`. Its second parent is the
reviewed head `48f0e20bda5f3cae7fc72f8b8d94fecc9d058c42`.

[Start Production Release run 40330496113](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40330496113)
then timed out on that commit:

```text
Trusted Cross Build Policy: no pull_request_target run of .github/workflows/cross-build-policy.yml for 48f0e20bda5f3cae7fc72f8b8d94fecc9d058c42 yet
```

The successful run existed:
[run 40302854283](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40302854283).
Organization ruleset 24977662, created on October 13, 2026, requires
`cross-build-policy.yml` from this repository at `refs/heads/main`. Because of
that, its PR runs are recorded under the ruleset required-workflow identity
`382932593`, not under the file workflow `315942345`. The gate searched only
the file workflow, so it could not see the run. v0.9.17 was published on
October 10, 2026, before the ruleset existed. No tag was created by that run.

[PR #6947](https://github.com/ferrum-edge/ferrum-edge/pull/6947) fixed the
gate. GPT-6.1 Sol and Muse (xhigh) reported CLEAN on its final head
`a8e72f208f5e40e8706de13a9f44b2384af2f8ac`. The fixed gate:

- accepts ruleset-required PR runs only when their identity is pinned in the
  inventory and confirmed by the live main branch rules;
- validates `total_count` completeness in run listings;
- fails closed on run records it cannot classify.

PR #6947 changes protected publication-gate surfaces. Its own head's Trusted
Cross Build Policy run therefore fails by design, and it was merged through
an administrator ruleset bypass at `89a995ea77a852cb422dcd77597df2b58506c2ee`.
That commit cannot itself be a release commit.

## Second protected merge and the fuzz lockfile advisories

The second protected follow-up,
[PR #6948](https://github.com/ferrum-edge/ferrum-edge/pull/6948), was merged
with a merge commit at `5967cdd0204f594d784210c64ca5e08c9758ab5c`. Its second
parent is the reviewed head `2afb138bf1c1516e4e9d6997680448d2d3144689`. With
the fixed gate, the Trusted Cross Build Policy evidence for that head was
accepted.

[Start Production Release run 40365022265](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40365022265)
was then blocked by the `Tests` check of
[CI run 40364992132](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40364992132)
on that commit. Its **Dependency Audit (cargo-deny)** job failed only for
`fuzz/Cargo.lock`. The failing RustSec advisories were:

- RUSTSEC-2026-0391, affecting `zstd` < 0.14.3;
- RUSTSEC-2026-0395 through RUSTSEC-2026-0406, affecting `zstd-safe` < 8.2.0;
- RUSTSEC-2026-0410, affecting `zstd-sys` < 2.1.2. The root and mesh-performance lockfiles already resolved
`zstd` 0.14.3, `zstd-safe` 8.2.0 and `zstd-sys` 2.1.2+zstd.1.5.7, but the
standalone fuzz workspace still locked 0.14.1, 8.1.0 and 2.1.1+zstd.1.5.7. The
fuzz harness is not shipped, and no tag was created by that run.

## Historical protected merge plan

This record is the third protected follow-up. Its PR is cut from main at
`5967cdd0204f594d784210c64ca5e08c9758ab5c`. It moves `fuzz/Cargo.lock` to the
same `zstd`, `zstd-safe` and `zstd-sys` versions and checksums as the root
lockfile, and is merged with a **merge commit**. Its reviewed head is the second
parent, and the merge tree equals that head's tree. **Start Production Release**
then runs for `v0.9.18` from that merge commit. A post-publication record
replaces this candidate record once the release, its images, and the matching
`contracts-edge-0.9.18` tag are verified.
