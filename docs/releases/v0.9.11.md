## Source changes already on main

This summary covers main through preparation base
`29f2c8544e5bb1bdc3657759b867aabb34c94b91`, after v0.9.10. That is a source
snapshot, not the future release commit. The detailed entries and their issue
identifiers remain in [CHANGELOG.md](../../CHANGELOG.md#0911---unreleased).

- Backend acquisition, request handoff, response-header waits, and retries
  retain the admitted authorization lifetime across direct HTTP/1.1, HTTP/2,
  gRPC, mesh, and HTTP/3 dispatch (GHSA-xcg4-wj3x-gjj2; #5961 / #5990 / #5993).
  Authorization expiry is latched once, suppresses replay, and remains neutral
  to backend health. Native gRPC keeps its pre-commitment `UNAUTHENTICATED`
  terminal. Native H3's wire marker still denotes completed HEADERS, not the
  first partial wire submission; expiry suppresses replay in either case.
- OIDC session configuration rejects published example keys, placeholders,
  unresolved templates, and equivalent Base64 key material in the current and
  previous encryption-secret fields (#5987 / #5996). Operators must provide
  unique random material.
- Conditional admin verification, coherent namespace snapshots, and atomic
  conditional restore use authoritative keyed strong tags and fail closed on
  stale state, unsupported topology, unavailable state, or lost admission
  leases (#5992 / #5999). JWT-authorized backend egress discovery describes
  the loaded process policy without exposing CIDRs or asserting a DP's policy
  from CP metadata (#5994 / #5999).
- The iproute2 layer's default runtime base is pinned to the production
  distroless OCI index digest (GHSA-c3r8-6276-9678; #6000). This source pin does
  not establish that 0.9.11 images have been built or verified.
- TLS selectors must agree with the field's material kind (#5959 / #5962;
  breaking). Fragmentless managed CA references work in CA expiry admission,
  and other fragmentless CA references check CA material (#5957 / #5958).
- HTTP/2 and gRPC uploads make progress with small legal flow-control windows;
  adaptive receive-window DATA-frame budgets follow window changes (#6001).
  Direct HTTP/2 uploads without size limits now retain their configured write
  stall timeout (#5588 / #5981 / #5982).
- gRPC shard affinity accounts for cancelled creates and uploads that outlive
  an early response (#5991). Redis semantic-cache quarantine compares the
  observed value atomically, and local cache cleanup preserves concurrent
  replacements (#5984 / #5986 / #5998).
- Extension-method spelling in `response_mock`, SSE `Accept` quality checks,
  and StatsD batching documentation are corrected (#5972 / #5973 / #5976 /
  #5985). Listener dispatch keeps large child futures out of poll frames
  (#5993).
- Direct HTTP/1.1 pooling, gRPC connection affinity, h2 DATA-frame coalescing,
  relay batching, and jemalloc cache sizing reduce dispatch and transport work
  (#5588 / #5961 / #5966 / #5967 / #5968 / #5969). Existing changelog benchmark
  observations describe earlier runs, not qualification of this release.
- Fuzz toolchain, vendored h2 fuzz visibility, and scheduled sanitizer memory
  provisioning repairs are on main (#5965 / #5971 / #5975 / #5977 / #5980).

## Upgrade actions

Read [Upgrading to 0.9.11](../upgrade_guide.md#upgrading-to-0911-release-draft)
before rollout. Correct contradictory TLS selectors (#5959), replace rejected
OIDC session keys (#5987), and review authorization deadlines and HTTP/2 write
timeouts. Account for the direct HTTP/1.1 pool default and larger jemalloc
thread cache. CP and DP must run the same build. The build-out policy still
requires a fresh database for a changed core baseline and the old database
for rollback; this patch version promises no in-place schema compatibility.
Earlier breaking-change identifiers and guidance remain in the changelog and
upgrade guide.

Conditional snapshot/restore and backend egress discovery require the
[ferrum-contracts handoff](../admin_contracts_handoff_5992_5994.md). Publish
contracts from the actual Edge release with full-SHA provenance before
downstream consumers rely on these additions; preserve previously published
contract tags.
