# ARM64 OOM recovery after the unpublished v0.9.18 tag

The immutable `v0.9.18` tag remains at
`57966eb9d047378ef6ebf8aa97c94ebf96a38fa6`. It is **TAGGED, NOT PUBLISHED**:
no GitHub Release exists. The replacement candidate is **v0.9.19**, prepared
on **2026-10-27 UTC**, carrying the planned 0.9.18 changes forward once.
Preserve the tag; reruns load the tag's original workflow and cannot use this
recovery. See the [historical candidate record](v0.9.18-candidate.md).

## Production evidence

[Production run 40403791934](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40403791934)
failed in its protected `Build (ferrum-edge-linux-aarch64)` producer:

- [Attempt 1](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40403791934/attempts/1),
  [ARM64 job 121856755990](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40403791934/job/121856755990),
  lost its runner early in compilation: “The runner has received a shutdown
  signal”. This attempt does not establish a compiler memory failure.
- [Attempt 2](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40403791934/attempts/2),
  [ARM64 job 121926746011](https://github.com/ferrum-edge/ferrum-edge/actions/runs/40403791934/job/121926746011),
  reached the gateway binary's `src/main.rs` fat-LTO `rustc` after dependency
  compilation. That single process was killed. The checksum-pinned resource
  observer's `--phase after` output proves host OOM, rather than merely an
  unexplained SIGKILL:

  ```text
  [Tue Oct 27 00:50:53 2026] oom-kill:constraint=CONSTRAINT_NONE,...,global_oom,task_memcg=/system.slice/docker-7a2f66...scope,task=rustc,pid=30068,uid=1001
  [Tue Oct 27 00:50:53 2026] Out of memory: Killed process 30068 (rustc) total-vm:25889204kB, anon-rss:15537336kB, ...
  ```

The excerpts above abbreviate the container scope and unrelated fields.
The host reported `MemTotal: 16373444 kB`, `SwapTotal: 3145724 kB`, no
cgroup memory limit, and approximately 86 GB free on `/`. The producer used
Ubuntu 24.04 and Cross 0.2.5 with `--features cloud-secrets`, `-C lto=fat`
and `-C codegen-units=1`.

Linux x86_64, both macOS targets, Windows x86_64, and both eBPF image builds
succeeded. Release version and SHA validation also succeeded. ARM64-dependent
publication skipped, and the GNU ABI and image-attestation gates failed
closed. Those successful jobs do not qualify a complete release. Any further
rerun of this tag still uses its original producer; it is not validation of
the changed producer described here.

## Recovery candidate

Keep the explicit Ubuntu 24.04 host restored for v0.9.17. Before the existing
`before` resource observation and Cross compilation, create a **32 GiB** swap
file at `/swapfile-ferrum-release` on the runner's root filesystem using only
host `fallocate`, `chmod`, `mkswap`, and `swapon`. Refuse an existing file or
symlink, restrict its permissions to `0600`, and stop the build if any command
fails. Keep the runner's existing swap enabled; this adds capacity without
requiring RAM to page everything back in first.

Print `swapon --show --bytes`, then require `/proc/swaps` to identify that
specific active file with at least 32 GiB minus 1 MiB of usable capacity,
allowing for swap metadata. Independently require at least that much total
swap in `/proc/meminfo`. The unchanged, checksum-pinned observer records
`SwapTotal`, `SwapFree`, RAM, disk, cgroup and kernel OOM observations after
provisioning and after compilation. No mutable third-party swap action or
download is introduced. Swap lives only on the disposable hosted runner.

Raise only this job's timeout from **120 to 240 minutes**. This doubles the
old job allowance and is over five times the historical 45m39s compile,
covering swap setup, image/sysroot preparation and slower disk-backed LTO.
It remains below the six-hour hosted-job default. This is a bounded recovery
allowance, not a measured successful duration: production timings must show
whether it is sufficient. A timeout, swap setup failure, OOM, or compiler
failure remains a release hold.

Refreeze the producer's pin-normalized exact SHA-256 job contract and add
regressions rejecting reduced swap, disabled/tolerated activation, bypassed
verification, or a changed deadline. The inherited environment and trigger
contracts, sanitized compiler command, fat LTO, codegen-units=1, feature set,
Cross/image/toolchain/action pins, ABI checks, artifact identities, signatures
and publication gates are preserved. The publication verifier and required
check inventory are unchanged.

## Alternatives and limits

`--jobs 1` limits concurrent Cargo compilation jobs; it cannot bound the
memory of the single gateway binary `rustc` that failed after its dependencies
finished. It therefore does not address this demonstrated peak. Adding swap
lets that process use disk-backed virtual memory without changing the
shipping optimization profile or compiler inputs. Reducing LTO, codegen
units, features, or publication checks is outside this recovery.

Swap trades speed for capacity. It does not guarantee completion, fix a
runner shutdown, or establish a new per-process peak-memory measurement.
Provisioning requires enough root disk space and host permission to enable
swap; failures stop before compilation. There is no paid runner or credential
change. The observer remains observational: missing telemetry stays explicit,
and absence of a matching kernel message cannot exclude another OOM.
