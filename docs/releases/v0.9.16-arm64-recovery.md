# ARM64 recovery after the v0.9.16 production failure

The immutable `v0.9.16` tag remains at
`4c81cb456f9723de42dbd7b0f09c3e3307d527d1`. It has no published GitHub
Release. [Production run 38048021101](https://github.com/ferrum-edge/ferrum-edge/actions/runs/38048021101)
failed in both attempts: the gateway's fat-LTO `rustc` process received
SIGKILL, then Cargo returned 101. The two compiler commands were identical.
Neither log proves OOM or a timeout. ARM64-dependent publication jobs skipped;
the GNU ABI and image-attestation gates failed closed. Eight independent jobs
succeeded. No binaries or images from another source can replace these inputs.

## Evidence and candidate

[v0.9.15's ARM64 producer](https://github.com/ferrum-edge/ferrum-edge/actions/runs/37823250818/job/113470001417)
at `25b37395ff61bfea0f3ffd189d9011c4984fa755` completed its compile in
48 minutes 33 seconds and uploaded both ARM64 assets. Its `ubuntu-latest`
label resolved to Ubuntu 24.04, image `20261004.327.1`. The failed v0.9.16
attempts used Ubuntu 26.04, image `20260927.149.1`.

The producer job differs only in its runner label. Cross.toml and
.cargo/config.toml are byte-identical, the release profile matches, and both
logs identify Rust 1.99.0 (`b940084d7`) and Cargo 1.99.0 (`5f94df478`).
Application source, including the vendored h2 implementation, also changed.
The runner difference therefore supports a controlled experiment, not a
causal diagnosis or a claim that the current source has passed on Ubuntu 24.04.

Restore only the ARM64 Cross producer to explicit `ubuntu-24.04`, rather than
the moving `ubuntu-latest` alias. Record host CPU, RAM, swap, disk, cgroup-root
counters and matching kernel OOM messages before and after compilation.
Unavailable or truncated observations remain explicit; no matching kernel
message does not exclude OOM. Host observations are not per-rustc peak memory
or proof about the removed Cross container. The observer reads fixed resources
and runs fixed diagnostic commands; it does not change the build environment,
compiler command, exit status or artifacts. The after step uses `always()`;
the compiler's failure still prevents asset creation and publication.
Both production observations verify the helper's pinned SHA-256 before
executing it. Editing the observer cannot add mutable automation to the frozen
producer; changed bytes fail closed and require another reviewed job refreeze.

The candidate workflow runs observation regressions and compares standard
Ubuntu 24.04/26.04 host resources without compiling or publishing. These checks
do not qualify production binaries. The protected production ARM64 job's
exact SHA-256 contract is refrozen; its environment and trigger contracts,
Cross/image/toolchain pins, fat LTO, codegen-units=1, features, ABI checks,
signatures and publication gates remain unchanged.

## Alternatives and limits

[`--jobs 1`](https://doc.rust-lang.org/cargo/commands/cargo-build.html)
limits concurrent Cargo jobs but does not bound the failing individual
fat-LTO process's peak memory. It has weaker direct historical evidence than
restoring the successful host, so this candidate leaves parallelism unchanged.
[GitHub's standard public runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)
list both Ubuntu 24.04 and 26.04 at 4 CPUs and 16 GB RAM. No free higher-memory
standard Linux runner was identified. No paid runner, credential or access
change is proposed. LTO reduction or gate bypass is not a recovery strategy.

## Admission and replacement version

This is a recovery candidate. The current trusted-base policy correctly
rejects the frozen producer and verifier edits; candidate self-tests cannot
authorize themselves or replace that gate. Landing requires a coordinated,
explicitly authorized frozen-policy migration after independent exact-head
review and all unrelated applicable checks. This draft does not alter the
trusted extraction workflow or grant a general exception. No bypass or
protected-main mutation is performed by preparing it.

A normal rerun of v0.9.16 still loads its original workflow. Preserve that tag.
The selected replacement patch version is **v0.9.17**. Its tag and GitHub
Release were absent during preparation. The candidate package, lockfile and
chart appVersions are 0.9.17. This version choice does not waive failed gates
or establish production success. Qualify the final merged source with all nine
publication checks, signed baseline/provenance and applicable affinity evidence;
then use the existing protected dispatcher and require the complete production
matrix, both gates, checksums and signed-image bindings. A failed build remains
a release hold. Publish matching Contracts from actual Edge receipts, and only
then apply the website updates. The candidate has not run a complete ARM64
production build and does not yet establish that a replacement release succeeds.
