# Ferrum Edge 0.9.21 publication record

Ferrum Edge [v0.9.21](https://github.com/ferrum-edge/ferrum-edge/releases/tag/v0.9.21)
was published on **2026-11-22 at 06:29:03 UTC** (GitHub Release `454250773`)
from immutable tag commit `f9915358c8032214f4034a17c28cdf72d14006c3`.
It is the current published release and follows published
[v0.9.20](v0.9.20-publication.md) directly.
Release changes and rollout requirements are in the
[changelog](../../CHANGELOG.md#0921---2026-11-21) and
[upgrade guide](../upgrade_guide.md#upgrading-to-0921).

## Release source

[PR #7470](https://github.com/ferrum-edge/ferrum-edge/pull/7470) prepared
0.9.21: the package, lockfile, OpenAPI and chart versions, the changelog
section and the upgrade guide. It changed no protected producer or verifier
surface. GPT-6.2 Sol and Gemini 4 Neon reviewed it, and it was merged with a
**merge commit** at `570d65ed2f7d44031ac2fe38cf0dcf5c01a08932`.

That merge commit could not be the release commit. On its first CI attempt the
`eBPF Live-Kernel Test` job, which the `Tests` aggregate requires on `main`,
lost its hosted runner ("The hosted runner lost communication with the
server") before any test ran, so that attempt's `Tests` check run concluded
failure. Only the failed jobs were rerun,
and they passed. The publication gate requires every `Tests` check run in the
canonical CI suite to succeed, including superseded attempts, so
[Start Production Release run 44964169295](https://github.com/ferrum-edge/ferrum-edge/actions/runs/44964169295)
refused `570d65ed2f` and created no tag.

Following [docs/ci_cd.md](../ci_cd.md#creating-a-new-release), the docs-only
follow-up [PR #7472](https://github.com/ferrum-edge/ferrum-edge/pull/7472)
became the release commit. It rewrote the CHANGELOG GHSA-49cr-v28q-9hgp entry
to state each plugin's duplicate-member JSON handling, the one review finding
left open on #7470. Sol and Neon reviewed it, and it was merged with a merge
commit at `f9915358c8032214f4034a17c28cdf72d14006c3`. Its first parent is
`570d65ed2f7d44031ac2fe38cf0dcf5c01a08932`, its second parent is the reviewed
head `ee71a8e43ef242f9a4e6c8794641ff3875e681bf`, and the merge tree equals that
head's tree. Every workflow triggered by the push to `main` at the release
commit succeeded on its first attempt.

## Production publication evidence

[Start Production Release run 44972313853](https://github.com/ferrum-edge/ferrum-edge/actions/runs/44972313853)
ran from `main` at the release commit. Its validation job passed every
publish-blocking check for that exact commit between 01:37:29 and 01:37:51 UTC.
It then created the `v0.9.21` tag, which triggered the release run at
01:37:58 UTC.

[Release run 44972356983](https://github.com/ferrum-edge/ferrum-edge/actions/runs/44972356983)
published the release on its second attempt:

- On the first attempt, both macOS binary builds hit the 165-minute
  `Build release binary` step timeout while compiling, on runners with a
  macOS capacity notice. No GitHub Release was created, and the two
  retraction gates failed with nothing to retract. Only the failed jobs were
  rerun.
- On the second attempt, the macOS builds finished at 05:17:04 UTC (aarch64)
  and 06:25:51 UTC (x86_64). The default, `-ebpf` and `-ebpf-tools` image
  manifests were pushed, and the GitHub Release was published at 06:29:03 UTC
  (the `Create GitHub Release` job completed at 06:29:06 UTC). The
  `Sign and attest release images` job completed successfully at 06:32:16 UTC,
  and both final publication gates (Linux GNU ABI and image attestation)
  succeeded.
- The `Anonymous image pull smoke` job failed. Its anonymous pulls of
  `docker.io/ferrumedge/ferrum-edge:v0.9.21` and
  `ghcr.io/ferrum-edge/ferrum-edge:v0.9.21` passed. Its SQLite volume smoke,
  first run against a published image in this release, stopped at its initial
  identity check: it expects the image `User` to read `65532:65532` or
  `nonroot:nonroot`, while the distroless `nonroot` base (unchanged in this
  respect since v0.9.20) reports `65532`. The job does not gate publication.
  It is recorded here as an open follow-up rather than rerun, because a rerun
  would fail the same way.

The published release contains all five gateway binaries and both Linux CNI
binaries, each with its checksum file.
