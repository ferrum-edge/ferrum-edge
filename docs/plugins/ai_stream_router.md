# ai_stream_router

Part of the [Plugin Reference](../plugins.md).

**Priority:** 2984 · **Phases:** `before_proxy`, `transform_request_body`, `enforce_final_backend_header_policy`, `on_final_request_body`, `normalize_response_body`, `after_proxy`, `response_stream_inspector` · **Protocols:** HTTP · **Failure policy:** `FailClosed`

Streaming counterpart to `ai_federation` — the answer to "can I use Ferrum as my OpenAI-compatible **streaming** AI gateway?". It runs at priority `2984`, before `ai_federation` (`4060`), and claims **only** OpenAI Chat Completions requests with a real `"stream": true` boolean. Non-streaming requests are left untouched for `ai_federation` to handle.

Unlike `ai_federation`'s buffered "terminate and respond" pattern, `ai_stream_router` does **not** make its own HTTP call. In `before_proxy` it rewrites the request's routing decision (`route_override_backend_scheme` / `_host` / `_port` / `_path` / `_authority`, with `route_override_path_is_absolute = true`) so the **normal proxy dispatch path** streams the provider response straight back to the client. This preserves true end-to-end streaming. The claim then commits its own egress policy rather than inheriting the proxy's: an `https` provider endpoint is verified against the built-in public trust roots only — isolated from every gateway-global backend TLS fallback (`FERRUM_TLS_CA_BUNDLE_PATH` is not used, `FERRUM_TLS_NO_VERIFY` cannot disable verification, and the global `FERRUM_BACKEND_TLS_CLIENT_CERT_PATH` / `_KEY_PATH` identity is never presented) — unless that provider sets `inherit_backend_tls: true`, and any `dns_override` inherited from the matched proxy is explicitly revoked so the provider host always resolves through provider DNS. (`ai_federation` honors only the global TLS settings and cannot opt back into per-proxy backend TLS at all.)

```yaml
plugin_name: ai_stream_router
config:
  enabled: true
  fail_on_missing_model: true
  fail_on_no_matching_provider: true
  inject_usage_options: true
  normalize_response_stream: true
  providers:
    - name: openai
      provider_type: openai
      endpoint: https://api.openai.com/v1/chat/completions
      api_key: ${FERRUM_PLUGIN_SECRET_OPENAI_API_KEY}
      model_patterns: ["gpt-*", "o*"]
      priority: 1
    - name: anthropic
      provider_type: anthropic
      endpoint: https://api.anthropic.com/v1/messages
      api_key: ${FERRUM_PLUGIN_SECRET_ANTHROPIC_API_KEY}
      model_patterns: ["claude-*"]
      priority: 2
      anthropic_version: "2023-06-01"
```

**Root configuration:**

| Parameter | Type | Default | Description |
|---|---|---|---|
| `enabled` | Boolean | `true` | Master switch. When false the plugin never claims a request. |
| `fail_on_missing_model` | Boolean | `true` | Reject a streaming request that has no top-level string `model` with an OpenAI-shaped `400`. |
| `fail_on_no_matching_provider` | Boolean | `true` | Reject a streaming request whose `model` matches no configured provider with an OpenAI-shaped `404`. |
| `inject_usage_options` | Boolean | `true` | Inject `stream_options.include_usage: true` for `openai` / `openai_compatible` providers so a final usage event is emitted. |
| `normalize_response_stream` | Boolean | `true` | Normalize provider-native SSE to OpenAI `chat.completion.chunk` SSE. Disabling forwards provider-native SSE verbatim. |
| `max_stream_bytes` | Integer | `8388608` (8 MiB) | Cumulative provider plaintext one Anthropic/Gemini normalizer accepts before failing closed, `1048576`–`268435456`. A residual provider `Content-Encoding` is still decoded under the fixed 8 MiB per-layer residual-decode limit. |
| `max_stream_events` | Integer | `100000` | Complete provider events one normalizer accepts, `1000`–`10000000`. |
| `max_normalized_stream_bytes` | Integer | `16777216` (16 MiB) | Cumulative OpenAI-shaped output one normalizer may emit, `1048576`–`536870912`. Buffered normalization is additionally bounded by the response's retained ceiling. |
| `providers` | Array | — | **Required**, non-empty. See below. |

**Provider configuration (`providers[]`):**

| Parameter | Type | Default | Description |
|---|---|---|---|
| `name` | String | — | **Required**, non-empty, unique within the instance. Surfaced as `ai_stream_router.provider`. |
| `provider_type` | String | — | **Required**. One of `openai`, `openai_compatible`, `azure_openai`, `anthropic`, `google_gemini`. |
| `endpoint` | String | — | **Required** absolute `https://` URL (or `http://` with `allow_plaintext`). May carry a literal `{model}` path placeholder and its own query string. A `google_gemini` endpoint without `{model}` is admitted only when `model_patterns` is the single exact model name the endpoint path itself names (`.../models/<model>:...`): Gemini routes the model only through the URL, so a fixed-model endpoint behind a wildcard, several names, or a different name would generate every admitted model with the endpoint's own model while stamping the requested one. Embedded userinfo (`user:password@`) and a `#fragment` are rejected (neither is ever sent). A literal-IP host is checked against the gateway backend egress policy at admission, and an explicit port `0` is rejected (an outbound destination cannot use port zero). |
| `api_key` | String | — | **Required**, non-empty. A whole-value `${FERRUM_PLUGIN_SECRET_<NAME>}` reference is resolved from the process environment at construction; a `${...}` reference to any other variable (including every other `FERRUM_*` setting) is refused at admission, and an unset or empty referenced variable fails construction. The resolved value must be a valid HTTP header value, so a stray newline is a configuration error rather than a `502` on every request. |
| `model_patterns` | Array | — | **Required**, 1–128 globs matched against the request `model`. Each glob is 1–256 ASCII bytes containing only letters, digits, `.`, `_`, `:`, `/`, `+`, `-`, and `*`, with no `..` sequence; unsupported wildcards such as `?` or `[` fail admission. `*` is the only wildcard, never consumes a URL-structural separator (`/`, `?`, `#`, `&`, `\`) or whitespace, and the pattern is anchored at both ends — so `*mini` matches `model-mini` and `mini-mini` alike, and never matches `mini-pro`. |
| `priority` | Integer | provider index + 1 | Lower is matched first. Must be at least `1` and fit in a `u32`. |
| `allow_plaintext` | Boolean | `false` | Required opt-in for an `http://` endpoint: plaintext provider egress is rejected at admission without it. It has no effect on an `https` endpoint and does not relax runtime TLS or FIPS policy. Use it only for an internal, same-trust-domain provider. |
| `anthropic_version` | String | `2023-06-01` | `anthropic-version` header value sent to `anthropic` providers. Must be a non-empty valid HTTP header value (an explicit `null` keeps the default; `""` is rejected). |
| `default_max_tokens` | Integer | `4096` | `anthropic` providers only (rejected on any other type). Anthropic `max_tokens` forwarded when the OpenAI request sets neither `max_tokens` nor `max_completion_tokens`, `1`–`4294967295`. |
| `inherit_backend_tls` | Boolean | `false` | Keep the proxy's own resolved backend TLS (custom CA bundle, SNI/SAN policy, backend mTLS client certificate — including the gateway-global fallbacks that resolution normally inherits) for this `https` provider. By default the provider is verified against the built-in public roots only, with no global CA bundle, no `FERRUM_TLS_NO_VERIFY`, and no gateway client certificate. No effect on an `http` endpoint. |

Every optional field also accepts an explicit `null`, which means "omitted" and keeps the documented default. A present value of the wrong JSON type is rejected — it is never coerced or silently defaulted.

An internal, plaintext provider therefore looks like this:

```yaml
plugin_name: ai_stream_router
config:
  providers:
    - name: internal-vllm
      provider_type: openai_compatible
      endpoint: http://vllm.internal.svc.cluster.local:8000/v1/chat/completions
      allow_plaintext: true
      api_key: ${FERRUM_PLUGIN_SECRET_INTERNAL_VLLM_KEY}
      model_patterns: ["llama-*", "mistral-*"]
```

**Provider types (MVP):**

- `openai` / `openai_compatible` — route + header rewrite only. The request and the provider's response SSE are already OpenAI-shaped, so the stream passes through unchanged (with optional `stream_options.include_usage` injection when `inject_usage_options: true`). No response-stream inspector runs, so these requests stay on the fast dispatch path.
- `azure_openai` — the same OpenAI-shaped passthrough for an Azure OpenAI deployment endpoint (for example `https://<resource>.openai.azure.com/openai/deployments/<deployment>/chat/completions?api-version=2024-10-21`), authenticated with the `api-key` header instead of `Authorization: Bearer`. Entra ID (OAuth2) tokens expire and cannot be static configuration, so they are not supported; neither are Vertex AI OAuth2 or Amazon Bedrock SigV4 (use `ai_federation` for those non-streaming).
- `anthropic` — the OpenAI request is translated to the Anthropic Messages API streaming request (system extraction, user/assistant/tool messages, `max_tokens`, `temperature`, `top_p`, `stop` → `stop_sequences`, `tools`/`tool_choice`, optional Anthropic `thinking`, `reasoning_effort` → `output_config.effort`, assistant `tool_calls` → `tool_use` blocks, matching `role: "tool"` → user `tool_result` blocks, legacy assistant `function_call` → `tool_use` with a deterministic `call_legacy_<index>` id, matching `role: "function"` → user `tool_result` blocks correlated by function name, `stream: true`). Message `content` is closed-shape at claim admission: a string or an array of text-part objects with exactly `type` and `text` may be translated, and a **user** message may also carry base64 data-URL `image_url` parts (`data:image/jpeg|png|gif|webp;base64,…`, optional `detail`, at most 20 MiB of base64 each, validated with a real standard-alphabet base64 decoder so bad padding or truncated quanta are refused), which become ordered Anthropic `text` / base64 `image` blocks; remote `http(s)` image URLs, other media types, malformed base64, audio/unknown parts, extra/unknown fields on a part, non-object array members, null system/developer content, and non-text system/developer/assistant content are rejected with an OpenAI-shaped `400` rather than silently reduced (diagnostics never echo the URL or payload). Intentional assistant null/empty content is preserved only when the same message carries a valid `tool_calls` or legacy `function_call` representation. OpenAI request parameters are mapped exactly or refused, never silently dropped: `parallel_tool_calls: false` becomes `tool_choice.disable_parallel_tool_use: true` when tools are callable; `n > 1`, non-zero `presence_penalty` / `frequency_penalty`, any `seed`, non-empty `logit_bias`, `logprobs: true` / `top_logprobs`, and a JSON `response_format` (`json_object` / `json_schema`) are rejected with an OpenAI-shaped `400` naming the parameter (`n: 1`, zero penalties, `{}` bias, `logprobs: false`, and `{"type":"text"}` are accepted as no-ops). A present non-null `max_tokens` / `max_completion_tokens` must be a positive integer (a string, float, zero, or negative value is a `400`); when the client sets neither, the provider's `default_max_tokens` (default `4096`) is forwarded. OpenAI `tool_choice: "none"` is translated to Anthropic `{"type":"none"}` while the request's `tools` list is retained; OpenAI string forms are limited to `none` / `auto` / `required` (`required` → Anthropic `{"type":"any"}`), and named choices must be exactly `{type:"function", function:{name:...}}`. Raw input string `any` is rejected. Optional Anthropic `thinking` is admitted only as closed shapes (`enabled` with `type`+`budget_tokens`, `adaptive` with `type` and an optional `display` of `summarized` or `omitted`, or `disabled` with exactly `type`); OpenAI `reasoning_effort` maps to Anthropic `output_config.effort` for `low`/`medium`/`high`/`xhigh`/`max`, and `none`/`minimal` (which have no Anthropic counterpart) or any other value are rejected with an OpenAI-shaped `400`; manual `enabled` requires `budget_tokens >= 1024` and `budget_tokens` strictly less than the effective Anthropic `max_tokens` this route forwards. Forced tool use is incompatible with manual extended thinking (`thinking.type: "enabled"`) and is rejected, and any extended thinking — manual `enabled` or `adaptive` — is rejected whenever tools are callable (declared `tools` with a `tool_choice` other than `none`, including forced `required` / named choices) or the request continues a tool turn (the last assistant message carries `tool_calls` / `function_call`): Anthropic requires the complete, unmodified signed `thinking` / `redacted_thinking` blocks emitted in a tool-use turn to be replayed with its tool results, and the OpenAI Chat Completions representation has no carrier for them, so manual mode would fail at the provider and adaptive mode would silently lose the turn's reasoning state. Use `tool_choice: "none"` or disable thinking for tool turns. Unsupported, malformed, or structurally ambiguous `tool_choice` / `thinking` values are rejected with an OpenAI-shaped `400` at admission rather than silently falling through to the provider default. Malformed tool-call history (bad argument JSON, missing ids, orphaned tool/function results, mixed modern `tool_calls` with legacy `function_call` history, oversized argument strings, unsupported roles) is likewise rejected with an OpenAI-shaped `400` rather than silently dropped. A `ResponseStreamInspector` then normalizes Anthropic SSE events into OpenAI `chat.completion.chunk` SSE on the fly: `content_block_delta` text deltas → `choices[].delta.content`, tool-use blocks / `input_json_delta` → `choices[].delta.tool_calls`, `message_delta` records the terminal reason and cumulative usage; `message_stop` emits exactly one `finish_reason`, known usage, and `data: [DONE]`. Missing/null intermediate reasons do not finish the response. `refusal` maps to `content_filter`, and unsupported reasons fail with an upstream error, matching buffered Anthropic reason mapping. When no reason arrives, `message_stop` uses `tool_calls` if client tools were emitted, otherwise `stop`. Usage from `message_start` is retained even without `message_delta`; unknown counts remain null, not zero. Only client `tool_use` blocks become tool calls; provider-executed `server_tool_use` and `mcp_tool_use` blocks remain outside the client tool-call representation. When the caller constrained the turn with `tool_choice: "none"`, any provider `tool_use` (or `stop_reason: "tool_use"`) fails closed with an `upstream_error` SSE frame instead of being normalized into executable OpenAI `tool_calls` deltas; the restriction is request-local and does not cross generations. Successful termination requires Anthropic `message_stop` (or an explicit provider `error` event); clean EOF before that state, and malformed complete/trailing SSE event data, surface an `upstream_error` SSE frame plus exactly one `[DONE]` instead of synthesizing a success-only sentinel. Terminal `message_stop` / provider `error` / fail-safe paths `Terminate` the inspector driver so upstream read stops immediately. The normalizer is robust to chunk splits — it accumulates raw bytes in a cursor-addressed buffer and only transcodes complete SSE events — and enforces fixed security-hardening bounds before UTF-8 conversion, JSON parse, or transcode: **1 MiB per SSE event** (including when a complete oversized event and its blank-line boundary arrive in one chunk), **8 MiB cumulative Anthropic plaintext** by default (`max_stream_bytes`; residual content-coding decode, including per-layer decode of stacked `gzip`/`br` chains, keeps its fixed 8 MiB layer limit), **16 MiB cumulative normalized OpenAI SSE output** by default (`max_normalized_stream_bytes`), **100000 events** by default (`max_stream_events`), and **JSON nesting depth 32**. A claimed normalizing 2xx response whose `Content-Type` is missing or not `text/event-stream` fails closed through `after_proxy` (OpenAI-shaped `502`), the stream inspector, and buffered normalization rather than streaming provider-native bytes under the OpenAI contract. Residual provider `Content-Encoding` chains reuse the shared bounded content-coding decoder (at most **4** layers, **1024:1** amplification). Overflow fails closed with a stable `upstream_error` SSE frame + `data: [DONE]` (diagnostics never echo provider payload). Unknown Anthropic event types are ignored for forward compatibility.
- `google_gemini` — the OpenAI request is translated to a Gemini/`streamGenerateContent` body (`contents`, optional `systemInstruction`, `generationConfig`, `tools`/`toolConfig`, assistant `functionCall` history and matching `functionResponse` / legacy `role: "function"` results). Authentication is the `x-goog-api-key` header; Vertex AI endpoints that require Google OAuth2 are not supported. Message `content` is closed-shape at claim admission: a string or an array of text-part objects with exactly `type` and `text` may be translated, and a **user** message may also carry base64 data-URL `image_url` parts (same media types and bounds as Anthropic) that become ordered Gemini `text` / `inlineData` parts; remote image URLs, other media, extra/unknown fields on a part, non-object array members, null system/developer/user content, and non-text system/developer/assistant content are rejected with an OpenAI-shaped `400` rather than silently reduced. OpenAI generation parameters with exact Gemini equivalents are mapped — `max_tokens` / `max_completion_tokens` → `maxOutputTokens` (positive integer required), `n` → `candidateCount`, `presence_penalty` → `presencePenalty`, `frequency_penalty` → `frequencyPenalty`, `seed` → `seed`, `response_format: {"type":"json_object"}` → `responseMimeType: "application/json"`, and `response_format: {"type":"json_schema","json_schema":{"name":…,"schema":{…}}}` → `responseMimeType` plus `responseJsonSchema` (closed shape; `strict` / `description` optional; a `strict: true` schema must use only the keywords Gemini enforces — `type`, `title`, `description`, `enum`, `format` (`date-time` / `date` / `time`), `anyOf`, local `#…` `$ref` without sibling constraints, `$defs`, `properties`, `required`, `additionalProperties`, `items`, `prefixItems`, `minItems`, `maxItems`, `minimum`, `maximum`, at most 32 levels deep — or it is rejected, so `minLength`, `pattern`, `uniqueItems`, `oneOf`, `const`, and similar constraints are never silently unenforced; a non-strict schema is forwarded as-is, best-effort as in OpenAI's own contract) — while non-empty `logit_bias`, `logprobs: true` / `top_logprobs`, an unrecognized `response_format`, and `parallel_tool_calls: false` with callable tools (Gemini has no single-call switch) are rejected with an OpenAI-shaped `400` naming the parameter. **Thought signatures.** Gemini thinking models attach an opaque `thoughtSignature` to function-call parts (and to text parts, including an empty final text part while streaming). A bounded base64 signature is the one recognized sibling field on a `text` / `functionCall` part, or on an otherwise empty part; a function-call signature is surfaced on the normalized OpenAI tool call as `extra_content.google.thought_signature` (Google's OpenAI-compatibility field), and request translation restores a client-echoed `tool_calls[i].extra_content.google.thought_signature` onto that same `functionCall` part so Gemini 3 tool continuations validate. Text-part signatures are accepted and not surfaced (they are not required for continuation). A malformed signature on either side fails closed. Intentional assistant null/empty content is preserved only when the same message carries a valid `tool_calls` or legacy `function_call` representation. The model is URL-scoped via an optional `{model}` endpoint placeholder; when response normalization is enabled the claim injects `alt=sse` if absent so native Gemini uses documented SSE framing, while Vertex-compatible JSON array / object streams remain accepted. A claimed normalizing 2xx response with a missing or unexpected `Content-Type` fails closed through `after_proxy` / stream inspector / buffered normalization (bounded OpenAI-shaped upstream error; non-2xx provider error envelopes still pass through untouched). Recognized `text/event-stream` and `application/json` remain accepted. A `ResponseStreamInspector` normalizes provider frames into OpenAI `chat.completion.chunk` SSE: text parts → `choices[].delta.content` (including multi-candidate `index`), `functionCall` → `tool_calls`, `finishReason` / prompt-block safety → terminal `finish_reason`, `usageMetadata` → a terminal usage chunk when present (a present `usageMetadata` must be an object; present `promptTokenCount` / `candidatesTokenCount` / `completionTokenCount` / `thoughtsTokenCount` / `toolUsePromptTokenCount` / `totalTokenCount` must be JSON integers representable as `u64`, with no silent fallback from a malformed preferred field to an alternate; omission remains allowed and is never charged as zero). The normalized usage keeps the provider's billable categories: Gemini bills thinking output and tool-use prompting outside `candidatesTokenCount`, so `thoughtsTokenCount` is added to `completion_tokens` (and republished as `completion_tokens_details.reasoning_tokens`), `toolUsePromptTokenCount` is added to `prompt_tokens`, and the provider's own `totalTokenCount` is preserved as `total_tokens` rather than replaced by a smaller recomputed sum — a `total_tokens` budget on a normalized route therefore charges what a native Gemini route would. Every addition is checked and overflow fails closed, and provider `error` envelopes → a bounded `upstream_error` frame (message capped; never echoes credentials, tool args, or oversized bodies). Present-but-malformed candidate fields fail closed rather than falling back: a present `index` must be a `u64`, a present `finishReason` must be a string, and a present `content.role` must be the string `model` (missing `index` still uses the documented positional fallback). Content part objects that include a representable `text` or `functionCall` field plus additional unrepresentable fields fail closed instead of emitting the representable subset. OpenAI `tool_choice: "none"` becomes Gemini `functionCallingConfig.mode: "NONE"`; provider function calls under that constraint fail closed. Successful termination requires every candidate that emitted client-visible output to reach a terminal `finishReason` (or a prompt block / explicit error) before EOF — a finished candidate cannot emit later content/tool deltas or a second terminal state, and duplicate candidate indexes within one provider event fail closed. Content parts are closed-shape (`text` / `functionCall`, each optionally with a `thoughtSignature`); unrepresentable or unknown parts (including scalars, media, code, `thought: true` summaries, and other metadata-only objects) fail closed with fixed-cardinality diagnostics that never echo provider data. The metadata-only exceptions are an empty JSON object `{}` and a part holding only a valid `thoughtSignature`. Premature EOF and malformed/oversized/deep JSON fail closed under the same SSE bounds as Anthropic (**1 MiB/event**, **8 MiB** plaintext, **16 MiB** normalized output, **100000** events, **JSON depth 32**), including the shared residual content-coding decoder for stacked `gzip`/`br` chains. Because the JSON-array/object fallback is normalized into SSE, the response `Content-Type` is relabelled `text/event-stream` (a provider label that is already `text/event-stream`, including its `charset` parameter, is left verbatim) — clients and intermediaries must never see OpenAI `chat.completion.chunk` frames plus `data: [DONE]` under an `application/json` label. Provider chunk framing is scanned incrementally, so a provider that splits a value across many small TCP segments costs work linear in the stream size rather than quadratic. A `promptFeedback.blockReason` terminal obeys the same candidate lifecycle as any other terminal: it never emits a second, contradictory terminal chunk for a candidate that already finished, and it fails closed (rather than closing with the success-shaped terminal) when another candidate emitted client-visible output without reaching a terminal `finishReason`. A `role: "tool"` message whose `tool_call_id` does not match a preceding assistant `tool_calls` entry is rejected at claim admission with the precise `messages[i]` diagnostic — the same rule the translator enforces — instead of falling through to the generic "could not be translated safely" `400`. **Known fidelity gaps.** The `MALFORMED_FUNCTION_CALL` and `UNEXPECTED_TOOL_CALL` finish reasons map to OpenAI `content_filter` because OpenAI has no closer equivalent — those two mean the model emitted a broken or unexpected tool call, not that a safety policy fired.

**Provider SSE framing.** Provider event streams are parsed against the WHATWG event-stream grammar rather than one hard-coded delimiter: an event ends at a blank line, and every line terminator may be LF, CRLF, or a lone CR, in any legal mix and split across transport chunks at any byte. A Gemini/Vertex response may additionally open with a UTF-8 byte-order mark or with any legal SSE preamble field (`id:`, `retry:`, a `:` comment) before its first `data:` event. The JSON-object/array fallback is unchanged — a first non-whitespace byte of `{` or `[` selects it — and only a stream that opens with a control byte (binary, not text) is refused as unrecognized framing.

**Header rewriting.** Every canonical client credential header — `Authorization`, `Proxy-Authorization`, `Cookie`, `X-API-Key`, `API-Key`, `APIKey`, `X-Goog-Api-Key`, `X-Access-Token`, `X-Auth-Token`, `X-Amz-Security-Token`, `X-Forwarded-Authorization` (the same set replay partitioning treats as caller credentials), matched case-insensitively and with `_` treated as `-` — plus this route's own configured authentication header locations (custom JWT/JWKS, OAuth, and key-auth header names) and the provider-protocol headers `anthropic-version`, `anthropic-beta`, `openai-beta`, `openai-organization`, and `openai-project` are stripped before forwarding (unlike `ai_federation`, this path reuses the client's header map, so session-bearing headers must be dropped explicitly), and the provider's credential is injected (`Authorization: Bearer …` for OpenAI-compatible, `api-key` for Azure OpenAI, `x-api-key` for Anthropic, `x-goog-api-key` for Google Gemini). `Host`, `Content-Type: application/json`, and `Accept: text/event-stream` are set for the provider. When provider SSE/stream framing will be normalized, every client `Accept-Encoding` variant is replaced with `Accept-Encoding: identity` so the provider does not return gzip/br octets that the line-delimited normalizer would misread. Because normalization rewrites the client-visible representation even when the provider sends identity bytes, representation headers (`Content-Encoding`, `Content-Length`, content-bound validators, and `Vary: Accept-Encoding`) are always repaired. If a provider still returns a non-identity `Content-Encoding`, Ferrum parses the header as an RFC 9110 `#content-coding` list (OWS-tolerant, case-insensitive; `x-gzip` normalized to `gzip`) and decodes supported chains (`gzip` / `br`, including stacked lists such as `gzip, br`) in reverse application order under the shared residual-decode limits — **8 MiB per layer**, **16 MiB aggregate decoded work**, **at most 4 layers**, and a **1024:1** raw-to-decoded amplification ratio (the same ratio the compression request path uses). `identity`-only lists are treated as identity; mixed `identity`, parameters, empty members, unsupported codings (`zstd`, `deflate`, …), more than four layers, ambiguous case-variant duplicate field-lines, truncated/malformed/concatenated members, and limit overruns fail closed with an OpenAI-shaped `502` before any opaque provider frame can be served as normalized AI output. Residual encoded streaming responses use a bounded fallback that holds encoded octets until EOF (never forwarding them mid-stream) and decodes only after the complete coding and checksum can be validated; ordinary identity SSE remains progressive. Gateway-asserted consumer-identity headers (`x-consumer-username` / `x-consumer-custom-id`) are also **suppressed** for claimed requests via the shared `suppress_backend_consumer_identity_headers` metadata marker, so an authenticated consumer's internal identifiers never reach the third-party provider (the resolved principal still drives rate limiting, logging, and policy plugins).

**Endpoint URLs.** An endpoint that carries its own query string (e.g. an Azure-style `?api-version=…`) is preserved: the endpoint query and the client's own query are merged with `&` into the forwarded URL (the client's parameters are marked as consumed so the dispatch path does not append a second `?`). IPv6 literal hosts are bracketed in the forwarded authority/`Host`. By default an `https` endpoint is verified against the built-in public trust roots only (the `system://` trust source), isolated from every gateway-global backend TLS fallback: a private `FERRUM_TLS_CA_BUNDLE_PATH` does not replace the public roots, `FERRUM_TLS_NO_VERIFY` cannot disable verification, and the global `FERRUM_BACKEND_TLS_CLIENT_CERT_PATH` / `_KEY_PATH` identity is never offered to the provider (the isolation is part of every backend TLS pool and config-cache key, so such a client is never shared with one built from the global pair). Set `inherit_backend_tls: true` on a provider to keep the proxy's own resolved backend TLS (custom CA bundle, SNI/SAN policy, backend mTLS client certificate, and the global fallbacks it normally inherits) for internal `openai_compatible` endpoints behind private PKI.

**Final provider boundary.** Claiming in `before_proxy` at 2984 only orders this plugin ahead of the plugins that run before it. `request_transformer` runs at 3000, and a `serverless_function` `pre_proxy` backend header overlay is merged later still — either could add, overwrite, or rename the provider credential this plugin just installed, leak a normal-backend static secret to the third party, restore a client credential, or rewrite the already-selected `model` in the translated body. Two shared lifecycle boundaries close that window, and neither depends on relative priority:

- **Header re-assertion.** The plugin declares `enforces_final_backend_header_policy()`, so the gateway re-applies its complete owned header set over the *finalized* backend-visible header map — after every `before_proxy` pass (including the deferred routing/remaining passes), after the reserved gateway-assertion refresh and egress baggage strip, and after a finalized-egress header overlay — on the H1/H2 and native HTTP/3 ladders alike. Every credential header listed above is re-stripped, gateway-asserted `x-consumer-username` / `x-consumer-custom-id` / `x-geo-country` are removed again, and only the selected provider's own credential (plus `Host`, `Content-Type`, `Accept`, `anthropic-version`, and the normalization `Accept-Encoding: identity`) is installed. The owned set is closed; headers outside it are untouched, so intended non-credential operator transforms still reach the provider. Ferrum does **not** attempt to classify an arbitrary unknown custom header as a credential — a bespoke normal-backend secret header that is neither a canonical credential name nor one of the route's configured authentication locations will still be forwarded, so do not configure such a rule on a proxy that routes to a third-party provider.
- **Query commitment.** `request_transformer` query rules also run later (3000) and could otherwise append a normal-backend static secret to the provider URL. The claim therefore freezes the exact safe backend-visible query at claim time — after the authentication-owned strip markers and any earlier plugin's published outbound query — and the gateway replays that frozen value at the single point where the backend-visible query is captured, on H1/H2, on native HTTP/3, and for every retry attempt. When an endpoint query is folded into the absolute override path, the separately appended query is committed **empty**; otherwise the already-safe client query continues unchanged. The committed query lives in private request state, never in metadata or a transaction log.
- **Destination, TLS, and DNS commitment.** A visible host/port match is not destination identity. The claim commits a *direct* provider endpoint: it clears any earlier `route_override_upstream_id` (so no load balancer can pick the dial target), pins the exact resolved backend TLS configuration (verification flag, SNI, CA bundle, and mTLS client materials — with plaintext HTTP represented as a distinct "no TLS" state), and explicitly revokes any inherited proxy `dns_override` even when the configured backend host text already equals the provider host. Without that last step, a same-host DNS pin would send the provider credential to an operator-chosen address instead of provider DNS.
- **Body / model / route revalidation.** `on_final_request_body` re-parses the exact backend-visible body after every `transform_request_body` hook and fails closed unless the provider-visible `model` is a non-empty string that is still *exactly* the model which selected this provider **and** still matches that provider's `model_patterns`. A body that is no longer valid JSON, has no usable `model`, or carries duplicate JSON members (which would make the provider-visible generation parser-dependent) is rejected the same way, as is any drift in the committed destination / upstream identity / resolved TLS / DNS decision above. Model failures return an OpenAI-shaped `400` (`code: model_policy_violation`); a broken provider/route invariant returns a `500` (`code: provider_policy_violation`). No offending model, header, query, or body value is echoed into the error envelope or logged.

**Multiple instances.** Several `ai_stream_router` instances may be effective on one proxy, and two of them may legitimately share a provider `name` while differing in endpoint, API key, `provider_type`, `model_patterns`, and `normalize_response_stream`. Exactly one instance can claim a request: the first (in configured priority order) whose provider matches wins, and later instances leave the claim alone. Ownership is recorded as an opaque per-instance identity in private request state — never in metadata, logs, configuration, OpenAPI, or a response — and every claim-dependent hook verifies it: request-body transformation, final header re-assertion, final body/route revalidation, response-header handling, and response stream inspector / normalizer selection. A losing instance therefore cannot reapply its own credential, translate the body a second time, revalidate against the wrong model policy, or install a second SSE normalizer. `fail_on_missing_model` and `fail_on_no_matching_provider` still decide an *unclaimed* request in normal plugin order; ownership begins only once some instance has successfully claimed.

Because that header mutation happens after every `before_proxy` hook, no fingerprint taken during that phase can witness it: plugin-cache admission **rejects** `ai_stream_router` composed with `request_deduplication` on the same proxy and protocol. (`response_caching` is refused alongside this plugin by its deferred-request-body-transformer rule.)

**Composition with other built-ins.** Because `ai_stream_router` runs first, a successful claim records a private typed claim on the request context and also publishes `ctx.metadata["ai_stream_router_claimed"] = "true"` for logs and third-party/custom plugins. Every BUILT-IN that must stand down on a claimed provider request — `ai_federation`, `request_mirror`, `serverless_function`, `mcp_gateway`, and `mesh_route_dispatch` — decides from that **private claim**, never from the metadata key: metadata is a mutable string map, so a later plugin deleting or rewriting the marker would otherwise let those plugins re-route, mirror, federate, or invoke a function over a request whose third-party provider credential, model, destination, and query are already committed. The two plugins split the work: `stream: true` is served by `ai_stream_router`, `stream: false` by `ai_federation`. Intentional **pass-through** (`fail_on_missing_model` / `fail_on_no_matching_provider` disabled) is a genuinely unclaimed request and still coordinates through `ctx.metadata["ai_stream_router_pass_through"]`. Claimed requests also set the shared `ai_request_streaming` marker for non-policy streaming helpers such as token metrics. The marker is not authority to waive an outbound security policy: `ai_response_guard`, WAF response-body inspection, response validators, and strict response-size policy buffer conservatively and decide from the pristine backend representation. In particular, an enforcing/redacting `ai_response_guard` rejects a genuine provider SSE response before commit because it cannot promise complete bounded inspection; use a stream-aware policy such as `ai_semantic_firewall` progressive inspection instead of relying on the marker.

**Metadata keys written:** `ai_stream_router.enabled`, `ai_stream_router.claimed`, `ai_stream_router_claimed`, `ai_request_streaming`, `suppress_backend_consumer_identity_headers`, `ai_stream_router.provider`, `ai_stream_router.provider_type`, `ai_stream_router.model`, `ai_stream_router.request_translated`, `ai_stream_router.tool_choice_none` (when the translated Anthropic request forbids tools for this generation), `ai_stream_router.normalized_response_stream`, and `ai_stream_router.provider_content_encoding` (when a residual provider coding must be decoded). There is no `ai_stream_router.fallback_attempts` key — the plugin never attempts a second provider, so a permanently-zero counter would only advertise a capability that does not exist. Every one of these keys is **observability and cross-plugin coordination only**; a later plugin may write any of them and no enforcement point reads them back. The committed **model**, destination, resolved backend TLS, DNS decision, backend-visible query, Anthropic-translation witness, tool-use guard, and instance-ownership identity are deliberately **not** metadata: they are private typed request state, so they cannot be forged by another plugin, and neither the routed model nor a query string that may hold a relocated credential ever reaches a transaction log. In particular `ai_stream_router.model` mirrors the routed model for logs, while final model enforcement and the response normalizers use the private committed copy — otherwise a later plugin could rewrite both the final body's `model` and that key to the same new value and pass an equality check while bypassing provider selection. The one metadata value a claim-owned hook still consults is `ai_stream_router.provider_content_encoding`, which comes from the provider's own response headers, only selects how this instance decodes its own upstream bytes, and is bounded by that decoder's limits.

**Fail-closed defaults.** A streaming request that lacks a top-level string `model` is rejected with an OpenAI-shaped `400`; one whose `model` matches no provider is rejected with a `404`. Set `fail_on_missing_model: false` / `fail_on_no_matching_provider: false` to pass such requests through instead.

Synthetic completion IDs and Gemini tool-call prefixes use a random UUID per stream, independent of the wall clock and gateway instance. A Gemini `responseId` received before output becomes the completion ID. If it first arrives after synthetic output, the emitted ID stays stable and that first provider value becomes the baseline; only a later different provider value is a stream error.

**Strict configuration admission.** Root and each `providers[]` object are fixed-shape: unknown keys are rejected with path-qualified diagnostics and spelling suggestions (for example `config.enabeld` → did you mean `enabled`?). There are no intentional free-form maps in this plugin. A `fallback` block is rejected outright with its own diagnostic (see below) rather than treated as a typo. The same constructor contract is shared by `ferrum-edge validate` / file startup, Admin and database writes, and CP/DP snapshot or reload publication. Registration policy is `FailClosed`: an invalid enabled config rejects publication so the gateway retains the last-known-good instance instead of silently omitting streaming routing controls or applying typo'd defaults.

**Limitations (MVP):**

- **Provider fallback is not implemented, and a `fallback` block is rejected at admission.** Any `fallback` key — object, empty object, `null`, or scalar — fails construction with `unsupported field 'fallback'`, which means an Admin API `400`, a fatal `ferrum-edge validate` / file-mode startup error, and a refused CP/DP publication under this plugin's `FailClosed` policy, so an operator can never submit valid-looking failover policy and silently receive none.

  Post-first-byte switching is impossible once response bytes reach the client, and pre-first-byte fallback is not expressible at this layer either: the provider route, credential headers, backend TLS resolution, and translated body are prepared once and replayed unchanged by the dispatch retry loop (which only rotates load-balancer targets within one upstream), and a plugin-owned retry loop would have to buffer the entire SSE response. Supporting it requires a per-attempt request-preparation boundary in proxy dispatch. Use gateway-level controls (health checks, circuit breaking, per-provider proxies) for provider redundancy.
- **Usage accounting depends on the provider emitting usage in the stream.** OpenAI-compatible providers emit a final usage event only when `stream_options.include_usage` is set (hence `inject_usage_options`); Anthropic usage is derived from `message_start`/`message_delta`; Gemini usage comes from `usageMetadata`, with its thinking and tool-use prompt categories folded into the normalized OpenAI counters and its own `totalTokenCount` preserved. Providers that omit usage yield no token counts, and an omitted counter is never charged as zero.
- Anthropic and Gemini request translation covers text and base64 data-URL images (top-level `tools`/`tool_choice` and OpenAI tool-call / tool-result history — including legacy `function_call` / `role: "function"` — are translated; any other message-content part is rejected with an OpenAI-shaped `400` rather than silently dropped). Remote image URLs, audio, and files are not translated. Anthropic signed thinking blocks are not carried through the OpenAI representation, so manual extended thinking cannot be combined with tool use (see above); so extended thinking (manual or adaptive) cannot be combined with tool use (see above). Buffered normalization that no longer fits the response's retained ceiling is replaced by the bounded upstream-error terminal (or an empty body if even that cannot fit), never by the raw provider body. Mixing modern `tool_calls`/`role: "tool"` with legacy `function_call`/`role: "function"` in one request, and other unrepresentable tool-history states, fail closed with field-specific diagnostics that do not echo argument payloads.
