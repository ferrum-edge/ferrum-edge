# CONNECT-UDP (RFC 9298) Rules

Split from `.claude/rules/proxy-protocols.md`, which keeps the one-line summary. Canonical operator doc: `docs/http3.md` (CONNECT-UDP over HTTP/3).

- `src/http3/connect_udp.rs` is the whole RFC 9298 surface. Its profile is capsule-only: HTTP Datagrams ride RFC 9297 DATAGRAM capsules (type `0x00`, Context ID `0`) on the CONNECT stream, `SETTINGS_H3_DATAGRAM` is never negotiated, and the 200 carries a transport-owned `Capsule-Protocol: ?1` written AFTER response-header policy. Do not invent a private framing and do not enable QUIC DATAGRAM frames without wiring the RFC 9297 quarter-stream-ID mapping and a vendored-h3 datagram patch. The tunnel destination is client-named but ADMITTED, never load balanced: it must already be the matched proxy's `backend_host:backend_port` or one of its upstream's targets, or it is 403 before any socket exists. "Never load balanced" is structural — the H3 handler substitutes `UpstreamSelection::unselected()` for CONNECT-UDP and skips the circuit-breaker check, the selected-target literal-egress guard, and the selected-target request-body preparation gate, so no member the client did not name can authorize or refuse a tunnel, and no LB cursor is advanced for a request that dials no HTTP backend. Admission runs through `connect_udp::admit_connect_udp_destination`, which returns the MATCHED target and screens it with `direct_http_mesh_transport_refusal` composed with `h3_bridge_transport_refusal`: a destination requiring HBONE, sidecar mTLS, cross-cluster east-west, or Unix-socket dispatch is refused even when a sibling (or an untagged duplicate of the same `host:port`) is directly dialable — the whole matching set is screened. CONNECT-UDP cannot use `h3_bridge_transport_refusal` alone: that helper admits mesh-tagged HTTP targets onto shared H3/H1/H2 mesh pools, while a CONNECT-UDP tunnel is a direct UDP socket. The backend egress policy is evaluated against the REQUESTED host and the route's effective `dns_override`. Unconfigured, transport-constrained, and egress-denied all return ONE 403 with ONE body, so the refusal discloses neither the configured set nor its dialability. The live generation re-check re-runs the same admission, transport screening included. A CONNECT-UDP request must not buffer a request body (`allows_request_body_buffering` excludes it exactly as it excludes WebSocket) — DATA frames after the 200 are capsules. Live tunnels re-check the published config generation and fail closed on route withdrawal and on an effective `dns_override` change (`dns_override_pin_unchanged`, exact comparison including `Some`/`None` transitions — the tunnel's CONNECTED socket cannot be re-pinned, and the check resolves nothing, logs nothing, and returns no target material); a tunnel admitted under a PLUGIN ROUTE OVERRIDE fails closed on ANY generation change, because the live `(namespace, id)` lookup recovers only the unoverridden base route and so cannot reconstruct the effective authorization. No circuit-breaker admission is taken for a tunnel (no HTTP backend is dialled), and the handler still releases any probe slot it is handed as defence in depth. RFC 9298 §3 shape is validated, not assumed: `:scheme` must be the listener's HTTPS scheme and `:authority` must be present, or the request is malformed (400) before any socket. RFC 9297 §3.2 forbids `Content-Length`/`Content-Type`/`Transfer-Encoding` on a Capsule Protocol message — refused on BOTH the raw client headers and the plugin-finalized outbound map, and force-removed from the 200 after response-header policy. A capsule fault — malformed capsule, over-ceiling capsule, or a client FIN IN THE MIDDLE of a capsule (RFC 9297 §3.3) — is a malformed HTTP message: `STOP_SENDING(H3_MESSAGE_ERROR)` on the receive half and `H3_MESSAGE_ERROR` reset on the send half, NEVER a clean `finish()`. An unknown CAPSULE TYPE is dropped and skipped at ANY declared length (RFC 9297 §3.1): `CapsuleDecoder` runs a streaming skip that counts the declared length down in `u64`, retains zero bytes, and resumes exact parsing at the next capsule — do not reintroduce a length ceiling on a capsule type the gateway does not materialize, and do not reset the stream over one. The configured ceiling still bounds DATAGRAM capsules and Context ID 0 payloads. A FIN mid-skip is still `TruncatedAtStreamEnd`. The tunnel socket is built through `socket2` with the platform do-not-fragment / PMTU option installed before Tokio takes it (RFC 9298 §3.1) and a `setsockopt` failure REFUSES the tunnel; there is NO best-effort arm — `socket_opts::set_udp_dont_fragment` returns `ErrorKind::Unsupported` where no option exists, and the whole profile is refused at startup and at admission on such a target. Connected-socket errors are classified in BOTH directions from one shared judgement (`is_transient_udp_datagram_error`), because the kernel surfaces an ICMP error for an earlier datagram on whichever syscall runs next: `classify_udp_send_error` and `classify_udp_recv_error` both drop one datagram for the DF/PMTU `EMSGSIZE` case and for genuinely transient local conditions (`EINTR`, `ENOBUFS`, send-side `WouldBlock`) and keep the tunnel. ICMP-derived destination-unreachable / refused / reset / unreachable / down / protocol-unreachable conditions mean the OS has reported the connected socket unusable, so RFC 9298 §3.1 requires tearing the request stream down — do not treat those as ordinary per-datagram loss. Do not restore "every `recv` error is a dead socket" for the remaining transient arms. A `recv` `WouldBlock` is `UdpRecvFault::AwaitReadable` — re-await readability, bounded by `MAX_CONSECUTIVE_NOT_READY_RECVS`, never a spin and never terminal. An unusable tunnel socket in EITHER direction resets with `H3_INTERNAL_ERROR` and never FINs; `SessionEnd::close_kind` is the ONE close mapping and the send-half owner applies it to whichever `SessionEnd` it is closing with (a consumed supervisor command, or a halt it decided for itself). A relay JOIN failure is `SessionEnd::RelayTaskFailed` → `H3_INTERNAL_ERROR`, never `ClientClosed` and never a clean FIN: the supervisor only classifies handles it has not aborted; a send-half task that completes during teardown contributes its joined `SessionEnd` as the authoritative report; a teardown panic or a `CLOSE_GRACE` abort whose intended FIN/reset did not land downgrades to the same internal-failure arm, and the handler returns `Err` so the failure is visible. Teardown aborts AND joins both relay handles within a bounded grace before releasing the session permit and connection guard; never detach. `FERRUM_HTTP3_CONNECT_UDP_MAX_SESSIONS` above `util::conn_limit::MAX_CONN_LIMIT` is an `EnvConfig::validate` error (never a clamp, never "unlimited"), and the idle default is 120s per RFC 9298 §3.2 — which also RAISES the frontend QUIC `max_idle_timeout` floor (`EnvConfig::effective_http3_idle_timeout_seconds` → `Http3ServerConfig::frontend_idle_timeout`), because an idle tunnel generates no QUIC activity and a 30s connection timer would otherwise close the advertised 120s tunnel. The derivation only raises, leaves `FERRUM_HTTP3_IDLE_TIMEOUT=0` (disabled) alone, does not touch H3 BACKEND pools, and is logged. An AUTHENTICATED tunnel additionally consumes the shared `proxy::auth_lifetime` contract (issue #3860): `effective_request_auth_deadline` is derived ONCE from the accepted `RequestContext` as a single captured `StreamAuthDeadline`; an already-elapsed deadline is the shared fixed/redacted pre-commitment 401 with no permit, lookup, or socket taken; awaited pre-commitment setup (DNS, socket connect) is bounded by that same plan through `ComposedAuthBound` (authorization-first/tie, existing protocol timeout when that earlier bound wins); the last instant before the 200 is offered re-checks the captured plan; the H3 HEADERS write is raced with `await_authorized_headers_write` against that plan and a successful 200 is counted only after the write actually succeeds — if authorization expires while the write is stalled, record exactly once, abort/reset, and release socket/permit/guards, never attempting another blocking terminal write; a live tunnel is bounded by an EXACT `sleep_until(deadline.at)` that is the FIRST arm of the `biased` relay supervisor (never folded into the one-second ticker, never recomputed from datagram activity); expiry is `SessionEnd::AuthorizationExpired`, which `close_kind` maps to `InternalError` so the capsule stream RESETS rather than presenting a completed tunnel; and it is counted exactly once through the request's `StreamAuthTerminationLatch` under the existing closed `StreamAuthProtocolFamily::StreamUdp` family — do not add a `connect_udp` family or any route/target/credential label. A client parked in QUIC send flow control has its `send_data` raced with the supervisor close command so `stop_stream` can land; `CLOSE_GRACE` abort-and-join still bounds teardown if that write never returns, and the send half RESETS on drop because Quinn would otherwise `finish()` it; `reconcile_authorization_teardown` keeps that DESIGNED abort classified as the expiry it was only when the send-half join is `Cancelled` AND the grace timed out — a panic or any unrelated cancellation stays `RelayTaskFailed`. UNAUTHENTICATED tunnels register no timer and are unchanged.
