# Datagram PROXY v2 Envelope Rules

Split from `.claude/rules/proxy-protocols.md`, which keeps the one-line summary. Canonical operator doc: `docs/tcp_udp_proxy.md` (Datagram Client-Address Metadata).

- The datagram gate is fail-closed with no fallback to the socket peer: an untrusted peer (`FERRUM_TRUSTED_PROXIES`), a missing/truncated/oversized/malformed envelope, any transport but `DGRAM` on a `PROXY` command (`AF_UNSPEC` included, so a TCP header cannot be laundered through a zeroed family nibble; `LOCAL` keeps the spec's `0x00` convention and never sets an identity), an unsupported family, a missing/duplicate/invalid HMAC tag or freshness record when `FERRUM_DATAGRAM_PROXY_PROTOCOL_SECRET` is set, an envelope minted for another listener's binding, a duplicate/stale/epoch-stale/exhausted sequence, a timestamp outside the freshness horizon, replay-state capacity exhaustion, or a forwarded client that disagrees with the established session all DROP the datagram. `direct_client_ip` (`source.ip`) is always the socket peer; only the authenticated envelope may set `client_ip` (`remote.ip`). The envelope is stripped once, at the single receive boundary (`process_datagram` for plain UDP, `DtlsServer::run` before demux), so no session, plugin, DTLS record layer, or backend send ever sees wrapped bytes — every refusal above happens at that same boundary, before session lookup/creation, pending-queue admission, DTLS demux/handshake allocation, hooks, backend selection/send, byte/amplification accounting, and idle refresh. Replies go back to the socket peer unwrapped; Ferrum never emits the envelope. Toggling the field is part of the stream-listener restart key. `FERRUM_DATAGRAM_PROXY_PROTOCOL_SECRET` is the MAC key VERBATIM at every layer (`EnvConfig` validation, `StreamListenerManager`, the gate): only an empty/absent value is the unauthenticated posture, and it is never trimmed — trimming would key the listener with bytes startup never validated, or drop a configured requirement entirely. Both refusal paths increment an internal listener-local drop counter (not an exported metric) and emit a rate-limited structured warning carrying only a fixed-cardinality reason and the direct socket peer. Once a 4-tuple is admitted, a different forwarded identity is dropped and does not refresh idle activity: in the UNAUTHENTICATED posture a spoof that wins a fresh-flow race can blackhole the genuine flow until the idle window, then self-heals; do not weaken that pin.
- Datagram envelope authenticity, listener-domain binding, and freshness are THREE separate properties (issues #3856, #3862); do not weaken one on the strength of another. The MAC input is `"ferrum-datagram-proxy-v1" | binding_version | protocol_tag | family_tag | canonical bind_addr | listen_port` followed by the whole datagram with the 32 tag bytes elided, so EVERY command and family — `LOCAL` and `AF_UNSPEC` included — is cryptographically bound to the exact receiving listener. `protocol_tag` separates the plain-UDP receive boundary from the DTLS-terminating one, and the canonical bind address separates wildcard from specific binds on one numeric port; the identity comes only from configured/bound listener properties, never from envelope bytes. The prefix is serialized ONCE at gate construction into a fixed inline buffer — never re-serialized or allocated per datagram. The envelope-declared destination port is still compared to `listen_port` as defense in depth, BEFORE the MAC, so an address-bearing cross-listener envelope reports the specific `listener_binding_mismatch` reason; keep both, since the declared destination cannot cover the address-less forms and the MAC alone cannot produce a distinguishable reason. Freshness is a mandatory single `0xE1` TLV (version, `sender_id` u32, `epoch` u64, `sequence` u64, `timestamp_ms` u64) inside that same MAC; a correctly tagged envelope WITHOUT it is refused as `missing_freshness` — there is deliberately no legacy/compat switch. Check-and-mark is one `DashMap` shard write guard per `sender_id` (highest sequence + 64-bit bitmap), shard-sized through `util::sharding::pool_shard_amount`, so concurrent receive workers cannot both admit a sequence; `u64::MAX` is a reserved wrap sentinel and a lower epoch is refused. State is capped at `MAX_REPLAY_SENDERS` per listener and reclaims only records idle beyond `4 × FRESHNESS_HORIZON_MS` — strictly more than twice the horizon, which is WHY reclaiming cannot reopen an old sequence — then refuses with `replay_state_capacity` rather than evicting live protection. `FRESHNESS_HORIZON_MS` is a compile-time constant, not a knob: it is the bound the lifecycle guarantee is stated in. Guarantee: exactly-once per `(listener, sender_id, epoch, sequence)` within one process; across listener reload, receiver restart, or another replica the gate is fresh, so exposure is bounded to that horizon and Ferrum does NOT claim cluster-wide anti-replay. Do not restate verbatim authenticated replay as a known limitation, and do not exempt `LOCAL`/`AF_UNSPEC` from binding or freshness.
