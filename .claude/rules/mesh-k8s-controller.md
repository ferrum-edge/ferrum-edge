# Mesh Kubernetes Controller Rules

Implementation invariants for this mesh subsystem. Shared mesh invariants: `mesh.md`; operator docs:
`docs/mesh.md`.

## Kubernetes Controller

- `FERRUM_K8S_CONTROLLER_ENABLED` and `FERRUM_K8S_POD_DISCOVERY_ENABLED` default true inside pods detected by `KUBERNETES_SERVICE_HOST`; outside pods they default false.
- Explicit operator `false` wins over pod detection.
- If `FERRUM_K8S_WATCH_NAMESPACES` is unset, watch scope falls back to CP scope: `Single`/`Set` use namespaced watches, `All` uses cluster-wide.
- **A reflector-backed store can go silently stale, and only `FERRUM_K8S_WATCH_IDLE_RELIST_SECS` bounds it.** kube-rs surfaces an error only when a watch *fails*; a watch that stops delivering without failing leaves the watcher task alive while its store serves a frozen object set, so later Gateway API / Istio resources never reach any reconcile. (The conformance artifact that motivated this proves the SYMPTOM — scope initialized, four TCPRoutes present, the sibling ReferenceGrant watcher still receiving events, the controller alive and reconciling, the TCPRoute store frozen, no watcher error/restart/status for 120s — which is consistent with a silently stalled or black-holed watch, but carries NO transport-level proof of where the stream was lost. Keep the prose symptom-shaped: the repair is a bounded authoritative recovery for ANY no-event stall.) `FERRUM_K8S_FULL_SYNC_INTERVAL_SECS` cannot recover that — it re-reconciles the SAME store — and watch bookmarks are consumed inside kube-rs, so there is no liveness signal to observe. `watcher::run_watcher_generations` therefore rebuilds a scope's reflector once it has delivered no event for the idle window (default **300s**, `0` disables, clamped `0..=86_400` at parse time so the doubled readiness timeout / `Instant` deadline / ms jitter conversion cannot overflow). The default is 300 and not 60 because a healthy quiet scope is INDISTINGUISHABLE from a stalled one and therefore always relists: a three-namespace controller carries ~39 scope watchers (~69 with Istio/core, scaling with namespaces), so the window IS the per-scope full-list rate against the API server. The per-scope offset mixes an FNV hash of `(apiVersion, kind, scope)` with a `RandomState`-derived **per-process** seed — a target-only hash would make every control-plane replica list the same scope in the same instant. Never assert an exact offset in a test; assert bounds (`< window/4`). The swap is **make-before-break**: the previous store stays registered and keeps serving until the replacement emits `InitDone`, then `ResourceStoreSet::replace_store_for_scope` swaps it in place under one lock — never remove-then-add, which would make a relist look like a mass deletion and broadcast a config wipe. A replacement that never finishes listing is abandoned after `readiness_timeout` (two idle windows, floored at 30s) and retried, still without blanking the scope. Relisting is in-task: it spawns nothing, registers nothing new with `ControllerTaskRegistry`, and leaves the stream-end contract (deregister the scope, return, let the CRD reprobe loop restart it) untouched.
- **A status patch batch is awaited INLINE on the serialized reconcile loop, so its wall-clock bound is a liveness bound for EVERY object's status** (issue #4239). `src/k8s_controller/status_budget.rs` is the one place those budgets live: 5s per API request, 10s per object's read-modify-write, 15s per batch (which also clamps the two inside it), and a 20s reconciler backstop the batch's own budget should make unreachable. Both writers — Gateway API and Istio — go through `await_status_operation`; do not add a status write that issues an unbounded `get_status`/`patch_status`, and do not raise a budget to (or past) an external observer's patience. The old shape was a single 60s whole-batch timeout with unbounded requests inside it, which is EXACTLY the Gateway API conformance suite's parent-status wait: one stalled write froze all reconciliation for 60s and whichever route was created in that window failed, on an arbitrary test (run `32913920801`: `elapsed_ms: 60036` around a three-update batch timeout, neighbours at 35–275 ms). A budget expiry is a fail-closed retry, not a lost write: it surfaces as a synthesized HTTP 504 `Timeout` API error (never a 409, so no conflict-retry path mistakes it for a lost CAS race), leaves the status-plan cursor unchanged, names the object, and counts `status_request_timeouts` / `status_batch_timeouts`. Dropping an in-flight write is **not** itself a CAS: the timed-out request can still finish later. Gateway/GatewayClass/ListenerSet SSA documents therefore carry the freshly read `metadata.resourceVersion` as the apply-body precondition (kube `Patch::Apply` serializes it; the API server uses it as etcd optimistic lock — `force` wins field ownership, not a stale RV). Route/policy status remains a `resourceVersion`-guarded merge patch. A live status read that fails or has no `resourceVersion` refuses the SSA write so the cursor stays unchanged. Do NOT lower the shared kube `Client`'s read timeout instead — the reflector watches use the same client.
- Istio status writer patches `status.conditions[]` (a `FerrumAccepted` condition plus a `status.ferrum.translation` detail block) for all ten translated Istio kinds when `watch_istio == true`: AuthorizationPolicy, PeerAuthentication, RequestAuthentication, DestinationRule, VirtualService, ServiceEntry, WorkloadEntry, Sidecar, Telemetry, and ProxyConfig. Successful translation writes `FerrumAccepted=True`; a `K8sTranslateError` writes `FerrumAccepted=False`/`Invalid` with the translator's reason so rejections are visible to `kubectl`. Writes are JSON Merge Patch with `metadata.resourceVersion` + UID optimistic concurrency (HTTP 409 re-reads and re-merges `Ferrum*` types only); `field_manager` is an identity string, not Server-Side Apply. Production plans must carry the watch-snapshot UID; identity-less writes are refused before GET/PATCH. Export conflict/retry/recreate/not-found/unsupported/missing-UID outcomes as unlabeled `ferrum_k8s_controller_istio_status_*` counters on `/metrics` via the shared `Arc<ControllerMetrics>` (no labels). Hosted Kind/apiserver competing-writer proof: `tests/k8s_istio_status_cas_live.rs` + `.github/workflows/istio-status-cas-live.yml`.
- Cross-namespace `WorkloadEntry.spec.service` hosts (`svc.ns.svc` / FQDN) are accepted only when a Gateway API `ReferenceGrant` in the **target Service namespace** permits `WorkloadEntry` → core `Service` and the target Service exists in the translated inventory. Stamp `Workload.service_namespace` for attachment matching while keeping SPIFFE/`Workload.namespace` on the WorkloadEntry namespace; missing/unauthorized/stale targets fail closed and must not widen attachment. Same-namespace hosts need no grant.
- **Gateway/ListenerSet synthetic `MeshService` names are kind-scoped and length-prefixed** (`gateway_api_listener_mesh_service_name`): `{kind}-{parent_byte_len}-{parent}-{listener}` with `kind` ∈ {`gateway`,`listenerset`}. Mesh consumers key by `(namespace, name)`; a plain hyphen join is ambiguous (`a-b`/`c` vs `a`/`b-c`), so one entry can overwrite the other while typed provenance still marks both Programmed. Do **not** truncate to a DNS-label ceiling (`MeshService.name` only requires non-empty) and do not reconstruct Programmed from the display name — status uses `GatewayApiListenerKey` / ListenerSet `programmed_listeners`. Keep Gateway and ListenerSet translators on the shared helper.
- Keep `istio_api_resource`/`is_supported_istio_kind` in `src/k8s_controller/istio_status.rs` in lock-step with `ISTIO_CRDS` in `src/k8s_controller/watcher.rs` (group + plural).
- Parsed-but-unenforced fields are surfaced as `status.ferrum.translation.deferred_fields` rather than only logged: DestinationRule `connectionPool.http.maxRequestsPerConnection` at EVERY scope (top-level, `portLevelSettings`, and `subsets[].trafficPolicy`) via `DEFERRED_CONNECTION_POOL_HTTP_FIELDS`. `idleTimeout`, `http2MaxRequests`, `h2UpgradePolicy`, `maxRetries`, and `http1MaxPendingRequests` are APPLIED at all three scopes (subset scope rides `SubsetTrafficPolicy`/`ResolvedSubsetTrafficPolicy` — see the DestinationRule materialization rules above; `http1MaxPendingRequests` as the concurrent-in-flight-H1 cap described there; `idleTimeout`/`http2MaxRequests` as the pool-idle / direct-H2-gRPC stream-cap projections, with the reqwest-H2 builder residual documented as a transport caveat) and must NOT produce ignored/deferred diagnostics — keep translator and status predicates in lock-step (also now APPLIED, not deferred: per-subset `connectionPool.tcp.connectTimeout` → overrides `backend_connect_timeout_ms` for subset-bound proxies; `portLevelSettings[].tls` → per-port backend TLS resolved onto `port_overrides[port].tls` and projected onto the effective proxy's `resolved_tls`; the full per-subset `outlierDetection` → *thresholds* resolved into the subset passive-health overlay consulted by `passive_health_for_target` AND the `maxEjectionPercent` *cap* resolved per-subset by `LoadBalancerCache::max_ejection_percent_resolved_from`, both with the same per-port > per-subset > upstream precedence so cap and thresholds share one tier); VirtualService `http[].corsPolicy` **only when the policy combination is unrepresentable** — a malformed/unknown origin matcher, an `allowOrigins[]` list over 64 entries, a matcher value over 512 bytes, an un-compilable/over-complex `regex`, an unparseable `maxAge`, an invalid method/header token, or credentialed exact `*`. `exact`/`prefix`/`regex` `StringMatch` and legacy `allowOrigin` policies are otherwise translated to a proxy-scoped `cors` plugin via the shared `config_sources::k8s::cors_policy_translatable` predicate, which the translator and status writer both call so they never diverge. Istio `exact` projects onto the plugin's LITERAL `{"exact": ...}` matcher, NEVER its plain-string form (which canonicalizes and reads a leading `*` as native wildcard-subdomain syntax), so a wildcard-shaped or noncanonical exact is preserved rather than widened or deferred (#3254); origin admission (count/byte/complexity bounds) lives once in `plugins::cors` and is shared by the translator, the plugin, and `modes::mesh::config` slice validation — do not fork it (#3253); `mirror`/`mirrorPercentage`, `redirect`, and `rewrite` are fully translated); and Sidecar `ingress[]` listeners Ferrum can't model (see below — resolvable loopback HTTP listeners are materialized, not deferred). VirtualService `spec.tcp[]` and `spec.tls[]` L4 route blocks are translated to stream proxies via `virtual_service_l4_proxies` (`tls[]` → passthrough TCP keyed by SNI, `tcp[]` → plain TCP keyed by port, reusing `proxy_for_route` + the stream/SNI machinery); L4 match predicates (`sourceLabels`/`sourceSubnets`/`destinationSubnets`/`gateways`/`sourceNamespace`) compile onto `Proxy.stream_match`; weighted multi-destination splits materialize an upstream-backed stream proxy (`istio-vs-l4-upstream-*`, carried on `MeshSlice.virtual_service_l4_upstreams`), while `destination.subset` (on ANY L4 destination, single or weighted), invalid weights, and multi-destination `destination.port` disagreement without `match.port` fail closed as `FerrumAccepted=False`/`Invalid`, not as `deferred_fields`. A generated `istio-vs-l4-upstream-` id MUST be listed in `K8S_MANAGED_UPSTREAM_ID_PREFIXES` (`src/k8s_controller/reconciler.rs`) — that list is the only withdrawal mechanism for translator-generated upstreams, and a missing prefix makes every compose append another copy instead of replacing it. Sidecar `ingress[]` is MODELED (F6 §6.2): resolvable loopback HTTP listeners (incl. `https`) materialize inbound routes and are reported via `status.ferrum.translation.ingress_modeled`; only listeners Ferrum can't represent (inadmissible `unix://` path / non-loopback `defaultEndpoint`, non-HTTP-family protocol — including a MISSING or MISTYPED `port.protocol`, which is deferred not guessed-as-HTTP — and omitted `defaultEndpoint`) stay in `deferred_fields`. The status writer's `classify_sidecar_ingress_entries` mirrors `MeshSidecarIngress::resolve` fail-closed semantics on the raw spec (via the shared `sidecar_ingress_protocol_is_http_family` → `sidecar_ingress_app_protocol` mapping) — keep the two in lock-step. The DR `connectionPool.http.maxRequestsPerConnection` deferred set is mirrored by a translator warning in `src/config_sources/k8s/istio.rs`; keep the two lists in sync.
- Status writer failures, such as missing `subresources.status`, warn and no-op; they never abort reconcile.
- `ProxyConfig` is watched as served `networking.istio.io/v1beta1` (`ISTIO_CRDS` + chart `proxyconfigs` RBAC), translated into `MeshProxyConfig`, transported on native/`ProxyConfigsCarrier`, and status-written — Istio's CRD declares `subresources.status`. Both numeric fields fail closed at translation: `spec.concurrency` outside `u32`, and `spec.tracing.sampling` that is non-numeric or outside `0..=100` (an unvalidated value would reach every matching workload's injected `workload_metrics.sampling_percentage`) — keep the latter in lock-step with `Telemetry.tracing.randomSamplingPercentage`. Reachability caveat: Istio's `proxyconfigs.networking.istio.io` v1beta1 CRD has a *structural* spec schema whose only properties are `selector`, `concurrency`, `image`, and `environmentVariables`, with no `x-kubernetes-preserve-unknown-fields` on `spec`. `spec.tracing` is therefore pruned by the API server and never reaches the watcher; `tracing_sampling` is a Ferrum mesh-model field supplied over native/file/xDS mesh config, so cluster-sourced ProxyConfigs always report `tracing.sampling: <unset>` in `FerrumAccepted`. Do not document it as a `kubectl apply`-able Istio field.
