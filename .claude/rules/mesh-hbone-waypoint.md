# Mesh HBONE And Node-Waypoint Rules

Implementation invariants for this mesh subsystem. Shared mesh invariants: `mesh.md`. Rationale,
history, and operator detail: `docs/mesh.md` (HBONE Protocol, Inbound Relay Destination Guard,
HBONE Admission Fence, HBONE Inner Application Connection Reuse, Trusted HBONE Assertors, Node
Waypoint).

## HBONE Identity Boundary

- HBONE is HTTP/2 CONNECT over mTLS on port 15008. `is_hbone_connect()` detects only the wire shape (H2 CONNECT + optional `x-ferrum-mesh-protocol`/`x-istio-protocol: hbone` marker); use it only for non-relay decisions (path normalization, metadata tagging, body-buffering branch).
- Relaying requires an authenticated, trust-domain-verified peer (`is_authenticated_hbone_connect()`, `ctx.peer_spiffe_id.is_some()`). `handle_hbone_request` rejects a peerless CONNECT, bare or marker-bearing, with `403` (`mesh_authz.deny_policy=hbone_unauthenticated_peer`) before dialing or circuit-breaking any backend. The marker is not a bypass; this is additive to TLS-time trust-bundle verification.
- **A relay-synthesis refusal is `403`, never a route-miss `404` (#5763).** `build_inbound_hbone_relay_proxy` returns `InboundConnectRelayRefusal`, answered by `reject_inbound_connect_relay_pre_plugin` (shared with the #6110 Sidecar refusal). Status, body, and policy (`hbone_relay_destination_denied` / `hbone_udp_relay_destination_denied`) come ONLY from `hbone_proxy::inbound_relay_refusal_terminal` via `hbone_proxy::record_inbound_relay_refusal` (stamps `mesh.relay.*`, brackets IPv6 via `relay_denied_destination`, counts `RelayDestinationDenied`) at synthesis, both handler re-checks, and both post-DNS screens. TCP `connect_backend` returns only `HboneConnectFailure::RelayDenied(reason)`; the handler settles the circuit breaker NEUTRAL through `settle_hbone_backend_connect_circuit_breaker_outcome`. Never re-derive a terminal or open-code the metadata/counter at a site.
  - `no_mesh_slice` is readiness: `503 hbone_relay_not_ready` / `hbone_udp_relay_not_ready`, audited, NOT counted, so a `403` always means a real denial (as in `HbonePoolError::public_status`). `address_not_terminated_here` stays `403` even during registry lag.
  - A peerless synthesis refusal (`!spiffe_identity::has_verified_peer_spiffe_identity(ctx)`, which reads `peer_spiffe_extraction_cache` and requires exactly one valid SPIFFE URI SAN in a valid window) answers `unauthenticated_peer_connect_terminal`: the `hbone_unauthenticated_peer` / `hbone_udp_unauthenticated_peer` body and policy, no `mesh.relay.*`, no count.
  - A test proving a HANDLER re-check must first prove synthesis admits (`inbound_relay_destination_decision == Ok`); 403-vs-404 proves nothing.
- `relay_hbone_udp` returns `HboneUdpRelayEnd` (#5765), which drives `body_completed` / `body_error_class` / `client_disconnected`, `hbone.udp.termination_reason`, and a `warn_sampled!` for socket errors; the fence's `revoked_reason()` overrides it. Do not swallow pump errors in `while let Ok(..)` loops.
- **A relay cut short resets the CONNECT stream (#5781, #5858).** Both relays end through `end_hbone_connect_stream`. Only a completed or idle relay gets a clean `END_STREAM` (datagram `tunnel_closed` / `idle_timeout`; byte-stream clean close or idle expiry per `tcp_proxy::relay_failure_is_idle_expiry`, identified by `STREAM_RELAY_IDLE_TIMEOUT_MESSAGE`). Every other ending — socket error, backend deadline, the half-close cap (`STREAM_RELAY_HALF_CLOSE_CAP_MESSAGE`), datagram write stall, fence revocation — sends `RST_STREAM(CONNECT_ERROR)` via the vendored `Upgraded::reset_with_connect_error()` (`HboneUdpRelayEnd::resets_stream` / `hbone_relay_failure_resets_stream`). No revocation, deadline, or cap carve-outs; tell idle from cap only by those constants. The datagram relay must not half-close the tunnel (it would queue `END_STREAM` ahead of the reset).

### Baggage and trusted assertors

- Baggage `source.principal` rewrites the authz principal only when the peer is in `mesh_authz.trusted_hbone_assertors` AND the baggage trust domain matches the peer cert or `FERRUM_MESH_TRUST_DOMAIN_ALIASES`. Untrusted assertors keep their peer-cert identity. Ambient UDP `source.pod_uid` grants namespace/selector scope only after that gate AND when the live slice maps the exact, unambiguous pod UID to the same SPIFFE ID; otherwise mesh-wide policies only.
- Never infer Ambient UDP pod scope per datagram: `NetnsUdpCaptureManager` fixes registry-derived `(pod UID, SPIFFE ID)` per pod-netns producer and `get_datagram_tunnel` stamps it on the authenticated CONNECT; conflicting identities in one netns suppress the stamp.
- **Assertor match is necessary, not sufficient (#4274).** Each entry carries an `AssertionGrant`; `mesh_authz` and `workload_metrics` consume ONE verdict (`hbone_assertion_verdict` → `Allowed` / `UntrustedAssertor` / `OutOfScope`). Do not add a telemetry-only predicate.
  - Grants: bare service account or bare exact SPIFFE pin ⇒ `SameNamespace` (both paths carry and match `/ns/<ns>/`; a namespace-less peer asserts only itself). `{"assertor": …, "asserts": [ids]}` ⇒ exactly those; `[]` authorizes nothing. `{"assertor": "spiffe://…", "scope": "mesh_wide"}` is the only mesh-wide opt-in: per entry, exact SPIFFE matcher only (reject bare SA), construction-time warning. Several matching entries ⇒ UNION.
  - Construction compiles exact-SPIFFE and SA maps (duplicates union); request time looks up the peer plus at most one SA key — no linear scan of NodeWaypoint inventory.
  - Gate order `untrusted_assertor` → `trust_domain_mismatch` → `assertion_out_of_scope` → honored; do not reorder. Emit only redacted reason codes, never the forged identity.
  - `MeshSlice.node_waypoint_assertors` is `Vec<NodeWaypointAssertor>` (`spiffe_id` + `asserts`), forward-derived by `node_waypoint_assertors_from_workloads` from destination-visible, CP-scope-authorized, bearer-`ns`-authorized `Workload.node_waypoint` bindings; `inject_mesh_global_plugins` projects each as an OBJECT (a bare string would fall back to `SameNamespace`). An assertor whose identities are all filtered out is dropped, never serialized empty.
  - Telemetry lockstep is conjunctive across every enabled global `mesh_authz` (capture-on force-injects `__mesh_authz` beside an operator global): injection stamps `_effective_mesh_authz_baggage_gates` on `__mesh_workload_metrics` from enabled configs (disabled rows omitted); honor requires every gate; each gate keeps its own absent/null/default, `[]`, and alias contract; a trigger is still required; malformed or over-bound (max 16) lists fail construction; direct `workload_metrics` without the field keeps its single gate.
- Metadata: dropped baggage sets `mesh_authz.ignored_baggage.untrusted_assertor=true` (denies: `deny_policy=untrusted_assertor`); trust-domain mismatches use `trust_domain_mismatch`; out-of-grant baggage sets `mesh_authz.ignored_baggage.assertion_out_of_scope=true` / `deny_policy=assertion_out_of_scope` / `mesh.ignored_baggage=assertion_out_of_scope` and increments the NodeWaypoint ADR counter `reason="assertion_out_of_scope"`.
- Defaults are `ztunnel` and `waypoint`. `FERRUM_MESH_TRUSTED_HBONE_ASSERTORS` accepts bare SA names or SPIFFE IDs, both `SameNamespace`; object entries exist only on a `mesh_authz` plugin override. Explicit `trusted_hbone_assertors: []` disables rewriting. Keep `HboneIdentity::from_headers()` alias keys in sync with tests.

## HBONE Admission Fence (#5042, `proxy/hbone_admission_fence.rs`)

- Every relayed tunnel (TCP and datagram) registers via `ProxyState.hbone_admission_fence.admit()` and relays through `tcp_proxy::bidirectional_copy_for_fenced_relay` / `relay_hbone_udp` with the tunnel's `revocation_token()`; never bypass it. The relay calls `AdmittedHboneTunnel::retire()` the instant it ends (before summary and logging) and classifies itself from `first_failure == HBONE_ADMISSION_REVOKED_MESSAGE`. Retire and revoke share ONE atomic terminal-state word (`TUNNEL_LIVE` → `TUNNEL_RETIRED` | `TUNNEL_REVOKED_BASE + reason`); `retire()` and `claim_revocation()` are single compare-exchanges — never split into two atomics.
- The request path captures `sweep_epoch()` BEFORE reading the request epoch / PeerAuthentication, and `admit()` rechecks it. Publish PeerAuthentication only through `ProxyState::publish_mesh_inbound_tls_policy` / `publish_mesh_inbound_app_port_aliases` (`ArcSwap::rcu`); never `mesh_inbound_tls_policy.store()` directly.
- Sweeps are coalesced and run on every request-epoch publication (`publish_request_epoch_with_gateway_trust`) and PeerAuthentication swap. Gates follow the CONNECT path so the `reason` label matches what the peer's next CONNECT would get, with ONE deliberate exception: the credential gate runs before authorization, so a peer failing both is refused `authorization_denied` on the wire but revoked `peer_trust` by a sweep. Sweep order: `proxy_withdrawn` (lifecycle, not a CONNECT gate) → credential (`peer_expired` → `peer_trust` → `peer_revoked`) → authorize chain with `MESH_AUTHZ_REEVALUATION_METADATA_KEY` (`authorization_denied`, using the recorded protocol / gRPC-Web plugin view and preceded by its `OMITS_ROUTE_ADMISSION_POLICY` bit) → `peer_auth_transport` → `relay_destination` (incl. the post-DNS loopback screen) → `reuse_withdrawn`. No verdict ⇒ `reevaluation_failed`. `HboneRevocationReason` is declared, indexed, and rendered in this order with `reevaluation_failed` last; keep `ALL`, `index()`, `as_str()`, the docs, and `docs/prometheus_metric_contract.json` in step.
- Revocations count on `ferrum_mesh_hbone_tunnel_revocations_total{proxy_id,reason,namespace}`, never as relay failures; per-sweep summary `info`, per-tunnel `debug`. Account first, cancel last: `claim_revocation` → counter + metric + log → `publish_revocation`.
- The recorded plugin view is the request path's, never a hardcoded `ProxyProtocol::Http`. A CONNECT declaring a gRPC / gRPC-Web content type is refused before routing with a plain HTTP `400`.
- Only `Plugin::reevaluates_live_admission() == true` plugins re-run (default `false`; `mesh_authz`, `access_control`). A sweep must not consume a budget, take a permit, mutate admission state, mirror, score, or call out; `mesh_authz` CUSTOM ext_authz is not re-consulted. A sweep DENY goes to `/mesh/policy-denies/recent` tagged `reevaluation: true` (part of the grouping key) but never to request-shaped counters (`NodeWaypointDestinationPolicyRejectReason::AuthzDeny`, ext_authz `ProviderConflict`). Classify every new authorize plugin and update `tests/unit/gateway_core/authorize_reevaluation_contract_tests.rs`.
- Expiry: one bounded task (`arm_expiry_watcher`) parked on the earliest live deadline, nudged only when a new deadline is strictly earlier, gone when none remain; it sweeps directly under `sweep_serial`, not through the coalescing `request_sweep`.

### Credential gate (#5568, #5574)

- `HboneAdmissionSnapshot` carries an optional `HbonePeerCredential`: peer SPIFFE id, leaf + intermediate DER (`Arc` clones), monotonic `AdmittedLeafExpiry`, `anchored_at_admission`, and the trust revision the CONNECT verified against.
- The gate also runs at CONNECT: `HbonePeerCredential::from_admitted_connect` re-verifies the retained chain against the anchors in force; on `HboneConnectCredential::Refuse` both handlers answer `403` through the unauthenticated-peer terminal and body with `hbone_peer_trust_withdrawn` / `hbone_udp_peer_trust_withdrawn` or `hbone_peer_revoked` / `hbone_udp_peer_revoked` (fixed four-value `HboneConnectRefusal`, one counter `connect_trust_refusals()`). Seed `verified_trust_revision` only from a revision the CONNECT actually verified. Do not replace this with a sweep on every admit.
- The trust half reads the INBOUND ADMISSION SLOT (`tls::SharedBundleSlot`, bound by `ProxyState::install_mesh_inbound_admission_trust` at CA-backend slot creation and after `build_mesh_inbound_spiffe_slot_with_federation`), never `RequestEpoch::gateway_trust()`.
- It is a regression check: a tunnel without `anchored_at_admission` is never judged, and a chain-only inbound posture installs no slot (its peers are bounded by `tls::client_trust`, #3857) and must not be mass-revoked.
- ONE skip key for trust and CRLs: the slot's revision (`MeshInboundAdmissionTrust`), advanced only when published X.509 material (local + federated domains and `x509_authorities`; not leaf/key/JWT authorities) changes AND compiles, compared with `AdmittedHboneTunnelInner::verified_trust_revision` (advanced on every `Trusted`). No separate `mesh_inbound_crl_generation` or two-generation fast path.
- Publish trust only via `ProxyState::publish_mesh_inbound_trust_bundle` (`publish_runtime_svid_to_inbound_slot` and `publish_staged_spiffe_bundle` end there; nothing calls `slot.store()`). Anchors are compiled once per in-force revision at publish time by `tls::spiffe::AdmittedPeerTrustAnchors::compile(material, crls)` and cached; neither a sweep nor a CONNECT builds one.
- Enforced CRLs are compiled INTO the anchors, and the handshake reads the same artifact: `ProxyState::mesh_inbound_admission` (`tls::InboundAdmissionArtifact`). `SpiffeClientCertVerifier` uses those anchors whenever any are in force; its own `SpiffePeerVerifierCache` is only the startup fallback. `tls::SvidServerCertResolver` keeps reading the raw slot.
- Publish CRLs only via `ProxyState::publish_mesh_inbound_crls` → `publish_inbound_admission_crls`: byte-identical records publish nothing; an unusable candidate (`crl_policy::usable_crl_records`) is not published (one sampled `warn!`); otherwise store, recompile, publish anchors to the artifact BEFORE advancing the revision, then `request_sweep()`. The publish window can be briefly stricter or looser than the fence; both directions fail closed.
- All three publishers (`install_inbound_admission_trust`, `publish_inbound_admission_trust`, `publish_inbound_admission_crls`) take the ONE fence-owned `publish_lock` from `HboneAdmissionFence::new` (never per trust) and re-check equality under it; a no-change `publish_enforced_crl_set` recompiles and advances nothing. The only production CRL republisher is `ProxyState::reload_backend_tls_material` (`FERRUM_BACKEND_TLS_LIVE_RELOAD_ENABLED`, `FERRUM_BACKEND_TLS_WATCH_INTERVAL_SECONDS`); per-destination validation failures in `proxy::validate_backend_tls_material_for_config` are skipped (#6105), so only a CRL load failure withholds publication.
- `compile` is ATOMIC and must match `SpiffePeerVerifierCache::build`: any domain that does not build (including a JWT-only federated domain) fails the whole set. A non-compiling candidate is stored in the slot but advances nothing and replaces no anchors (sampled `warn!` naming only `local`/`federated`/`absent`); a non-compiling rebind of `install_inbound_admission_trust` keeps the existing binding. `InboundAdmissionArtifact::put_in_force` takes `Arc<AdmittedPeerTrustAnchors>`, never `Option`. Never judge per domain.
- Reasons follow webpki precedence (`notAfter` before anchors; `UnknownIssuer` before revocation; `CertRevoked` outranks `UnknownIssuer`). `reevaluation_failed` covers an unparseable or unretained leaf and an in-force CRL past `nextUpdate`; an uncompilable bundle or unusable CRL candidate is never `reevaluation_failed` (neither is in force).
- Gateway trust publishes only via `ProxyState::publish_live_gateway_trust` (store, then `request_sweep()`); `fence_gateway_trust_generation` does not sweep.

## Source-Side Inner Connection Reuse (#5042, `proxy/hbone_inner_pool.rs`)

- Plain HTTP keeps an exclusive inner HTTP/1.1 sender; native gRPC keeps a bounded set of shared nested HTTP/2 senders per key; raw TCP, WebSocket, and datagram tunnels are untouched.
- Reuse is granted by the DESTINATION only: `handle_hbone_request` stamps `x-ferrum-mesh-tunnel-reuse: fenced` (`modes::mesh::hbone::TUNNEL_REUSE_HEADER`) on the CONNECT `200` only while `AdmittedHboneTunnel::fence_in_force()` holds AND the admitting chain is unanimously reuse-safe (#5583): `admitting_chain_allows_inner_reuse` folds `Plugin::allows_hbone_inner_reuse_for(HboneReuseContext)` over the dispatcher's own `plugins` slice, never a set re-derived from `HboneAdmissionView`. `HboneAdmissionSnapshot.advertised_inner_reuse` is recorded before `admit()` and read back for the response; `reuse_context` keeps the admitting `mesh_direction` and `frontend_listen_port`. Every sweep re-runs the same pure fold over `admitting_request_view`'s `plugins()` for the current generation and revokes `ReuseWithdrawn` (last gate; unadvertised tunnels are never judged). `handle_hbone_udp_request` never advertises. The header authorizes nothing and must not feed any other decision; absent or unknown means per-request behaviour.
- Classification default is a literal `false` (do not derive it from `is_authorize_plugin()`). Declare `true` only for a plugin with no per-operation decision or side effect, or whose every decision the fence re-issues. Reusable today: `mesh_authz` iff `ext_authz.is_none()`, `access_control`, `spiffe_identity`, `workload_metrics`, `stdout_logging`, `prometheus_metrics`, `otel_tracing`, `proxy_alerts`, `bpf_metrics`. Explicit `false`: `rate_limiting` (every `limit_by`), `adaptive_concurrency`, `request_mirror`. Never opt in a bearer-credential plugin. `PluginInstanceWrapper` forwards both methods. Update `tests/unit/gateway_core/hbone_inner_reuse_classification_tests.rs` for any new plugin.
- `mesh_outbound_registry` (PR #5595) advertises reuse only for CONNECTs it did not decide: nonempty scope AND `!should_enforce_for_request_facts(mesh_direction, frontend_listen_port)`. Its request hook delegates to the same predicate first, and every instance skips `Some(Inbound)` before lookup, metrics, or rejection. Scoped instances on matching `Some(Outbound)` or non-mesh listeners enforce and refuse reuse (NodeWaypoint capture is stamped Outbound); unscoped instances (incl. `deny_all`) always refuse. A sweep never re-runs the lookup. Do not infer reuse from a nonempty port scope or assume every CONNECT terminator is Inbound. `MeshRuntimeConfig::validate_listener_direction_ports` (`run` / `validate` and pre-bind) requires distinct nonzero port numbers for planned inbound/outbound TCP listeners; UDP capture and port `0` excluded.
- The key (`write_hbone_inner_pool_key`) is the complete transport + admission identity: inner protocol, app endpoint as dialled, dial peer + HBONE port, pinned peer / SNI / remote trust domain, asserted source principal and whether it was asserted, namespace + proxy id + upstream id + proxy lifecycle generation, SVID leaf fingerprint (fixed index 2) + backend SVID generation, and `write_pool_config_key`. It excludes per-request policy (timeouts, body ceilings), like `unix_backend_pool`.
- Every lease is bounded by the earliest source credential deadline (`RequestContext::credential_deadline_at` folded with the gateway leaf `notAfter` through `parse_leaf_credential_deadline`; `Invalid` = already elapsed; `CredentialDeadline::Unbounded` = `None`).
- H1 returns to idle only after a clean, fully consumed response (streaming bodies carry a `PooledBackendLease` released on clean EOF). H1 and H2 liveness are `!is_closed()`. The only replay reuse adds is the at-most-one pre-wire `try_send_request` handback (`take_message()` is `Some` only when nothing reached the wire); `retry::should_retry` with `retryable_methods` stays the only replay authority.
- The pool is owned by `HboneConnectionPool` so `drain_retired_fingerprints` / `force_drain_all` reach it; do not move it onto `ProxyState`.
- Draining is fenced on both sides. Every retirement (`drain_all`, `retire_svid_fingerprints`, `retain_live_routes`) advances `drain_generation` FIRST; `checkin_h1_when_idle` / `checkin_h1` compare the lease generation before AND after insert (withdrawing by entry id), and `publish_h2` does the same plus `HboneConnectionPool::source_dial_fence` / `source_dial_fence_intact` (SVID slot ptr, CRL slot ptr, fingerprint). Never a single read, never a bump after the pass. `entry_drain_generation` (advanced only by `drain_all` and `retire_svid_fingerprints`, never `retain_live_routes`) is stamped onto every `IdleH1` / `SharedH2` at insert and re-read inside the shard guard by `take_idle_h1` / `checkout_h2`, which evict a mismatch rather than hand it out or adopt the caller's generation (`unix_backend_pool::take_idle_h1` follows the same rule). A refused check-in counts as `fenced`, not `discard`.
- `ProxyState::reconcile_hbone_inner_pool` runs `retain_live_routes` on every current publication, comparing the recorded route span `|namespace|proxy_id|lifecycle_generation` (never re-split from the key) with the `collect_live_hbone_inner_routes` superset (every declared proxy with keep-alive on). The effective upstream id is in the key but not the span; an entry with no lifecycle generation is exempt. `checkout_h2` / `publish_h2` honour `enable_http_keep_alive` like the H1 pair.
- Bounds are constants (`MAX_IDLE_H1_PER_KEY`, `MAX_SHARED_H2_PER_KEY`, `MAX_POOLED_INNER_CONNECTIONS`, `MIN_INNER_IDLE_TIMEOUT_SECONDS`); nested-H2 width is `FERRUM_POOL_HTTP2_CONNECTIONS_PER_HOST` clamped by `MAX_SHARED_H2_PER_KEY`. Carriers track the peer's `SETTINGS_MAX_CONCURRENT_STREAMS` and are chosen least-loaded-with-room, so per-key gRPC concurrency is at most cap × width (document changes in `docs/mesh.md`). `open_hbone_grpc_sender` creates `HboneInnerH2Load` before the spawn and the driver stores `Connection::current_max_send_streams()` after every poll; never a one-shot read after `await_peer_settings` (it returns hyper's pre-SETTINGS default of 100). `active_rpcs` is released when the gRPC dispatch returns, so it under-reports long streaming RPCs; that only delays a widen.
- A pooled connection holds one outer H2 stream and a live entry in the destination's fence. Metric: `ferrum_mesh_hbone_inner_pool_events_total{protocol,event,namespace}`.

## Node-Waypoint Per-Pod Policy Scope

- Source identity comes from the eBPF `connect4`/`connect6` cgroup-stamped `SO_COOKIE` record via `NodeWaypointIdentityResolver`. The hooks key `FERRUM_WORKLOAD_IDENTITY` by `bpf_get_current_cgroup_id()` (the container LEAF), so the node-agent enrolls the whole pod cgroup subtree (`cgroup::collect_cgroup_tree_inodes`) and re-walks on reconcile; never key only the pod inode. `FERRUM_INCLUDE_PORTS` is keyed and re-walked the same way; unannotated pods skip the walk.
- Lazy identity reclamation: `sweep_cgroup_stale_identities` (`FERRUM_MESH_NODE_WAYPOINT_CGROUP_SWEEP_INTERVAL_SECS`) reclaims a non-cgroup-bound identity only when its `pod_uid` is referenced by no live cookie record AND its identity `Arc` has `strong_count == 1` (HTTP/HBONE connections hold the `Arc` and re-query scope per request; do not drop that guard). `sock_ops` removes the orig-dst record on TCP close. Cgroup-bound identities belong to the cgroup-binding pass.
- HBONE/HTTP and raw TCP accept paths stamp `node_waypoint_policy_scope` (`RequestContext` / `StreamConnectionContext`) via `policy_scope_for_pod(pod_uid)`. TCP threads the resolver `ProxyState` → `StreamListenerManager::set_node_waypoint_identity_resolver` (before the first stream reconcile) → `TcpListenerConfig` → `resolve_node_waypoint_stream_scope`. Only `NodeWaypoint` topology installs the resolver; every other topology passes `None`.
- **GAP-2M accept-side bridge** (`ebpf/ferrum-ebpf/src/sock_ops.rs`, IPv4 and IPv6): active-established re-keys the record by `(netns cookie, tuple)` (`FERRUM_ORIG_DST_BY_TUPLE4/6`); passive-established re-stamps it under the accept-side cookie into `FERRUM_ORIG_DST4/6`. IPv6 ctx words are read with verifier-safe volatile per-`u32` loads (`read_ctx_ip6`) and keyed by `ConnTuple6`; never copy the whole `[u32;4]`. Keep `netns_cookie` in the key (captured tuples collapse to loopback + ephemeral port across netns). A mismatch writes nothing, so resolution stays fail-closed. CI compile- and load-tests the programs (`build-ebpf`, `ebpf-live`).
- Enrollment: slice apply installs a `workload_spiffe_hash` → SPIFFE index seeded by `build_policy_scope_snapshot_from_slice` from `workloads` ∪ `node_waypoint_capture_destinations` (#6800); never seed from `workloads` alone or fold the inventory into `workloads`. Capture-inventory sources are vouched ONLY by exact pod UID + matching hash (`capture_sources_by_pod_uid` via `vouched_spiffe`), never by the hash join, but still mark colliding hash entries `Collision`. A pod UID with disagreeing records is in `conflicted_pod_uids` and never resolves. `resolve_record` lazily hash-joins the eBPF `(pod_uid, workload_spiffe_hash)` (unmatched ⇒ `UnknownPod`) and re-checks the current index on EVERY resolve.
- The gate and scope index are one `ArcSwap<NodeWaypointSlice>` generation; scope is keyed strictly by exact pod UID (`scopes_by_pod_uid`), never by SPIFFE ID, and an absent workload has no scope. `resolve_*` returns identity and scope from one load. Scope is reclaimed by slice updates, not identity lifecycle. TCP captures both at accept; HTTP re-queries per request.
- Withdrawn or conflicted identities: HTTP re-checks via `current_policy_scope_for_identity` and 403s an identity the generation no longer vouches. UDP/DTLS attribution (`policy_scope_observation_for_pod_identity`) refuses `capture_only_pod_uids`. Raw TCP (`resolve_node_waypoint_stream_identity`) refuses at accept and records the drop when `NodeWaypointIdentityError::carries_capture_evidence`; only `UnknownCookie` / `SocketCookieUnavailable` keep the mesh-wide-only fallback. Do not move this into a `mesh_authz` census.
- A missing scope sets `mesh_authz.scope_missing=true` and, when any namespace/selector-scoped policy exists, rejects `403` (`deny_policy=scope_missing`) on HTTP/HBONE per request and TCP/UDP at accept; with only mesh-wide policies both fall through. The HBONE listener still drops an unresolved identity at accept.
- **In-netns outbound capture listeners** (`NetnsCaptureManager`, `src/proxy/netns_capture.rs`; always on for NodeWaypoint): `connect4`/`connect6` rewrite captured pod outbound TCP to pod loopback (UDP/DTLS `connect()` is not rewritten), so listeners must live INSIDE each enrolled pod's netns (`setns(CLONE_NEWNET)` on a dedicated thread, deduped by netns inode) on `127.0.0.1` and `[::1]` at the `outbound_listen_addr` PORT (skipped when `0`); a host-netns listener cannot substitute. Pods come from `FERRUM_MESH_NODE_WAYPOINT_POD_REGISTRY_DIR` (default `/run/ferrum/node-waypoint-pods`, one file per pod UID). One shared `max_connections` semaphore; an IP change within a netns updates `source_ip_override` in place (no rebind, no marker retraction); a netns move closes and reopens. Per-family readiness markers `.ready4/<pod_uid>` / `.ready6/<pod_uid>` (no unsuffixed `.ready`); the registry dir is RW for the proxy. NodeWaypoint adds `::/0` to the capture include set with `ipv6_outbound_deny` clear. Linux-only.

## NodeWaypoint Transparent Capture Relay (#3287)

- The capture relay (`proxy/node_waypoint_ingress_capture.rs`) stamps a DESTINATION scope: `build_node_waypoint_capture_relay_entry` resolves the captured `orig_dst` to exactly one slice `Workload` (none, or divergent `PolicyScopeCache` records, fails closed) and sets `MeshTcpInboundEntry.node_waypoint_policy_scope`, which `handle_mesh_tcp_inbound` stamps. The same workload yields the PeerAuthentication mode via `slice::resolve_effective_mtls_mode`, never `mesh_inbound_tls_policy.modes_by_port`; ownership resolves before the posture gate. Sidecar `MeshTcpInboundEntry`s keep `socket_mark: None` and `node_waypoint_policy_scope: None`.
- The resolver reads a DEDICATED cross-namespace inventory, never `mesh.workloads` / `mesh.peer_authentications`: `MeshSlice.node_waypoint_capture_destinations` (workloads whose trusted `Workload.node_waypoint.spiffe_id` is this NodeWaypoint's `workload_spiffe_id`) and `node_waypoint_capture_peer_authentications` (via `peer_auth_applies_to_workload`), back-projected as `serde(skip)` fields in `prepare_normalized_gateway_config_for_mesh`. Gated by `MeshSliceRequest.node_waypoint_capture_scoping` (NodeWaypoint only); do not overload `ambient_udp_source_scoping`.
  - The CP resolves it in `filter_mesh_config_to_request` BEFORE the `workloads`/`peer_authentications` retains and AFTER `node_waypoint_capture_namespace_allowed` (the strict `Single`-scope boundary shared with Ambient UDP) + the bearer `ns` claim, and preserves it on incremental refilter. Transports: proto field 9, `XdsNodeMetadata.node_waypoint_capture_scoping`, and the ECDS carriers.
  - NEVER fold it into `workloads` / `services` / `peer_authentications`. `content_eq` compares both fields. An empty inventory refuses the connection (`relay_destination_denied`), never falls back to `workloads`.
- The destination's AuthorizationPolicy rides the same inventory: `MeshSlice.node_waypoint_capture_mesh_policies` (policies `policy_scope_applies_to_workload` applies to a destination; CP owner = destination namespace or root, computed before the `mesh_policies` retain). `mesh_authz` unions it into `slice.mesh_policies` only under `per_pod_policy_scoping`, before validation, `has_scoped_policies`, condition keys, and the CUSTOM census (`merge_node_waypoint_capture_mesh_policies`); the per-connection `policy_applies_to_pod` filter keeps each policy on the scopes it selects. Never fold it into `mesh_policies` on the wire; keep it in `content_eq`, `NodeWaypointCaptureMeshPoliciesCarrier`, the xDS `config_fingerprint`, the `ext_authz_providers` projection, and `validate_recovered_ext_authz_binding` / `validate_mesh_config_update`.
- Completeness is explicit: every capture-scoped build stamps `node_waypoint_capture_mesh_policies_resolved`; xDS emits the policy carrier whenever it is set (even empty) and recovers the marker from carrier presence; `MeshSlice::validate_node_waypoint_capture_inventory` (top of `prepare_normalized_gateway_config_for_mesh` and xDS `reverse_translate`) refuses destinations or policies without it. Never default the marker to true.
- The missing-scope census is split: `has_scoped_policies` covers ordinary `mesh_policies` (pre-merge) for SOURCE-scope paths; `has_scoped_capture_destination_policies` widens it only for `__mesh-inbound-hbone-relay`. The non-Linux UDP census (`mesh_authz_config_policies`) reads ordinary policies only. Capture-only body-inspecting CUSTOM rules keep their scope (`capture_body_inspecting_custom_policies`) and prebuffer only when the destination (`node_waypoint_destination_scope_match`) or source scope selects them, never via scope-blind `body_inspecting_custom_rules`.
- Provenance: `MeshConfig.node_waypoint_capture_inventory_state` (`Unfiltered` / `Resolved` / `NotResolved`) decides what the slice builder may derive from (whole document / dedicated fields even when empty / nothing). Every ADS stream rebinds its placeholder config on its FIRST node-identified request (`bind_stream_config_to_node`); the xDS fingerprint hashes the provenance. Never rebuild an inventory from narrowed or Sidecar-widened views or infer provenance from emptiness.
- Inbound HBONE relays to capture destinations resolve scope from `NodeWaypointCaptureDestinationScopes`, only for `__mesh-inbound-hbone-relay`, and it is AUTHORITATIVE for any address it names (`node_waypoint_destination_scope_match`; canonical-address via `IpAddr::to_canonical`, declared-port, and divergent-records rules shared with the capture resolver; hostnames matched case-insensitively). An undeclared port or ambiguity is no scope, never a fallback. The missing-scope guard is never relaxed.

## NodeWaypoint UDP/DTLS (#3286)

### Source attribution

- Never use the socket cookie (one shared UDP socket, one cookie). The channel is the kernel-reported ingress interface (`IP_PKTINFO`/`IPV6_PKTINFO`) joined against registry pod addresses + attested SPIFFE ID (`src/proxy/node_waypoint_udp_identity.rs`), reusing `host_udp_capture::plan_host_udp_bindings`. An interface claimed by two pods refuses both.
- `NodeWaypointUdpSourceScoping::resolve` snapshots the binding, `policy_scope_for_pod_identity` proves pod UID + principal against one generation, and admission revalidates both after plugin hooks. Scope and principal are stamped before `on_stream_connect`; an unattributable session has no scope and hits the TCP fail-closed rule.
- A scoped listener forces `IP_PKTINFO` regardless of `FERRUM_UDP_PKTINFO_ENABLED` and must enable it for EVERY family its socket serves: `socket_opts::enable_ingress_pktinfo` reads `IPV6_V6ONLY`, requires both on dual-stack `[::]`, and returns `IngressPktinfoError`, propagated by the UDP listener and `DtlsServer::from_socket_with_limits`. `v4_ok || v6_ok` is not acceptable.
- DTLS `DtlsServerLimits::capture_ingress_ifindex` switches the demux to the shared `RecvMmsgBatch` reader, drained at most `DTLS_INGRESS_CAPTURE_DRAIN_LIMIT` per wake-up.
- Admitted sessions pin their binding and re-authorize every datagram via `attribution_eq` (generation excluded). `revalidate_datagram`: a different ingress interface while the pinned binding still resolves is `DropDatagram` (session untouched); otherwise `CloseSession`. Do not collapse them.
- Refusal reasons are a closed `&'static str` enum with per-reason rate-limited warns; never put registry or peer values in labels. A DTLS session end aborts AND joins losing relays (`abort_and_join_dtls_relays`, skipping the `select!` winner).
- `fail_closed_node_waypoint_udp_dtls_scoped_policies` and the `node_waypoint_dns_slice_for_prepared_config` DNS carve-out run only when `node_waypoint_udp_identity::source_identity_supported()` is false (non-Linux); keep both on that one condition.

### Listener surface

- Listeners come from `materialize_node_waypoint_udp_listeners`, never a VirtualService L4 proxy (`Proxy::validate` rejects `stream_match` on `udp`/`dtls`). It runs DP-side in `prepare_normalized_gateway_config_for_mesh`, before `fail_closed_node_waypoint_udp_dtls_scoped_policies` (which strips both UDP upstream prefixes, `is_node_waypoint_suppressible_udp_upstream_id`), and emits reserved-id `__mesh-nw-udp-*` proxies/upstreams per in-mesh `MeshService` UDP-family port, gated by `FERRUM_MESH_NODE_WAYPOINT_UDP_LISTENERS_ENABLED` (default off). Bind failures stay visible as `StreamBindFailure`.
- `AppProtocol::Dtls` is the same L4 transport as `Udp` (`is_udp_mesh_protocol`) and only selects `frontend_tls: true`; it comes from an `appProtocol: dtls` / port-name hint on a `protocol: UDP` port or an Istio `dtls` protocol. A `protocol: TCP` port never becomes `Dtls`; the EgressGateway refuses `Dtls`.
- Backend locality is exact-node: targets only for workloads whose `node_waypoint.node_name` equals the non-empty `FERRUM_K8S_NODE_NAME` (the relay mark cannot cross nodes). Enabling listeners without it fails serving startup.
- Same-port Services are supported (#3861): compatible plain-`udp` claimants share one socket (`__nwudp_{port}` group) demultiplexed by exact local destination via `NodeWaypointUdpDestinationRouter`, chosen before session lookup, hooks, `on_stream_connect`, backend choice, and accounting. Session key: `(client tuple, destination IP, namespaced route owner, listener spawn generation)`. No fallback route. Route tables are `ArcSwap` snapshots republished under the running socket; group membership is not in the restart key. Refusals: duplicate `(ClusterIP, port)` refuses both; mixed `udp`/`dtls` or more than one `dtls` claimant refuses every claimant; headless is refused on a shared port. A single-claimant port keeps an individual listener with no table (the direct-address lane).
- DTLS material is `FERRUM_DTLS_CERT_PATH` / `_KEY_PATH` / `FERRUM_DTLS_CLIENT_CA_CERT_PATH`, never `FERRUM_FRONTEND_TLS_*` (`load_mesh_frontend_server_identity`); PeerAuthentication reload reads the same pair. Ordinary `dtls` without material stays `FrontendDtlsDeferred`; for generated listeners, missing cert/key or a Strict route without the client CA rejects the whole candidate and retains last-good.
- `apply_scoped_dtls_socket_options` applies `DtlsServerLimits::socket_mark`, `::transparent_reply_source`, and `::capture_ingress_ifindex` before the server exists; any failure is a bind failure.

### Relay authorization past `tc_inbound` (#3956, #3957)

- UDP to an enrolled pod passes only on `relay cgroup AND relay mark AND (configured node source OR exact live reply source)`, evaluated in `udp_relay_sender_authorized` before the DNS-response carve-out; the mark check stays in `enrolled_destination_authorized`. `bpf_skb_cgroup_id()` must hit `FERRUM_UDP_RELAY_CGROUPS` (it answers only at the tc egress hook of the pod's host-side veth). Keep both source lanes (backend dial needs node-source, pinned replies need reply-source) and never hoist one outside the helper. The TCP arm reads none of this.
- The frontend and per-session backend sockets both carry `NODE_WAYPOINT_INBOUND_AUTH_MARK`; marking the frontend is a startup precondition.
- Reply sources are pinned by PKTINFO to the address the client addressed. Direct lane: only addresses in `FERRUM_NODE_AGENT_NODE_IP` / `_NODE_IPS` can be answered; do not unpin, widen trust, or auto-render `status.hostIP`. Steered lane: exact `(address, port)` entries in `FERRUM_UDP_REPLY_SOURCES` / `_SOURCES6`, never CIDR, range, or port-blind; both families, `FERRUM_UDP_RELAY_CGROUPS`, and `FERRUM_UDP_REPLY_SOURCE_GATE` are required by `validate_required`. `PktinfoLocal::send_ifindex` derives the egress ifindex; never reuse the captured ingress ifindex.
- Forbidden: ClusterIPs in `FERRUM_NODE_IPS*`, loosening `source_is_node`, widening kubelet probe sources, weakening the TCP arm, admitting arbitrary marked UDP sources, unpinning the reply source, or admitting UDP without the relay-cgroup sender proof.

### Relay cgroups and the reply-source manifest (`src/proxy/node_waypoint_udp_reply_source.rs`)

- The node-agent derives relay cgroups host-side from `FERRUM_MESH_NODE_WAYPOINT_RELAY_POD_UID` (downward-API `metadata.uid`, refused as an `ambient.env` override) and refuses a UID naming an enrolled workload, an id inside an enrolled subtree, an unresolvable identity, or more than `UDP_RELAY_CGROUP_MAX_ENTRIES`. Without a relay identity, active publications are refused; an inactive withdrawal stays publishable.
- Manifest protocol is `v3`; `v1`/`v2` are unparseable by design.
- Publishing is not applying. `NodeWaypointUdpSteering` installs rules only after the node-agent acknowledges the exact generation (`SteerReconcileOutcome::PendingAck` otherwise; retry next tick, never block). Order: remove outgoing rules, publish, await ack, install. Teardown mirrors it: exact-name rule teardown must succeed before the INACTIVE generation is published, and `Removed` requires its ack. Publication or ack-read failure is `Failed` with strict teardown; unproven state is retried.
- The node-agent is the sole BPF-map writer; the proxy's bpffs mount stays read-only. Channel: `<pod registry dir>/.udp-reply-src/desired` (proxy; whole set + `(owner, sequence, active)`, staged and `rename`d) and `applied` (node-agent). Claim lines are `<family>-<hex address>-<port>`, strictly ascending and unique; any malformation refuses the whole generation. The owner is a secure-random per-process 16-hex token; unavailable randomness fails closed.
- Node-agent apply order: retract the ack, disable the shared gate, replace the relay-cgroup map FIRST, then both source families, re-read `desired`, enable the gate, write `applied` last. A gate-disable failure stops mutation and surfaces the residual. The whole generation is refused with no ack on an over-bound set, a missing map (including an empty withdrawal), any map-op or partial-family failure, a malformed manifest, or an entry naming an enrolled pod address. An absent or refused channel disables the gate.
- Every source-index manager-future exit calls `steering.shutdown()`.

### Service-path steering (`src/proxy/node_waypoint_udp_steering.rs`, `crate::capture::node_waypoint_udp_steer_setup_script`)

- Rules notrack (`raw PREROUTING`) and mark (`mangle PREROUTING`) `-i <pod veth> -d <ClusterIP> --dport <port>` and route the mark to local delivery via `ip rule fwmark 0x736 lookup 33136` + `ip route add local … dev lo table 33136`. Nothing is rewritten. Requires `iptables`/`ip` in the image and `NET_ADMIN`.
- (a) `udp` and `dtls` are both steered: the `DtlsServer` pins the whole `PktinfoLocal` per peer (`DtlsSessionState::reply_local`) and sends every record through `send_dtls_record` over an `IP_TRANSPARENT` socket; a scoped datagram with no or a non-matching capture is dropped before session state (`dtls_scoped_capture_admits`). No `send_to` on a scoped DTLS path.
- (b) Steered interfaces are the PUBLISHED source generation (`PublishedSourceGeneration::ifaces`), never the planner's list.
- (c) The first reconcile of every process runs the exact-name teardown even for an empty plan; later unchanged polls run nothing.
- (d) Setup empties the mangle mark chain before repopulating the raw notrack chain.
- (e) Teardown runs per family independently, but success requires every family proven (otherwise never set `reaped` or publish a replacement). Within a family, mark→notrack is proven gone before routing is removed; without `ip`, xtables cleanup still runs and routing is retained. Only exact Ferrum-owned objects are touched, and only genuine absence (incl. iproute2's `FIB table does not exist` for table 33136) is idempotent success.
- (f) Every published family installs completely or the apply fails under `set -e`; no per-family best effort.
- (g) Preparation never calls `publish_plan` / `retract_plan`. `StreamListenerManager` publishes only destinations bound on the accepted serving generation and retracts before sockets go away (bind failure, deferred DTLS, withdrawal, task failure, shutdown). Destination/interface updates share one cold-path mutex; task exit marks its spawn generation non-serving before retraction, so a predecessor cannot retract a replacement; shutdown fences bind-watchers under the listener-map lock, retracts, then closes. Ownership is the generated `NamespacedResourceId` / `__mesh-nw-udp-` prefix (`is_node_waypoint_udp_listener_id`), never a substring match.
- `NODE_WAYPOINT_UDP_STEER_MARK` (0x736) and table 33136 stay distinct from the TPROXY mark/table, the relay auth mark (0x734), and the tc ingress-redirect mark (0x735) (compile-time asserts). Never hook `OUTPUT`.

### Live gate

- `run_node_waypoint_udp_datapath_checks` and `run_node_waypoint_dtls_datapath_checks` (`tests/k8s/node_waypoint_ebpf_live/run.sh`) probe at a trusted node source (`node_waypoint_listener_ip`). The spoof assertion is emission-gated (`NET_RAW`, `SPOOF-SENT:` after `sendto`); a sandbox that cannot forge fails the gate. The direct-node-address (`node_waypoint.dtls.listener_*`) and Service-path (`…service_path_*`) groups are distinct evidence; keep both.
- `node-waypoint-ebpf-live.yml` deliberately has no `paths:` filter (#3908): PR relevance comes from the `node-waypoint-ebpf-live` patterns in the trusted-base `.github/scripts/ci_runtime_plan.py`, and shared mesh/UDP files are exercised by this suite on every push to `main`. Do not re-add a workflow `paths:` list.
