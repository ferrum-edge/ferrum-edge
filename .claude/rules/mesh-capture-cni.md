# Mesh Capture, Injector, Node Agent, And CNI Rules

Implementation invariants for this mesh subsystem. Shared mesh invariants: `mesh.md`; operator docs:
`docs/mesh.md`.

## Injector, Node Agent, And CNI

- Injector mode serves `POST /mutate` Kubernetes AdmissionReview and emits JSON patches only.
- Sidecars run as `PROXY_UID`; optional iptables init container requires `NET_ADMIN`.
- IPv4/IPv6 capture CIDRs must stay partitioned into `iptables` and `ip6tables` blocks. `FERRUM_MESH_IP6TABLES_ENABLED=auto|true|false` controls IPv6 fan-out.
- **UDP capture uses `mangle` TPROXY, not REDIRECT** (`FERRUM_MESH_CAPTURE_UDP_ENABLED`, default off: no rules and no listener). Operator reference: `docs/mesh.md` → "UDP TPROXY capture"; full rule-ordering reference: `docs/mesh_udp_capture.md`. The three settings are parsed in ONE place (`capture::udp_capture_settings_from_env`), shared by `CaptureConfig::from_env` and the injector.
- The `ip rule` priority `TPROXY_ROUTE_RULE_PRIORITY=100` is SEPARATE from table `TPROXY_ROUTE_TABLE=33133` and must stay below the kernel `main` rule (32766). Table `33133` is Ferrum-owned (never Istio's `133`); cleanup deletes only the EXACT rule (`ip rule del priority 100 lookup 33133`) and exact route, never by-lookup or table-flush.
- **Inbound emission is topology-specific (#1808):** the Sidecar injector passes `emit_inbound = true` (pod-destined plaintext UDP is captured and dropped fail-closed); the Ambient per-pod producer passes `false` (outbound-only, or relayed delivery is black-holed). Keep the OUTBOUND `! --dst-type LOCAL` jump ordered before any inbound catch-all.
- **Fail closed when routing is unavailable**: the script fatally preflights `command -v ip` before any UDP rule, the routing ADDs are NOT `|| true`, and routing is installed BEFORE the two `mangle PREROUTING` jumps (the injector init script has no cleanup trap).
- **Pod-netns only**: `CaptureConfig::host_netns` makes `udp_tproxy_commands_for_family` emit NO UDP rules for the node-agent host-netns fallback (TCP-only); host-network UDP capture is the separate `FERRUM_MESH_CAPTURE_UDP_HOST_NETNS_ENABLED` path.
- The default mark `0x733` is deliberately NOT Istio's `0x539` and does not alias Cilium's masked `0xF00` class (compile-time asserts in `src/capture/mod.rs`); `NODE_WAYPOINT_UDP_STEER_MARK = 0x736` is compile-time asserted distinct from `0x734`/`0x735`. The UDP listener port is distinct from the TCP outbound port.
- TPROXY is PREROUTING-only, so locally generated egress uses the MARK-only `FERRUM_MESH_UDP_OUTPUT_MARK` chain (proxy-UID `-m owner` self-exclusion lives HERE, never in PREROUTING) plus the mark-match `FERRUM_MESH_UDP_REINJECT` PREROUTING rule; live validation rides `netns-capture-live`.
- **UDP datagram-over-mesh egress (F3 §3.3 Stage 4, DUAL-TRANSPORT — mirrors raw-TCP egress)**: the Stage-3 capture→drop is replaced by capture→frame→mesh-tunnel→peer→unframe→local `UdpSocket`, plus the return path. Materialization mirrors raw-TCP VIP egress and is **dual-transport** (#1808): `materialize_mesh_outbound_udp_upstreams` gates `Ambient => Hbone, Sidecar => SidecarMtls, _ => return` — **Ambient** relays the datagram tunnel over an HBONE CONNECT (`:15008`), **Sidecar** over a mesh-mTLS CONNECT (`:15006`, `MeshMtlsConnectionPool::open_datagram_tunnel` — the Sidecar counterpart of `get_datagram_tunnel`: same `udp` marker + baggage, 1:1 fresh connection per session, NO capability probe, REQUIRED pinned peer). `build_outbound_mesh_targets` stamps the per-transport tag (`mesh.mtls` + pinned `mesh.spiffe_id` for Sidecar). `service_udp_stream_ports` × `cluster_ips`, `mesh_outbound_udp_upstream_id` (DISTINCT `__mesh-out-udp-upstream-*` id space), `mesh_outbound_udp_relay_proxy` (scheme `Udp` — the HBONE probe gate accepts `Http | Tcp | Udp`). Route table: `HostRouteTable.mesh_udp_egress` via `mesh_udp_egress_decision`, strict `(VIP, UDP port)` (canonicalized for mapped-IPv6). **DR connect timeout**: the synthesized relay proxy carries the UDP upstream's `dispatch_port_overrides` (per-port `portLevelSettings` connectTimeout/keepalive), and `apply_destination_rules` ALSO seeds a DR top-level `trafficPolicy.connectTimeout` onto the upstream's per-TARGET-port overrides (only where no per-port value exists, so portLevelSettings wins) so BOTH `get_datagram_tunnel` AND `open_datagram_tunnel` honor it — the UDP egress upstream is referenced by NO `config.proxies`, so the top-level timeout (applied only to config proxies) would otherwise be lost and the dial would fall back to the relay proxy's 5s default. Capability enrollment: a THIRD pass in `collect_mesh_tcp_egress_capability_targets` enrolls ONLY the Ambient `mesh.hbone` UDP targets (same `retain_keys` trap; widened probe gate or every UDP dial 502s) and SKIPS Sidecar `mesh.mtls` UDP targets (mirrors the raw-TCP passes — never a `:15008` probe to a sidecar; the Sidecar egress branch requires NO capability record). **Framing** (`src/proxy/mesh_udp_frame.rs`): `[u16 BE len][payload]`, max 65535; stateful `read_datagram` decoder over the byte-stream tunnel (partial reads normal; EOF mid-frame ⇒ None, never a partial; 0-length datagram preserved); GRO-coalesced reads framed PER segment. **Marker**: `UDP_PROTOCOL="udp"` + `is_udp_hbone_connect` (NARROWER than `is_hbone_connect` — requires the explicit `udp` marker; the two are DISJOINT, so an old dest 404s a `udp` CONNECT = fail-closed skew). Do NOT loosen `is_hbone_connect`. **Capability probe**: a UDP target probes with `HboneConnectionPool::warmup_datagram_connection_via` (`udp`-marked datagram CONNECT, mirrors `get_datagram_tunnel`) — NOT the byte-stream `warmup_connection_via` (`hbone` marker), which would hit the dest's byte-stream relay (TCP→app) instead of its `udp` relay; `probe_hbone` branches on `HboneProbeTarget.is_udp` (set from `BackendScheme::Udp`). **Source-capture producers (per topology, #2013)**: `MeshRuntimeConfig::udp_capture_listener()` emits the current-netns `PlaintextUdpCapture` listener for **Sidecar ONLY** (the injected sidecar shares the pod netns where the injector installed the TPROXY rules). **Ambient** by default binds no host-netns listener — its proxy runs outside the pod netns, so a host listener would receive nothing; instead mesh startup runs the per-pod-netns producer `NetnsUdpCaptureManager` by default. (`src/proxy/netns_udp_capture.rs` + `ProxyNetnsUdpBackend`), which installs the UDP TPROXY rules + binds the transparent capture/reply sockets INSIDE each enrolled pod's netns via `setns` (reusing `IptablesPlan::udp_setup_script`/`udp_teardown_script` over the shared `udp_tproxy_commands_for_family`, the shared `run_mesh_udp_capture_on_socket` loop, and a `PodNetnsReplySocketFactory`). The separate opt-in host placement (`FERRUM_MESH_CAPTURE_UDP_HOST_NETNS_ENABLED`, default false, Ambient-only) instead selects `ProxyHostUdpBackend`/`HostUdpCaptureManager` with its own interface-scoped host UDP command plan; keep that manager distinct from the Sidecar-only current-netns listener helper and from the node-agent host-netns iptables fallback limitation. **OUTBOUND-ONLY**: `udp_tproxy_commands_for_family` takes an `emit_inbound` param — the injector passes `true`, the producer passes `false` (`udp_only_commands_for_family`). The producer installs rules in EVERY enrolled pod netns incl. DESTINATION pods, where the inbound `--dst-type LOCAL` chain would capture+drop the HBONE relay's own delivery to the local app AND the source pod's return-path reply → black-hole both ways. It rides the node-agent per-pod registry (also published for Ambient when UDP capture is on: `should_publish_registry = node_waypoint_in_netns || udp_capture_enabled` — UDP alone, NOT anded with `outbound_capture_enabled`, so a port-0 TCP outbound listener cannot suppress UDP registry publication; does NOT flip the NodeWaypoint ipv6-deny/connect4-deferral posture), binds the socket BEFORE the rules (no black-hole), tears down only its own rules on removal (graceful shutdown `shutdown_all().await`s the per-netns teardown tasks), and disables the proxy-UID owner-match RETURN (no co-located proxy to exclude; keeping `1337` would fail-open a `1337`-app). **Fail-closed startup**: a malformed capture config OR a runtime image missing `sh`/`ip`/`iptables` (`preflight_capture_tools`) aborts mesh startup, never silent-retry. Helm requires `nodeAgent.enabled=true`+ebpf when the ambient UDP producer is on, and the UDP-enable chart predicate accepts only `true`/`1` (matches `parse_bool_env`). **Ambient per-pod authz evidence:** the node-agent registry publishes the pod's SPIFFE ID beside the pod UID; the per-netns producer fixes that pair for its lifetime and `get_datagram_tunnel` stamps `source.principal` + `source.pod_uid` in the existing authenticated HBONE baggage. Destination `mesh_authz` uses it only after the shared trusted-assertor/trust-domain gate and an exact live pod-UID↔SPIFFE slice lookup; otherwise it evaluates mesh-wide policies only. NodeWaypoint UDP/DTLS is a SEPARATE, node-local channel (issue #3286: ingress interface + registry pod addresses) and is unaffected by this HBONE-baggage evidence path. A topology with NO UDP relay (EastWestGateway / EgressGateway / waypoints) with `FERRUM_MESH_CAPTURE_UDP_ENABLED=true` emits NO listener/producer + a one-time `warn!`. `EnvConfig::reserved_gateway_ports()` reserves the host capture port for **Sidecar ONLY** — the Ambient producer binds in the pod netns, so the host port stays free. **Injector/init TPROXY-rule gating for Sidecar is MATCHED to the listener gate** (#1808): the injector only emits Sidecar pods, and `injector::sidecar_udp_capture_supported()` (a central `const fn` switch, currently `true`) ENABLES the init container's UDP TPROXY rules, the sidecar's runtime-enable env, AND the transparent-bind capability (`NET_ADMIN`) TOGETHER — so an injected Sidecar with the operator's `udp_capture_enabled` flag set both diverts UDP and binds a listener (the first working end-to-end UDP path). (`udp_tproxy_commands_for_family` itself still gates only on `host_netns`; the topology decision lives in the injector, the only pod-netns emitter. The node-agent/ambient host-netns path installs no UDP rules (`host_netns` short-circuits `udp_tproxy_commands_for_family`); Ambient's UDP source-capture instead rides the **per-pod-netns producer** (#2013, installs rules INSIDE each pod netns) and relays over HBONE. eBPF UDP capture (#1803) stays a non-goal.) **Egress datapath** (`mesh_udp_capture.rs`): the recv loop does route lookup + admit + drop-on-full `try_send` only (hot-path-light); a per-session mpsc+task opens the datagram tunnel via a **dual-transport branch mirroring `mesh_tcp_egress::handle_mesh_tcp_egress`** (1:1 dial, `udp` marker): **Ambient `mesh.hbone`** → `HboneConnectionPool::get_datagram_tunnel` (dial `:15008`, capability-record-gated + pinned `mesh.spiffe_id` plus optional per-pod source evidence); **Sidecar `mesh.mtls`** → `MeshMtlsConnectionPool::open_datagram_tunnel` (dial `:15006`/`mesh.mtls_port`, REQUIRED pinned `mesh.spiffe_id` via `target_mesh_mtls_expected_peer`, NO capability registry); a target with neither tag ends the session. Both share the LB guard + gateway-SVID-present gate; frames+writes. A `LoadBalancerConnectionGuard` is held for the session's lifetime (acquired right after LB selection, like `mesh_tcp_egress`), so least-connections LB sees active UDP sessions. Session teardown removes the map entry via `remove_if` keyed on a per-session `session_id` token (not unconditional `remove`), so an idle-sweep reap + same-key replacement in the gap before the task observes its closed channel never clobbers the replacement / double-decrements the cap. **Egress idle is bidirectional** (mirrors `relay_hbone_udp`): a shared `last_activity` atomic is bumped on BOTH client→egress sends and return-path (tunnel→client) datagrams, watched by one watchdog — a one-way reply stream (client quiet, dest streaming) does NOT time out mid-flow. **Tunnel writes are batched and bounded** (issue #5048): the egress loop drains only ALREADY-queued datagrams (`drain_queued_datagrams`, `try_recv`, never waiting for a batch to fill) into one `mesh_udp_frame::FrameBatch` (≤16 KiB wire / ≤1024 datagrams, the first datagram always joins, an over-bound follower is `held` and opens the next batch so FIFO holds) and writes it as ONE tunnel write under the write deadline (the idle window, or a fixed fallback when idle is disabled); byte reservations are released per dequeued datagram exactly as before, and a failed/stalled write accounts only the datagrams the tunnel fully accepted (`BatchWriteFailure`). `relay_hbone_udp`'s socket→tunnel arm does the same with `try_recv` on the destination socket. Coalescing is load-bearing, not just cheaper: h2 0.4.16 budgets sub-256-byte DATA frames per connection (`too_many_data_frames` → `ENHANCE_YOUR_CALM` GOAWAY), so one-frame-per-datagram bursts of small datagrams can kill the pooled HBONE connection; do not regress to per-datagram `write_all`. A stalled HBONE peer / exhausted flow-control tears the session down (drop tunnel, decrement `active_sessions`, `remove_if`-owned) instead of leaking a stuck task. **Return path (risk #1)**: a per-session transparent `UdpSocket` bound NON-LOCALLY (via `IP_TRANSPARENT`) to the captured orig-dst, so replies are SOURCED FROM the VIP:port the pod dialed (PKTINFO sets only the source IP, not port — a bound transparent socket sets both). **IPv4-mapped clients are canonicalized at capture**: the dual-stack `[::]` socket reports IPv4 senders as `::ffff:a.b.c.d` (`SocketAddr::V6`) while the orig-dst cmsg for the same packet is `SocketAddr::V4`; the client addr is unmapped to its V4 form BEFORE keying the session and building the reply socket, so the reply socket's family matches the orig-dst family and `send_to(client)` succeeds (genuine IPv6 clients are untouched). The session key uses the canonicalized client so key + reply agree. **Dest side**: `is_udp_hbone_connect` flows through the SAME transparent-relay synthesis (`build_inbound_hbone_relay_proxy` + open-relay guard) as the byte-stream relay (a combined `is_hbone_connect_any` drives path-norm / body-buffering-avoidance / CONNECT-405-bypass / route-miss-synthesis); `handle_hbone_udp_request` unframes the tunnel into a local `UdpSocket` to the CONNECT authority (open-relay guard applies — AND is RE-CHECKED on the post-route-override EFFECTIVE destination via `inbound_hbone_relay_destination_decision`, since the unknown-id synthesized relay proxy inherits the global plugin chain and a route-override plugin could otherwise move the destination outside the loopback / slice-declared-workload allowlist after the build-time guard ran) and frames replies back. `relay_hbone_udp`'s idle is refreshed on activity in BOTH directions (shared `last_activity` atomic + watchdog), so a one-way tunnel→app flow (e.g. telemetry) doesn't time out while the tunnel is active. The destination relay (`handle_hbone_udp_request`/`relay_hbone_udp`) is e2e functional-tested by `functional_mesh_udp_dest_*` **in isolation** (Stage 7: a `udp` mTLS CONNECT → framed datagram → local (non-enrolled) UDP echo → framed reply; + off-allowlist-refused + untrusted-peer-fail-closed; no root/netns needed) — this does NOT cover the destination pod being an ENROLLED Ambient pod, where the `tc_inbound` eBPF guard drops UDP to the pod IP and the pod's own OUTPUT-mark rules re-capture the app's reply to a host-netns relay socket. Two gaps remain, both fail-CLOSED (dropped, not leaked) and out of scope for the transport-half producer (#2030): (1) the live **source-capture** e2e (TPROXY → tunnel → return-source spoofing), which rides the §3.1 `netns-capture-live` follow-up; and (2) the full **e2e Ambient relay to an enrolled destination pod**, pending a TC-inbound UDP admit keyed on the relay socket's mark/identity (`ebpf/ferrum-ebpf/src/tc_inbound.rs`) + moving the dest-side inbound relay socket INSIDE the destination pod netns (so the reply is pod-LOCAL, excluded by the existing `! --dst-type LOCAL` scope) — a two-pod (both enrolled) live verification (tracked under #2013). **DTLS passthrough (Stage 5):** a DTLS port on THIS path is declared `protocol: UDP` and rides the SAME egress datapath **OPAQUELY**, with no `AppProtocol::Dtls` involved (that variant exists only for the NodeWaypoint listener surface of issue #3286 and is refused outright at the EgressGateway): the mesh never terminates DTLS, parses the ClientHello, or routes on DTLS SNI (UNLIKE the standalone `passthrough` UDP/DTLS stream proxy, which peeks the ClientHello for SNI). The inner DTLS stays end-to-end between workloads; the outer mesh hop is HBONE/mesh-mTLS-secured. East-west pod→peer only; EgressGateway external **DTLS** stays out of scope. Opaque relay pinned by `dtls_handshake_datagram_round_trips_opaque` in `mesh_udp_frame`.
- **External UDP egress via the EgressGateway (issue #3263) — BOTH halves**: the TERMINATOR is the gateway's `:15090` SVID-mTLS listener; `materialize_egress_gateway_proxies` publishes the runtime-only allowlist `MeshConfig.egress_udp_destinations` (rebuilt + reassigned on EVERY apply, empty off `EgressGateway` / with `FERRUM_MESH_EGRESS_STREAM_ENABLED=false`), consulted by `mesh_egress_udp_destination_dial_endpoint` / `mesh_egress_udp_destination_allowed`. **AUTHORITY ≠ DIAL DESTINATION** — each admission carries a precomputed bounded `dial_endpoints` set (`MAX_EGRESS_UDP_DIAL_ENDPOINTS` per destination + closed total `MAX_EGRESS_UDP_DESTINATIONS` allowlist cap, modulo-cursor selection, one relaxed atomic per CONNECT; entries beyond either cap are refused fail-closed). Post-override `mesh_egress_udp_destination_allowed` matches **dial endpoints only** (a STATIC hostname authority must never become an effective socket target — that would DNS-bypass `endpoints[]`; DNS/NONE and STATIC endpoint-IP dial targets remain usable because they are themselves dial endpoints; original-authority lookup and the authenticated-peer gate are unchanged): under `STATIC` a host authority dials the declared `endpoints[]` and is NEVER DNS-resolved, an endpoint-IP authority dials ONLY the endpoint it names, and a `STATIC` port with no usable endpoint is refused OUTRIGHT (never fall back to resolving the host); under `DNS`/`NONE` the single dial endpoint is the authority host itself. Do NOT collapse `host` and `dial_endpoints` back into one field. The PRODUCER is `materialize_mesh_external_udp_egress_upstreams` (`Sidecar`/`Ambient` only — the topologies with a UDP source-capture producer), gated by the SAME `FERRUM_MESH_EGRESS_STREAM_ENABLED` opt-in as the gateway allowlist (flag-off clears/publishes nothing so the two halves cannot disagree): for each `MESH_EXTERNAL` `ServiceEntry` UDP port with `resolution: STATIC` + IP-literal endpoints it emits `MeshConfig.external_udp_egress_routes` (`serde(skip)`, id space `__mesh-out-udp-ext-upstream-*` / `__mesh-out-udp-ext-relay-*`) plus ONE upstream whose single target dials the operator-configured `FERRUM_MESH_EGRESS_GATEWAY_ADDR` tagged `mesh.mtls` + `mesh.mtls_port` + REQUIRED pinned `mesh.spiffe_id` (`FERRUM_MESH_EGRESS_GATEWAY_SPIFFE_ID`) with `mesh.mtls_authority_host` = the EXTERNAL endpoint. Never `mesh.hbone`: the gateway has no `:15008`. `RouterCache::build_route_table` folds those routes into the SAME `mesh_udp_egress` `(dest ip, port)` index AFTER the in-mesh VIP loop (`or_insert`, so an in-mesh VIP always wins) — `mesh_udp_capture` therefore needs no external special case. **The two halves must refuse the SAME entry shapes**, or the producer publishes a route whose CONNECT the terminator is guaranteed to 404: the per-entry admission tests are kept identical to `build_egress_proxies_and_upstreams`'s — `location == MESH_EXTERNAL`, `service_entry_exported_to_namespace` against THIS workload's namespace (re-applied producer-side because `prepare_gateway_config_for_native_slice` takes a CP/xDS slice that `MeshSlice::from_gateway_config` never re-narrowed, and an empty `exportTo` is namespace-local), and a NON-EMPTY `hosts[]` (the gateway skips a host-less entry before the UDP branch, so it admits nothing at all — not even its endpoint-IP authorities). Fail closed with field-specific diagnostics at every step (no configured gateway ⇒ no route; non-`STATIC` resolution ⇒ refused, since a datagram carries no Host and only a declared endpoint address can attribute it; one env var without the other ⇒ startup error), and never a direct unauthenticated dial of the external destination.
- **UDP fail-closed contract (F3 §3.3 Stage 6 — consolidates Stage 3–4 hardening; full gate table in `docs/mesh.md`)**: the UDP datapath mirrors the raw-TCP egress fail-closed table gate-for-gate, and **every gate drops/rejects on doubt with NO plaintext or alternate-hop fallback** — every dial-error path ENDS the session. Do not regress any of: **routability** (orig-dst ∈ `mesh_udp_egress`; non-match drops BEFORE a slot/task is reserved), **gateway SVID present** (no SVID ⇒ end session, never plaintext), **Ambient capability probe** (un-enrolled `Udp` ⇒ drop, never blind-dial; the probe gate stays `Http|Tcp|Udp`), **pinned-peer SPIFFE** (missing/corrupt ⇒ refuse dial), **transport selection** (materializer stamps exactly one of `mesh.hbone`/`mesh.mtls`; runtime precedence HBONE→mesh-mTLS, neither ⇒ end session; a both-tags target — corrupted-only — resolves to HBONE, never relaxing a gate), **dest authenticated-peer** (`peer_spiffe_id.is_none()` ⇒ 403 before any socket opens; enforced inline in the handler, predicate-pinned; the fail-closed OUTCOME is e2e-tested by `functional_mesh_udp_dest_untrusted_peer_fails_closed` — under STRICT inbound the unchained peer is rejected at TLS, handler 403 stays predicate-pinned), **dest open-relay guard** (loopback / slice-declared workload addr+port only, RE-checked on the post-route-override effective destination ⇒ 403), **marker discipline** (`is_udp_hbone_connect`/`is_hbone_connect` disjoint AND exhaustive — a present-but-unparseable/non-UTF-8 marker fails closed to neither, NOT markerless; an unknown/future/malformed marker ⇒ neither ⇒ the dispatcher 405s the unrecognized CONNECT, pinned by `connect_marker_classification_is_exhaustive_and_fail_closed`), **session DoS bounds** (count + queued-bytes + idle), **return-path isolation** (per-session transparent socket bound to orig-dst, send-only, reply only to the captured client). Each gate has a named regression pin (see the `docs/mesh.md` table); posture confirmed by two independent audits + an adversarial red-team over 10 attack classes (no fail-open found). The ONE residual — the inbound guard validating the destination *string* before DNS resolution — is **not UDP-specific** (identical to the byte-stream relay's `connect_backend`) and inert in practice (workload addresses are pod IPs/loopback); out of scope for this stage.
- **Sidecar TCP capture listeners are family-complete (#4271).** `iptables` and `ip6tables` REDIRECT at the SAME ports, so the Sidecar listener plan is derived from whether IPv6 capture rules exist (`FERRUM_MESH_CAPTURE_IPV6_ENABLED`, derived from `FERRUM_MESH_IP6TABLES_ENABLED` + include/exclude CIDR families when unset; set explicitly by the injector when the rendered init plan contains `ip6tables` commands). A WILDCARD capture address becomes ONE dual-stack `[::]` listener with `IPV6_V6ONLY` explicitly disabled (a sibling `0.0.0.0` bind on the same port would be `EADDRINUSE`), downgrading to `0.0.0.0` ONLY on genuine IPv6 unavailability (`EAFNOSUPPORT`/`EADDRNOTAVAIL`/`EPROTONOSUPPORT`) and NEVER on `EADDRINUSE`. A LOOPBACK capture address becomes TWO listeners (`127.0.0.1` + `[::1]`) because `REDIRECT` in `OUTPUT` targets `127.0.0.1`/`::1` and a `[::1]` socket never sees v4-mapped traffic. Any other specific literal is a startup error from `validate_capture_listener_families` (`listener_plan()` stays infallible and warn-falls-back for read-only callers). `original_dst_from_raw_fd` folds a v4-mapped local address to IPv4 BEFORE choosing `SOL_IP`/`SOL_IPV6`, and compares the recovered destination against the CANONICAL local address.
- **`nat FERRUM_MESH_OUTBOUND` leads with `-m addrtype --dst-type LOCAL -j RETURN` (#4276)**, both families, ahead of every REDIRECT, gated on `!host_netns` exactly like the UDP sibling's `addrtype` direction split. Without it the shipped catch-all REDIRECT hairpins intra-pod `127.0.0.1` TCP into the outbound proxy. Order is load-bearing: once REDIRECT fires the chain returns.
- **Inbound HBONE relay screens resolved DNS answers (issue #4150).** A relay destination that resolves to loopback is refused immediately before the ordinary TCP/UDP dial via `MeshConfig::screen_inbound_relay_resolved_ips` on the current `RequestEpoch` mesh snapshot: mixed answers retain only the non-loopback candidates, an all-loopback answer fails closed. Canonicalisation folds IPv4-mapped IPv6 (`::ffff:127.0.0.1`) BEFORE the check, because `IpAddr::is_loopback()` is false for the mapped form while the dial still reaches `127.0.0.1`. Sidecar retains its own-network-namespace loopback privilege; Sidecar `ingress[]` remaps and separately authorized EgressGateway external UDP skip the screen.
- Cleanup scripts are best-effort even when `ip6tables` is missing.
- Injected SPIFFE ID format is `spiffe://{trust_domain}/ns/{namespace}/sa/{service_account}`.
- JWT secrets in injected manifests use `SecretKeyRef`, never plaintext.
- Opt in with `ferrum.io/inject=true` or `ferrum.io/mesh=enabled`; opt out with `sidecar.istio.io/inject=false` or `ferrum.io/inject=false`.
- Node-agent CNI is opt-in with `FERRUM_NODE_AGENT_CNI_ENABLED=false` by default.
- When enabled, node-agent binds `FERRUM_NODE_AGENT_CNI_SOCKET_PATH` and the `ferrum-cni` binary forwards kubelet ADD/DEL/CHECK/STATUS/GC over that socket.
- STATUS (CNI 1.1.0 only) is a fail-closed readiness probe: success means the node-agent listener is up, the main loop has completed initial pod sync, and a bounded live Kubernetes API pods list probe (same RBAC as ADD metadata; ≤750ms, under the 5s CNI RPC timeout) succeeded so ADD can be serviced; socket/IPC failure or not-ready replies map to CNI error code 50 without attachment fields or secret/input/Kubernetes-detail echoing. Older negotiated versions keep ADD/DEL/CHECK and fail closed on STATUS.
- Explicit node-global iptables fallback has no pod watcher or per-pod metadata dependency: its CNI ADD/CHECK/STATUS/GC remain unavailable until fallback rule installation completes, after which STATUS reflects node-global capture readiness rather than the eBPF relist/API probe.
- GC (CNI 1.1.0 only) reconciles Ferrum-owned CNI attachments against the required `cni.dev/valid-attachments` valid set and never removes watcher-only, another CNI network's, another pod's, or foreign-generation state. Ownership is mirrored into a crash-safe durable file beside the absolute `FERRUM_NODE_AGENT_CNI_SOCKET_PATH` (bound to the exact socket path identity) so GC can rehydrate Ferrum-owned `(network, containerID, ifname) -> pod UID` identity and the cleanup snapshot required to tear down stale eBPF state after node-agent restart. GC waits for the initial pod relist before using restored cleanup keys; rejected durable state and unresolved enrollment ownership fail closed without sweeping.
- In explicit node-global iptables fallback, CNI passthrough is gated on completed rule installation. GC may no-op only when the socket-bound durable file proves that the requested network has no stale eBPF claim; otherwise it fails closed and retains the record for an eBPF-capable generation to reconcile.
- kube-rs watcher remains source of truth; CNI only closes the kubelet-vs-watcher race and does not carry labels or annotations.
- **The chained conflist is a node-wide pod-creation dependency** (#3609). ADD fails closed on IPC transport failure — do not relax ADD to pass through unenrolled. DEL transport failure returns CNI empty-success so kubelet can finish teardown (stale state is reclaimed by GC and node-agent sweeps, #4309); CHECK transport failure stays fail-closed. The install order, ownership evidence, and swap checks are canonical in `docs/node_agent.md` → "Ownership markers" and "Ordering, locking, and what the swap checks do not claim".
- **Install order is fixed:** preflight the target conflist under the lock (remember marker + device/inode/length) → find the primary, build and serialize the chain BEFORE any shared write → stage the binary (`O_EXCL | O_NOFOLLOW`, hashed while written, final mode via `fchmod` on the open handle, #6126) → gate the shared binary → write the manifest → `rename` the binary → write the conflist LAST. Do NOT reorder the binary ahead of the manifest, and do NOT move validation/construction after the shared writes.
- **`previousBinarySha256` is an attestation, not an observation**: record it ONLY when the on-disk manifest carries this owner, names these artifacts, and already recorded that digest; otherwise write `null`.
- **Shared-binary rule, both directions**: install never replaces `/opt/cni/bin/ferrum-cni` with different bytes while another `.conf`/`.conflist`/`.json` names `ferrum-cni` (byte-identical republication allowed; unclassifiable/unscannable fails safe with `SharedBinaryInUse`); uninstall removes it only when this chain is cleared, nothing else references it, the manifest names THESE artifacts, and the digest matches. `uninstall` removes only marker-matching artifacts, conflist FIRST.
- **A failed install must not strand a same-owner chain**: on the error path it removes the preflight-classified chain after re-proving owner AND generation AND device/inode; the original error is always surfaced.
- Publish is `rename`-only (never truncate in place); an identical staged digest skips the rename. Every mutating run holds the exclusive `flock` on `.ferrum-cni-install.lock`; artifacts are opened `O_NOFOLLOW`, classified, capped, and hashed through the SAME handle and removed only after a re-open confirms device/inode. A foreign conflist makes cleanup exit non-zero.
- **`rollback-watch`** (native sidecar ordered BEFORE the installer) waits for a conflist with its OWN owner AND generation before starting the readiness budget, and must NOT probe STATUS before then (pinned by `a_status_probe_before_publication_can_never_disarm_the_rollback`). Outcomes stay distinct (`Ready` / never-published / rolled-back / superseded / incomplete); only rolled-back may claim the dependency was lifted. Post-readiness crash-loops are deliberately NOT auto-rolled-back.
- **Helm cleanup graph**: cleanup is a `pre-delete` DaemonSet (never a Job; never add `pre-upgrade`/`pre-rollback`), `hostNetwork: true`, whose readiness marker is retracted at start (non-regular marker REFUSED) and republished only after this run's cleanup succeeded. Its ServiceAccounts/Role/RoleBinding are ORDINARY release resources (Helm 3.19+/v4 delete earlier `hook-succeeded` hooks on a later failure) and the DaemonSet carries `before-hook-creation` ONLY. The wait Job deletes the DaemonSet with FOREGROUND propagation, succeeds only on a 404, has only `get`+`delete` on the named DaemonSet plus `get` on its status, and treats a `0/0` report as failure. Evidence: Rust integration suite, CI Helm contract assertions, and `tests/k8s/cni_lifecycle_live/run.sh`.
