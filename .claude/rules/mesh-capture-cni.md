# Mesh Capture, Injector, Node Agent, And CNI Rules

Implementation invariants for this mesh subsystem. Shared mesh invariants: `mesh.md`; operator docs:
`docs/mesh.md`.

## Injector, Node Agent, And CNI

- Injector mode serves `POST /mutate` Kubernetes AdmissionReview and emits JSON patches only.
- Sidecars run as `PROXY_UID`; optional iptables init container requires `NET_ADMIN`.
- IPv4/IPv6 capture CIDRs must stay partitioned into `iptables` and `ip6tables` blocks. `FERRUM_MESH_IP6TABLES_ENABLED=auto|true|false` controls IPv6 fan-out.

### UDP TPROXY Capture Rules

- **UDP capture uses `mangle` TPROXY, not REDIRECT** (`FERRUM_MESH_CAPTURE_UDP_ENABLED`, default off: no rules and no listener). Operator reference: `docs/mesh.md` → "UDP TPROXY capture"; full rule-ordering reference: `docs/mesh_udp_capture.md`. The three settings are parsed in ONE place (`capture::udp_capture_settings_from_env`), shared by `CaptureConfig::from_env` and the injector.
- The `ip rule` priority `TPROXY_ROUTE_RULE_PRIORITY=100` is SEPARATE from table `TPROXY_ROUTE_TABLE=33133` and must stay below the kernel `main` rule (32766). Table `33133` is Ferrum-owned (never Istio's `133`); cleanup deletes only the EXACT rule (`ip rule del priority 100 lookup 33133`) and exact route, never by-lookup or table-flush.
- **Inbound emission is topology-specific (#1808):** `udp_tproxy_commands_for_family` takes `emit_inbound`. The Sidecar injector passes `true` (pod-destined plaintext UDP is captured and dropped fail-closed); the Ambient per-pod producer passes `false` via `udp_only_commands_for_family` (OUTBOUND-ONLY: it installs rules in EVERY enrolled pod netns incl. destination pods, where an inbound `--dst-type LOCAL` chain would capture+drop the HBONE relay's delivery to the local app AND the source pod's return-path reply, black-holing both ways). Keep the OUTBOUND `! --dst-type LOCAL` jump ordered before any inbound catch-all.
- **Fail closed when routing is unavailable**: the script fatally preflights `command -v ip` before any UDP rule, the routing ADDs are NOT `|| true`, and routing is installed BEFORE the two `mangle PREROUTING` jumps (the injector init script has no cleanup trap).
- **Pod-netns only**: `CaptureConfig::host_netns` makes `udp_tproxy_commands_for_family` emit NO UDP rules for the node-agent host-netns fallback (TCP-only); host-network UDP capture is the separate `FERRUM_MESH_CAPTURE_UDP_HOST_NETNS_ENABLED` path.
- The default mark `0x733` is deliberately NOT Istio's `0x539` and does not alias Cilium's masked `0xF00` class (compile-time asserts in `src/capture/mod.rs`); `NODE_WAYPOINT_UDP_STEER_MARK = 0x736` is compile-time asserted distinct from `0x734`/`0x735`. The UDP listener port is distinct from the TCP outbound port.
- TPROXY is PREROUTING-only, so locally generated egress uses the MARK-only `FERRUM_MESH_UDP_OUTPUT_MARK` chain (proxy-UID `-m owner` self-exclusion lives HERE, never in PREROUTING) plus the mark-match `FERRUM_MESH_UDP_REINJECT` PREROUTING rule; live validation rides `netns-capture-live`.

### UDP Datagram-Over-Mesh Egress

Capture→frame→mesh tunnel→peer→unframe→local `UdpSocket`, plus the return path (F3 §3.3 Stage 4). Narrative: `docs/mesh_udp_capture.md` ("Capture listener, egress, and destination relay", "Source-capture producers", "DTLS", "Fail-closed gates") and `docs/mesh.md` → "UDP egress".

- **Dual-transport, mirroring raw-TCP VIP egress (#1808):** `materialize_mesh_outbound_udp_upstreams` gates `Ambient => Hbone, Sidecar => SidecarMtls, _ => return`. Ambient tunnels over HBONE (`:15008`, `HboneConnectionPool::get_datagram_tunnel`); Sidecar over mesh-mTLS (`:15006`, `MeshMtlsConnectionPool::open_datagram_tunnel`: same `udp` marker + baggage, 1:1 fresh connection per session, NO capability probe, REQUIRED pinned peer for same-cluster targets). `build_outbound_mesh_targets` stamps the per-transport tag (`mesh.mtls` + pinned `mesh.spiffe_id` for a same-cluster Sidecar target); cross-cluster targets follow the next bullet.
- **Cross-cluster UDP targets (`mesh.cross_cluster`) are the pin/probe exception.** UDP rides the cross-cluster builders (`append_cross_cluster_ambient_hbone_targets` / `append_cross_cluster_sidecar_l4_targets`); the east-west gateway LB-picks the remote pod, so these targets carry NO `mesh.spiffe_id` pin and Ambient skips the HBONE capability gate (and enrollment). Each dial instead REQUIRES the remote `mesh.trust_domain`, the per-port east-west SNI (`mesh.eastwest_sni`), the gateway dial endpoint (`mesh.hbone_dial_host`/`mesh.hbone_port`, or `mesh.mtls_dial_host`/`mesh.mtls_port`), and the real-pod CONNECT authority (`mesh.hbone_authority_host` / `mesh.mtls_authority_host`); a missing one refuses the dial (`mesh_udp_capture.rs` HBONE branch; `MeshMtlsDialPlan::resolve` sets `expected_peer: None` only on this arm). Do NOT apply the same-cluster pin/probe rules to these targets or drop their metadata checks. Pin: `cross_cluster_udp_materializes_per_port_targets_for_both_captured_topologies`; narrative: `docs/mesh.md` → "Raw-TCP egress" (Cross-cluster L4 extension).
- Upstreams: `service_udp_stream_ports` × `cluster_ips`, `mesh_outbound_udp_upstream_id` (DISTINCT `__mesh-out-udp-upstream-*` id space), `mesh_outbound_udp_relay_proxy` (scheme `Udp`; the HBONE probe gate accepts `Http | Tcp | Udp`). Routing: `HostRouteTable.mesh_udp_egress` via `mesh_udp_egress_decision`, strict `(VIP, UDP port)`, canonicalized for mapped-IPv6.
- **DR connect timeout:** the relay proxy carries the UDP upstream's `dispatch_port_overrides` (per-port `portLevelSettings` connectTimeout/keepalive), and `apply_destination_rules` ALSO seeds a top-level `trafficPolicy.connectTimeout` onto each UDP target policy port lacking a per-port value (`portLevelSettings` wins), so BOTH `get_datagram_tunnel` AND `open_datagram_tunnel` honor it. The UDP upstream is referenced by NO `config.proxies`, so without the seed the dial falls back to the relay proxy's 5s default (pin: `mesh_outbound_udp_upstream_receives_top_level_dr_connect_timeout`).
- **Capability enrollment:** a THIRD pass in `collect_mesh_tcp_egress_capability_targets` enrolls ONLY same-cluster Ambient `mesh.hbone` UDP targets (cross-cluster targets are skipped; same `retain_keys` trap; widened probe gate or every UDP dial 502s) and SKIPS Sidecar `mesh.mtls` UDP targets (never a `:15008` probe to a sidecar; the Sidecar branch needs NO capability record).
- **Framing** (`src/proxy/mesh_udp_frame.rs`): `[u16 BE len][payload]`, max 65535; stateful `read_datagram` decoder (partial reads normal; EOF mid-frame ⇒ None, never a partial; 0-length datagram preserved); GRO-coalesced reads framed PER segment.
- **Marker:** `UDP_PROTOCOL="udp"` + `is_udp_hbone_connect`, NARROWER than and DISJOINT from `is_hbone_connect`, so an old dest 404s a `udp` CONNECT (fail-closed skew). Do NOT loosen `is_hbone_connect`.
- **Capability probe:** a UDP target probes with `HboneConnectionPool::warmup_datagram_connection_via` (`udp` marker), NOT the byte-stream `warmup_connection_via` (`hbone` marker), which would reach the dest's TCP→app relay instead of its `udp` relay; `probe_hbone` branches on `HboneProbeTarget.is_udp` (set from `BackendScheme::Udp`).

#### Source-capture producers (#2013)

- `MeshRuntimeConfig::udp_capture_listener()` emits the current-netns `PlaintextUdpCapture` listener for **Sidecar ONLY** (the sidecar shares the pod netns holding the injector's TPROXY rules). **Ambient** binds no host-netns listener by default (it would receive nothing); mesh startup runs the per-pod-netns producer `NetnsUdpCaptureManager` (`src/proxy/netns_udp_capture.rs` + `ProxyNetnsUdpBackend`), which installs the rules and binds the transparent capture/reply sockets INSIDE each enrolled pod netns via `setns`, reusing `IptablesPlan::udp_setup_script`/`udp_teardown_script` over `udp_tproxy_commands_for_family`, `run_mesh_udp_capture_on_socket`, and a `PodNetnsReplySocketFactory`.
- The opt-in host placement (`FERRUM_MESH_CAPTURE_UDP_HOST_NETNS_ENABLED`, default false, Ambient-only) selects `ProxyHostUdpBackend`/`HostUdpCaptureManager` with its own interface-scoped command plan; keep it distinct from the Sidecar-only listener helper and from the node-agent host-netns iptables fallback limitation.
- **Registry:** `NodeAgentConfig::from_env_config` publishes the per-pod registry when `should_publish_registry = node_waypoint_in_netns || ambient_topology`: for Ambient even with UDP off (the `NetnsUdpCleanupManager` needs it to reap stale rules), and NOT anded with `outbound_capture_enabled` (a port-0 TCP outbound listener must not suppress it). Publication does NOT flip the NodeWaypoint ipv6-deny/connect4-deferral posture.
- **Producer lifecycle:** per pod netns, install a scope-exact fail-closed OUTPUT DROP guard, bind the socket BEFORE the TPROXY rules (no black-hole), and remove the guard only after the socket is adopted and the full ruleset is live; a failed bind/setup keeps the guard (never a plaintext bypass). It tears down only its own rules (graceful shutdown `shutdown_all().await`s the per-netns teardown tasks) and disables the proxy-UID owner-match RETURN (no co-located proxy; keeping `1337` would fail-open a `1337`-app). Readiness markers and the BPF UDP gate: `docs/mesh_udp_capture.md` → "Source-capture producers".
- **Fail-closed startup:** a malformed capture config OR a runtime image missing `sh`/`ip`/`iptables` (`preflight_capture_tools`) aborts mesh startup, never silent-retry. Helm requires `nodeAgent.enabled=true`+ebpf when the ambient UDP producer is on; the chart UDP-enable predicate accepts only `true`/`1` (matches `parse_bool_env`).
- **Ambient per-pod authz evidence:** the registry publishes the pod's SPIFFE ID beside its UID; the producer fixes that pair for its lifetime and `get_datagram_tunnel` stamps `source.principal` + `source.pod_uid` in the authenticated HBONE baggage. Destination `mesh_authz` applies per-pod source scope only after the shared trusted-assertor/trust-domain gate and an exact live pod-UID↔SPIFFE slice lookup, else mesh-wide source scoping (either way unioned with the destination-scoped policy set). NodeWaypoint UDP/DTLS (issue #3286: ingress interface + registry pod addresses) is a SEPARATE channel, unaffected.
- A topology with NO UDP relay (EastWestGateway / EgressGateway / waypoints) and `FERRUM_MESH_CAPTURE_UDP_ENABLED=true` emits NO listener/producer + a one-time `warn!`. `EnvConfig::reserved_gateway_ports()` reserves the capture port only in mesh mode, with UDP capture enabled, a nonzero port, and a topology where the mesh proxy binds it: **Sidecar** (also when the topology is unset), or Ambient with the host placement. The default Ambient producer binds in the pod netns.
- **Sidecar injector gating MATCHES the listener gate** (#1808): `injector::sidecar_udp_capture_supported()` (central `const fn`, currently `true`) enables the init container's UDP TPROXY rules, the runtime-enable env, AND `NET_ADMIN` TOGETHER, so a Sidecar with the operator's `udp_capture_enabled` flag both diverts UDP and binds a listener. `udp_tproxy_commands_for_family` gates only on `host_netns`; the topology decision lives in the injector, the only pod-netns emitter. eBPF UDP capture (#1803) stays a non-goal.

#### Egress datapath (`mesh_udp_capture.rs`)

- The recv loop does route lookup + admit + drop-on-full `try_send` only. A per-session mpsc+task branches like `mesh_tcp_egress::handle_mesh_tcp_egress` (1:1 dial, `udp` marker): `mesh.hbone` → `get_datagram_tunnel` (same-cluster: capability-record-gated, pin from the materializer-stamped `mesh.spiffe_id` via `target_expected_peer_spiffe`, where a corrupt pin refuses and an absent tag on an operator-supplied target keeps trust-domain-only verification; optional per-pod source evidence); `mesh.mtls` → `open_datagram_tunnel` (`:15006`/`mesh.mtls_port`, same-cluster REQUIRED pin via `MeshMtlsDialPlan::resolve` / `target_mesh_mtls_expected_peer`, NO capability registry); cross-cluster targets of either tag use the remote-scope checks above instead; neither tag ends the session. Both share the LB guard + gateway-SVID-present gate.
- A `LoadBalancerConnectionGuard` is held for the session's lifetime (acquired right after LB selection), so least-connections sees UDP sessions. Teardown uses `remove_if` keyed on a per-session `session_id` (not unconditional `remove`), so an idle-sweep reap + same-key replacement never clobbers the replacement or double-decrements the cap.
- **Idle is bidirectional** (mirrors `relay_hbone_udp`): one `last_activity` atomic, bumped by client→egress sends AND tunnel→client datagrams, feeds one watchdog, so a one-way reply stream does NOT time out.
- **Tunnel writes are batched and bounded (#5048):** drain only ALREADY-queued datagrams (`drain_queued_datagrams`, `try_recv`, never wait to fill) into one `mesh_udp_frame::FrameBatch` (≤16 KiB wire / ≤1024 datagrams; the first always joins; an over-bound follower is `held` for the next batch, so FIFO holds) and write it as ONE tunnel write under the write deadline (idle window, or a fixed fallback when idle is disabled). Byte reservations release per dequeued datagram; a failed/stalled write accounts only datagrams the tunnel fully accepted (`BatchWriteFailure`). `relay_hbone_udp`'s socket→tunnel arm does the same. Do not regress to per-datagram `write_all`: h2's small-DATA-frame budget (`too_many_data_frames` → `ENHANCE_YOUR_CALM` GOAWAY) would kill the pooled HBONE connection.
- A stalled HBONE peer / exhausted flow-control tears the session down (drop tunnel, decrement `active_sessions`, `remove_if`-owned), never a stuck task.
- **Return path (risk #1):** a per-session transparent `UdpSocket` bound NON-LOCALLY (`IP_TRANSPARENT`) to the captured orig-dst, so replies are SOURCED FROM the dialed VIP:port (PKTINFO sets only the IP). **IPv4-mapped clients are canonicalized at capture:** the dual-stack `[::]` socket reports `::ffff:a.b.c.d` while the orig-dst cmsg is `SocketAddr::V4`, so the client is unmapped BEFORE keying the session and building the reply socket, keeping key, reply family, and `send_to(client)` consistent (genuine IPv6 clients untouched).

#### Destination relay and DTLS

- `is_udp_hbone_connect` uses the SAME relay synthesis (`build_inbound_hbone_relay_proxy` + open-relay guard) as the byte-stream relay; a combined `is_hbone_connect_any` drives path-norm / body-buffering-avoidance / CONNECT-405-bypass / route-miss-synthesis. `handle_hbone_udp_request` unframes into a local `UdpSocket` to the CONNECT authority. The guard is RE-CHECKED on the post-route-override EFFECTIVE destination (`inbound_hbone_relay_destination_decision`), because the synthesized relay proxy inherits the global plugin chain. A guard denial is overridden only by the EgressGateway external-UDP allowlist, matched on dial endpoints only (see below). `relay_hbone_udp` idle refreshes in BOTH directions.
- Enrolled Ambient destination pod: `maybe_bind_pod_netns_udp_relay_socket` maps the destination IP through the pod registry and opens the relay socket INSIDE that pod netns (reply stays pod-LOCAL); failure refuses the tunnel, never a host-netns fallback. This socket carries no mark and needs no `tc_inbound` admit: delivery from inside the pod netns never crosses the host-veth classifier. The marked-socket, relay-cgroup and reply-source `tc_inbound` admission in `mesh-hbone-waypoint.md` → "Relay authorization past `tc_inbound`" governs only the separate NodeWaypoint UDP listener relay; do not apply it here. Coverage: `functional_mesh_udp_dest_*` (relay in isolation, no root/netns) and `functional_mesh_live_source_capture_udp_manager_hbone_round_trip` in `netns-capture-live` (full source-capture → enrolled-destination round trip; `docs/mesh.md` support-matrix note 12).
- **DTLS passthrough (Stage 5):** a DTLS port here is `protocol: UDP` relayed **OPAQUELY** on the same datapath (`AppProtocol::Dtls` matters only on the NodeWaypoint listener surface of issue #3286 and is refused outright at the EgressGateway). Never terminate DTLS, parse the ClientHello, or route on DTLS SNI (unlike the standalone `passthrough` stream proxy). East-west only; external **DTLS** egress stays out of scope. Pin: `dtls_handshake_datagram_round_trips_opaque` in `mesh_udp_frame`.

### External UDP Egress Via The EgressGateway (issue #3263)

Narrative: `docs/mesh.md` → "External UDP egress (EgressGateway)" and the source-side paragraph under "UDP egress". Both halves are gated by `FERRUM_MESH_EGRESS_STREAM_ENABLED`.

- **Terminator** (`:15090` SVID-mTLS): `materialize_egress_gateway_proxies` publishes the runtime-only allowlist `MeshConfig.egress_udp_destinations`, rebuilt + reassigned on EVERY apply (empty off `EgressGateway` or flag-off), consulted by `mesh_egress_udp_destination_dial_endpoint` / `mesh_egress_udp_destination_allowed`.
- **AUTHORITY ≠ DIAL DESTINATION:** each admission carries a precomputed bounded `dial_endpoints` set (`MAX_EGRESS_UDP_DIAL_ENDPOINTS` per destination, closed total `MAX_EGRESS_UDP_DESTINATIONS`; over-cap entries refused fail-closed). `STATIC`: a host authority dials the declared `endpoints[]` and is NEVER DNS-resolved, an endpoint-IP authority dials ONLY that endpoint, and a port with no usable endpoint is refused OUTRIGHT. `DNS`/`NONE`: the single dial endpoint is the authority host. Do NOT collapse `host` and `dial_endpoints` into one field.
- Post-override `mesh_egress_udp_destination_allowed` matches **dial endpoints only**, so a STATIC hostname authority never becomes a socket target (DNS bypass of `endpoints[]`); DNS/NONE and STATIC endpoint-IP targets stay usable because they are dial endpoints. Original-authority lookup and the authenticated-peer gate are unchanged.
- **Producer:** `materialize_mesh_external_udp_egress_upstreams` (`Sidecar`/`Ambient` only), flag-off clears/publishes nothing. For a `MESH_EXTERNAL` `ServiceEntry` UDP port with `resolution: STATIC`, it emits one `MeshConfig.external_udp_egress_routes` entry (`serde(skip)`, ids `__mesh-out-udp-ext-upstream-*` / `__mesh-out-udp-ext-relay-*`) and one single-target upstream PER usable IP-literal `(endpoint IP, service port)` (route count capped by `MAX_EGRESS_UDP_DESTINATIONS`); each target dials `FERRUM_MESH_EGRESS_GATEWAY_ADDR`, tagged `mesh.mtls` + `mesh.mtls_port` + REQUIRED pinned `mesh.spiffe_id` (`FERRUM_MESH_EGRESS_GATEWAY_SPIFFE_ID`), `mesh.mtls_authority_host` = the EXTERNAL endpoint. Never `mesh.hbone` (no `:15008` on the gateway).
- `RouterCache::build_route_table` folds those routes into the SAME `mesh_udp_egress` `(dest ip, port)` index AFTER the in-mesh VIP loop (`or_insert`: an in-mesh VIP always wins); `mesh_udp_capture` needs no special case.
- **Both halves must refuse the SAME entry shapes** (else the route's CONNECT is guaranteed to 404). Keep the producer's tests identical to `build_egress_proxies_and_upstreams`: `location == MESH_EXTERNAL`; `service_entry_exported_to_namespace` for THIS workload's namespace (re-applied because `prepare_gateway_config_for_native_slice` takes a CP/xDS slice `MeshSlice::from_gateway_config` never re-narrowed; empty `exportTo` is namespace-local); NON-EMPTY `hosts[]` (the gateway skips a host-less entry entirely).
- Fail closed with field-specific diagnostics: no configured gateway ⇒ no route; non-`STATIC` ⇒ refused (a datagram has no Host; only a declared endpoint address attributes it); one env var without the other ⇒ startup error. Never a direct unauthenticated dial.

### UDP Fail-Closed Contract (Stage 6)

- The UDP datapath mirrors the raw-TCP egress fail-closed table gate-for-gate: **every gate drops/rejects on doubt with NO plaintext or alternate-hop fallback**, and every dial-error path ENDS the session. Gate table with regression pins: `docs/mesh_udp_capture.md` → "Fail-closed gates". Do not regress: routability (drop BEFORE a slot/task is reserved), gateway SVID present, Ambient capability probe (same-cluster; gate stays `Http|Tcp|Udp`), pinned-peer SPIFFE (same-cluster; cross-cluster requires the remote trust domain + east-west SNI + CONNECT authority instead), transport selection (exactly one tag; HBONE→mesh-mTLS precedence; a corrupted both-tags target resolves to HBONE, never relaxing a gate), dest authenticated peer (`peer_spiffe_id.is_none()` ⇒ 403 before any socket, inline in the handler; outcome e2e-pinned by `functional_mesh_udp_dest_untrusted_peer_fails_closed`), dest open-relay guard (re-checked post-override), session DoS bounds (count + queued-bytes + idle), return-path isolation.
- **Marker discipline:** `is_udp_hbone_connect`/`is_hbone_connect` are disjoint AND exhaustive. A present-but-unparseable/non-UTF-8 marker fails closed to neither, NOT markerless; an unknown/future/malformed marker ⇒ the dispatcher 405s the CONNECT (`connect_marker_classification_is_exhaustive_and_fail_closed`).
- Residual, not UDP-specific (same as the byte-stream `connect_backend`): the guard matches the destination *string* before DNS resolution; the only post-resolution check is the #4150 loopback screen below. Inert in practice (workload addresses are pod IPs/loopback).

### Sidecar TCP Capture, Relay DNS Screen, And Injection

- **Sidecar TCP capture listeners are family-complete (#4271).** `iptables` and `ip6tables` REDIRECT at the SAME ports, so the Sidecar listener plan is derived from whether IPv6 capture rules exist (`FERRUM_MESH_CAPTURE_IPV6_ENABLED`, derived from `FERRUM_MESH_IP6TABLES_ENABLED` + include/exclude CIDR families when unset; set explicitly by the injector when the rendered init plan contains `ip6tables` commands). A WILDCARD capture address becomes ONE dual-stack `[::]` listener with `IPV6_V6ONLY` explicitly disabled (a sibling `0.0.0.0` bind on the same port would be `EADDRINUSE`), downgrading to `0.0.0.0` ONLY on genuine IPv6 unavailability (`EAFNOSUPPORT`/`EADDRNOTAVAIL`/`EPROTONOSUPPORT`) and NEVER on `EADDRINUSE`. A LOOPBACK capture address becomes TWO listeners (`127.0.0.1` + `[::1]`) because `REDIRECT` in `OUTPUT` targets `127.0.0.1`/`::1` and a `[::1]` socket never sees v4-mapped traffic. Any other specific literal is a startup error from `validate_capture_listener_families` (`listener_plan()` stays infallible and warn-falls-back for read-only callers). `original_dst_from_raw_fd` folds a v4-mapped local address to IPv4 BEFORE choosing `SOL_IP`/`SOL_IPV6`, and compares the recovered destination against the CANONICAL local address.
- **`nat FERRUM_MESH_OUTBOUND` leads with `-m addrtype --dst-type LOCAL -j RETURN` (#4276)**, both families, ahead of every REDIRECT, gated on `!host_netns` exactly like the UDP sibling's `addrtype` direction split. Without it the shipped catch-all REDIRECT hairpins intra-pod `127.0.0.1` TCP into the outbound proxy. Order is load-bearing: once REDIRECT fires the chain returns.
- **Inbound HBONE relay screens resolved DNS answers (issue #4150).** A relay destination that resolves to loopback is refused immediately before the ordinary TCP/UDP dial via `MeshConfig::screen_inbound_relay_resolved_ips` on the current `RequestEpoch` mesh snapshot: mixed answers retain only the non-loopback candidates, an all-loopback answer fails closed. Canonicalisation folds IPv4-mapped IPv6 (`::ffff:127.0.0.1`) BEFORE the check, because `IpAddr::is_loopback()` is false for the mapped form while the dial still reaches `127.0.0.1`. Sidecar retains its own-network-namespace loopback privilege; Sidecar `ingress[]` remaps and separately authorized EgressGateway external UDP skip the screen.
- Cleanup scripts are best-effort even when `ip6tables` is missing.
- Injected SPIFFE ID format is `spiffe://{trust_domain}/ns/{namespace}/sa/{service_account}`.
- JWT secrets in injected manifests use `SecretKeyRef`, never plaintext.
- Opt in with `ferrum.io/inject=true` or `ferrum.io/mesh=enabled`; opt out with `sidecar.istio.io/inject=false` or `ferrum.io/inject=false`.

### Node-Agent CNI

- Node-agent CNI is opt-in with `FERRUM_NODE_AGENT_CNI_ENABLED=false` by default.
- When enabled, node-agent binds `FERRUM_NODE_AGENT_CNI_SOCKET_PATH` and the `ferrum-cni` binary forwards kubelet ADD/DEL/CHECK/STATUS/GC over that socket.
- STATUS (CNI 1.1.0 only) is a fail-closed readiness probe: success means the node-agent listener is up, the main loop has completed initial pod sync, and a bounded live Kubernetes API pods list probe (same RBAC as ADD metadata; ≤750ms, under the 5s CNI RPC timeout) succeeded so ADD can be serviced; socket/IPC failure or not-ready replies map to CNI error code 50 without attachment fields or secret/input/Kubernetes-detail echoing. Older negotiated versions keep ADD/DEL/CHECK and fail closed on STATUS.
- Explicit node-global iptables fallback has no pod watcher or per-pod metadata dependency: its CNI ADD/CHECK/STATUS/GC remain unavailable until fallback rule installation completes, after which STATUS reflects node-global capture readiness rather than the eBPF relist/API probe.
- GC (CNI 1.1.0 only) reconciles Ferrum-owned CNI attachments against the required `cni.dev/valid-attachments` valid set and never removes watcher-only, another CNI network's, another pod's, or foreign-generation state. Ownership is mirrored into a crash-safe durable file beside the absolute `FERRUM_NODE_AGENT_CNI_SOCKET_PATH` (bound to the exact socket path identity) so GC can rehydrate Ferrum-owned `(network, containerID, ifname) -> pod UID` identity and the cleanup snapshot required to tear down stale eBPF state after node-agent restart. GC waits for the initial pod relist before using restored cleanup keys; rejected durable state and unresolved enrollment ownership fail closed without sweeping.
- In explicit node-global iptables fallback, CNI passthrough is gated on completed rule installation. GC may no-op only when the socket-bound durable file proves that the requested network has no stale eBPF claim; otherwise it fails closed and retains the record for an eBPF-capable generation to reconcile.
- kube-rs watcher remains source of truth; CNI only closes the kubelet-vs-watcher race and does not carry labels or annotations.
- **The chained conflist is a node-wide pod-creation dependency** (#3609). ADD fails closed on IPC transport failure — do not relax ADD to pass through unenrolled. DEL transport failure returns CNI empty-success so kubelet can finish teardown (stale state is reclaimed by GC and node-agent sweeps, #4309); CHECK transport failure stays fail-closed. The install order, ownership evidence, and swap checks are canonical in `docs/node_agent.md` → "Ownership markers" and "Ordering, locking, and what the swap checks do not claim".
- **Install order is fixed:** preflight the target conflist under the lock (remember marker + device/inode/length) → find the primary, build and serialize the chain BEFORE any shared write → stage the binary (`O_EXCL | O_NOFOLLOW`, hashed while written, final mode via `fchmod` on the open handle, #6126) → gate the shared binary → write the manifest → `rename` the binary → write the conflist LAST. Do NOT reorder the binary ahead of the manifest, and do NOT move validation/construction after the shared writes.
- **`previousBinarySha256` is an attestation, not an observation**: record it ONLY when the on-disk manifest carries this owner, names these artifacts, and already recorded that digest; otherwise write `null`.
- **Shared-binary rule, both directions**: install never replaces `/opt/cni/bin/ferrum-cni` with different bytes while another `.conf`/`.conflist`/`.json` names `ferrum-cni` (byte-identical republication allowed; unclassifiable/unscannable fails safe with `SharedBinaryInUse`); uninstall removes it only when this chain is cleared, nothing else references it, the manifest names THESE artifacts, and the digest matches. `uninstall` removes only marker-matching artifacts, conflist FIRST.
- **A failed install must not strand a same-owner chain**: on the error path it removes the preflight-classified chain after re-proving owner AND generation AND device/inode; the original error is always surfaced.
- Publish is `rename`-only (never truncate in place); an identical staged digest skips the rename. Every mutating run holds the exclusive `flock` on `.ferrum-cni-install.lock`; artifacts are opened `O_NOFOLLOW`, classified, capped, and hashed through the SAME handle and removed only after a re-open confirms device/inode. A foreign conflist makes cleanup exit non-zero.
- **`rollback-watch`** (native sidecar ordered BEFORE the installer) waits for a conflist with its OWN owner AND generation before starting the readiness budget, and must NOT probe STATUS before then (pinned by `a_status_probe_before_publication_can_never_disarm_the_rollback`). Outcomes stay distinct (`Ready` / never-published / rolled-back / superseded / incomplete); only rolled-back may claim the dependency was lifted. Post-readiness crash-loops are deliberately NOT auto-rolled-back.
- **Helm cleanup graph**: cleanup is a `pre-delete` DaemonSet (never a Job; never add `pre-upgrade`/`pre-rollback`), `hostNetwork: true`, whose readiness marker is retracted at start (non-regular marker REFUSED) and republished only after this run's cleanup succeeded. Its ServiceAccounts/Role/RoleBinding are ORDINARY release resources (Helm 3.19+/v4 delete earlier `hook-succeeded` hooks on a later failure) and the DaemonSet carries `before-hook-creation` ONLY. The wait Job deletes the DaemonSet with FOREGROUND propagation, succeeds only on a 404, has only `get`+`delete` on the named DaemonSet plus `get` on its status, and treats a `0/0` report as failure. Evidence: Rust integration suite, CI Helm contract assertions, and `tests/k8s/cni_lifecycle_live/run.sh`.
